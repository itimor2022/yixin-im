## 2. 修复目标与边界

目标：

- 先修复 5 个 P1，消除后台录音、断网语音无法恢复、现场视频发送失败和离线消息乱序。

- 最后修复 1 个 P3，并完成 400 项复测。
- 每个 Bug 都必须有自动化测试或真机证据，不能只凭代码审查关闭。

边界：

- 本方案不直接把 179 个 `BLOCKED` 改为通过。
- 短信、语音转写等依赖外部服务的能力必须先确认产品是否启用；确认启用才接真实服务，否则应调整产品范围和测试基线，不能保留半成品入口。
- 消息、群权限、通话和通知状态以服务端状态为权威，客户端缓存只负责展示和离线降级。
- 涉及协议字段或事件类型的改动必须兼容旧客户端，至少保留一个发布周期。

## 4. Phase 1：P1 严重 Bug

### 4.1 录音生命周期与断网恢复

统一由 `VoiceRecordService` 管理录音状态机，页面不再自行维护第二份录音状态。状态至少包含 `idle / recording / stopping / ready / uploading / failed / cancelled`。

| 编号 | 问题 | 修复方案 | 验收标准 |
| --- | --- | --- | --- |
| IM-167 | 来电中断录音后仍隐藏继续 | 收到来电事件时先调用幂等 `stopAndDiscard(reason: incomingCall)`，确认录音文件句柄释放后再进入来电页；失败也必须终止系统录音会话 | 录音中来电后 1 秒内停止；返回聊天无录音覆盖层、无残留文件、无后台麦克风占用 |
| IM-169 | 切后台后录音继续 | 在 App 生命周期进入 `inactive/paused/detached` 时终止或按产品规则保存草稿；通知 UI 同步退出录音态 | 录音中按 Home，系统麦克风占用立即结束；返回 App 不继续计时，不出现僵尸覆盖层 |
| IM-171 | 断网语音重试一直失败 | 失败消息保留本地文件 URI、媒体类型、时长和上传状态；重试时若无远端 URL，重新上传本地文件，上传成功后再发送消息；成功后清理本地临时文件 | 断网录音发送失败后恢复网络，点击重试一次成功；接收端能播放；同一 `client_msg_id` 不重复生成消息 |

建议修改：

- `lib/core/services/voice_record_service.dart`
- `lib/features/chat/pages/chat_detail_media_voice_actions.dart`
- `lib/features/chat/providers/message_provider.dart`
- 来电状态订阅和 App 生命周期协调代码

必须新增录音状态机单测、后台切换组件测试和本地媒体重试测试。

## 10. 跨模块技术改造

### 10.1 服务端权威事件

建议统一事件信封：

```json
{
  "event_id": "uuid",
  "type": "chat.dissolved",
  "entity_id": "chat_id",
  "version": 12,
  "occurred_at": "2026-07-16T00:00:00Z",
  "actor_id": "user_id",
  "payload": {}
}
```

群资料、角色、解散、消息撤回、送达回执和通话状态都使用事件版本号去重。客户端发现版本跳跃时拉取服务端快照，不靠猜测补状态。

### 10.2 本地发送任务

图片、语音、视频、文件统一使用持久化发送任务，至少保存：

- `account_id`
- `chat_id`
- `client_msg_id`
- `local_path`
- `remote_url`
- `media_type`
- `upload_state`
- `retry_count`
- `created_at`

退出账号必须只清理当前账号任务，不能全量清其他账号数据。

### 10.3 错误码与提示

服务端为撤回超时、权限不足、群已解散、媒体失效、通话忙线、通知权限等返回稳定业务错误码；客户端用错误码映射本地化文案，禁止依赖后端中文字符串判断业务。

### 10.4 可观测性
