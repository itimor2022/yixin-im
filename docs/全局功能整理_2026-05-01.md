## 6. 当前需要持续关注的点

### 6.1 推送侧
- Android 原厂推送能否真正到达，仍要看生产环境：
  - SDK 是否启用
  - 证书/密钥是否正确
  - 真机厂商系统限制
- FCM 是否完整生效，也需要真机和 Firebase 控制台联调验证

### 6.2 联系人缓存侧
- 当前联系人备注在冷启动时已加了显示兜底
- 但本地缓存模型还没有把 `remark/uuid` 做成完整持久化字段
- 这属于低风险一致性问题，后续可以继续补强

### 6.3 语音会议稳定性
- 群语音“RTC 未连接”的问题需要继续实机压测
- 当前群视频链路比群语音更稳定，说明问题更可能在音频入会时序、网络切换或客户端状态恢复

### 6.4 自动化测试
- 后端 `go test ./...` 已具备基础回归能力
- Flutter 当前更多依赖 `dart analyze` 和构建验证
- 仓库缺少系统化 `test/` 自动化 UI/业务测试集

## 7. 建议下一步整理方向

1. 继续补“联系人缓存模型”，把 `uuid/remark` 正式持久化
2. 继续做“消息、语音、推送”三条链路的真机联调清单
3. 单独整理一份“生产环境上线前配置检查表”
4. 单独整理一份“全平台已知问题与回归测试清单”
