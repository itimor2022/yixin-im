# 聊天扩展菜单后台开关开发方案

> 日期：2026-07-13
> 范围：Vue 管理后台、Go 后端、Flutter 客户端
> 目标：让管理员可以在后台统一开启或关闭聊天输入框“+”扩展菜单中的 9 个入口，并保证菜单自动重排、配置及时生效、旧数据兼容。

## 1. 结论

采用“1 个菜单总开关 + 9 个功能开关”的方案：

| 顺序 | 后台开关 | 私聊显示 | 群聊显示 | 默认 |
| --- | --- | --- | --- | --- |
| 1 | 相册 | 相册 | 相册 | 开启 |
| 2 | 摄像头 | 摄像头 | 摄像头 | 开启 |
| 3 | 音视频通话/群会议 | 视频通话 | 会议 | 开启 |
| 4 | 位置 | 位置 | 位置 | 开启 |
| 5 | 红包 | 红包 | 红包 | 开启 |
| 6 | 转账 | 转账 | 不显示 | 开启 |
| 7 | 收藏 | 收藏 | 收藏 | 开启 |
| 8 | 文件 | 文件 | 文件 | 开启 |
| 9 | 阅后即焚 | 阅后即焚 | 阅后即焚 | 开启 |

其中：

- 前 8 项使用新的 `chat_attachment_menu` JSON 配置。
- “阅后即焚”直接复用项目已有的 `burn_after_read_enabled`，不再新增重复字段。
- 所有开关缺省时都按“开启”处理，避免升级后原功能突然消失。
- 这是全局系统配置，本期不区分用户、角色、组织或 App 平台。

## 2. 产品规则

### 2.1 菜单生成规则

客户端不再把第一页和第二页写死，而是按以下规则动态生成：

1. 先按固定顺序生成 9 个候选入口。
2. 过滤掉后台已关闭的入口。
3. 再过滤掉当前会话不适用的入口，例如群聊不显示转账。
4. 将剩余入口每 8 个分成一页。
5. 不保留被关闭入口的空位，后续入口自动向前补位。
6. 只有一页时不显示底部分页圆点。
7. 如果只剩“阅后即焚”，它直接显示在第一页第一个位置。
8. 菜单总开关关闭，或当前会话没有任何可用入口时，隐藏输入框左侧“+”按钮。

### 2.2 开关语义

本方案默认把新增的 8 个开关定义为“扩展菜单入口开关”：

- 关闭后，不影响用户查看已存在的图片、文件、位置、红包或转账消息。
- 关闭后，不删除历史数据。
- “音视频通话/群会议”只控制该扩展菜单里的入口；如果其他页面还有通话按钮，不应被意外关闭。
- “阅后即焚”继续保持已有的全局功能开关语义：关闭后隐藏入口，后端同时忽略旧版客户端传入的阅后即焚标记。

如果产品后续要求“关闭后任何版本都不能调用该功能”，应另立全局功能权限，不要直接扩大菜单显示开关的语义。详见本文第 8 节。

## 3. 当前代码基础

### 3.1 Flutter 菜单

当前菜单实现位于：

- `lib/features/chat/pages/chat_detail_attachment_sheet.dart`
- `lib/features/chat/pages/chat_detail_media_actions.dart`
- `lib/features/chat/pages/chat_detail_input_composer.dart`
- `lib/features/chat/widgets/chat_input_bar.dart`

现状：

- 相册、摄像头、通话/会议、位置、红包、转账、收藏、文件组成第一页。
- 第一页通过 `firstPage.take(8)` 固定最多取 8 项。
- 阅后即焚被单独写在第二页。
- 菜单已会根据会话类型把通话切换为会议，并且仅在私聊显示转账。

因此本次不需要重写菜单 UI，只需把“固定分页”改为“动态过滤后分页”。

### 3.2 现有系统设置链路

项目已有可直接复用的链路：

```text
管理后台 /admin/settings
          ↓
system_settings 键值表
          ↓

Flutter SystemSettings + Riverpod Provider + 本地缓存
```

关键文件：

- `admin/src/api/admin.ts`

`system_settings` 已支持 `bool`、`int`、`string`、`json` 类型，所以本次不新增表，也不需要数据库迁移。

### 3.3 阅后即焚现有能力

项目已有：

- 后台 `burn_after_read_enabled` 开关。
- `/app/settings` 公开配置输出。
- Flutter `SystemSettings.burnAfterReadEnabled` 解析。
- 客户端菜单隐藏与当前状态清理。
- 后端发送消息时忽略已禁用的阅后即焚标记。

本次只需要把它移入统一的后台设置卡片，并纳入新的动态排版算法。

## 4. 配置设计

### 4.1 存储键

新增系统设置键：

```text
chat_attachment_menu
```

类型：

```text
json
```

数据示例：

```json
{
  "enabled": true,
  "album": true,
  "camera": true,
  "call": true,
  "location": true,
  "red_packet": true,
  "transfer": true,
  "favorite": true,
  "file": true
}
```

不在这个 JSON 内再存储 `burn_after_read`，避免和现有 `burn_after_read_enabled` 产生两份真相。

### 4.2 Go 配置结构

建议新增：

```go
type ChatAttachmentMenuSetting struct {
    Enabled   bool `json:"enabled"`
    Album     bool `json:"album"`
    Camera    bool `json:"camera"`
    Call      bool `json:"call"`
    Location  bool `json:"location"`
    RedPacket bool `json:"red_packet"`
    Transfer  bool `json:"transfer"`
    Favorite  bool `json:"favorite"`
    File      bool `json:"file"`
}
```

同时提供：

```go
func DefaultChatAttachmentMenuSetting() ChatAttachmentMenuSetting
func LoadChatAttachmentMenuSetting(db *gorm.DB) ChatAttachmentMenuSetting
func ValidateChatAttachmentMenuSetting(raw interface{}) error
```

默认函数必须返回全部 `true`。不能直接依赖 Go `bool` 的零值，否则旧数据库没有该键时会被误判为全部关闭。

### 4.3 公开 App 配置

`GET /app/settings` 增加：

```json
{
  "chat_attachment_menu": {
    "enabled": true,
    "album": true,
    "camera": true,
    "call": true,
    "location": true,
    "red_packet": true,
    "transfer": true,
    "favorite": true,
    "file": true
  },
  "burn_after_read_enabled": true
}
```

注意：

- 该公开接口只返回开关，不包含管理员信息或敏感配置。
- JSON 解析失败时应记录日志并回退到默认全开，不应让 `/app/settings` 整体失败。
- 后台更新接口必须验证只接受上述已知字段和布尔值。

## 5. 管理后台方案

### 5.1 页面位置

在：

```text
系统设置 → 客户端功能
```

增加“聊天扩展菜单”卡片，并把已有“阅后即焚”开关移入该卡片。

### 5.2 建议布局

```text
聊天扩展菜单                         [总开关]

控制聊天输入框左侧“+”中显示的功能。

[相册]       [摄像头]       [音视频通话/群会议]
[位置]       [红包]         [转账]
[收藏]       [文件]         [阅后即焚]
```

交互规则：

- 关闭总开关后，9 个子开关置灰，但不覆盖子开关已保存的值。
- 重新打开总开关时，恢复之前的子开关组合。
- “转账”下方提示“仅私聊显示”。
- “音视频通话/群会议”下方提示“私聊显示通话，群聊显示会议”。
- “阅后即焚”下方保留现有的后端兜底说明。
- 演示管理员继续只读，所有开关禁用。
- 统一点击“保存客户端功能”后提交，不做单个开关的即时写库。

### 5.3 TypeScript 类型

```ts
export interface ChatAttachmentMenuSettings {
  enabled: boolean
  album: boolean
  camera: boolean
  call: boolean
  location: boolean
  red_packet: boolean
  transfer: boolean
  favorite: boolean
  file: boolean
}

export interface SystemSettings {
  chat_attachment_menu?: ChatAttachmentMenuSettings
  burn_after_read_enabled?: boolean
}
```

后台加载时对 JSON 每个字段都使用 `!== false` 的兼容语义，不应直接使用 `|| false`。

## 6. Flutter 客户端方案

### 6.1 配置模型

在 `system_settings_service.dart` 新增不可变模型：

```dart
class ChatAttachmentMenuSettings {
  final bool enabled;
  final bool album;
  final bool camera;
  final bool call;
  final bool location;
  final bool redPacket;
  final bool transfer;
  final bool favorite;
  final bool file;

  const ChatAttachmentMenuSettings({
    this.enabled = true,
    this.album = true,
    this.camera = true,
    this.call = true,
    this.location = true,
    this.redPacket = true,
    this.transfer = true,
    this.favorite = true,
    this.file = true,
  });
}
```

`SystemSettings.fromJson` 规则：

- `chat_attachment_menu` 缺失：返回 `const ChatAttachmentMenuSettings()`。
- 子字段缺失：该字段默认 `true`。
- 字段为显式 `false`：关闭。
- JSON 类型错误：回退默认值，不阻断 App 启动。
- `toJson` 必须包含完整菜单配置，确保本地缓存可完整恢复。

### 6.2 菜单组装

建议将 `_buildPages` 改成以下思路：

```dart
final actions = <_AttachmentActionData>[
  if (config.album) albumAction,
  if (config.camera) cameraAction,
  if (config.call && isPrivateChat) callAction,
  if (config.call && isGroupChat) meetingAction,
  if (config.location) locationAction,
  if (config.redPacket && canSendRedPacket) redPacketAction,
  if (config.transfer && isPrivateChat) transferAction,
  if (config.favorite) favoriteAction,
  if (config.file) fileAction,
  if (burnAfterReadEnabled && allowBurnAfterRead) burnAfterReadAction,
];

final pages = <List<_AttachmentActionData>>[];
for (var start = 0; start < actions.length; start += 8) {
  pages.add(actions.sublist(start, math.min(start + 8, actions.length)));
}
```

实际落地时可以用项目现有工具方法，不要为了分页引入额外依赖。

### 6.3 菜单总开关和“+”按钮

不能只在 `_AttachmentSheet` 内返回空容器，否则用户点击“+”后会看到空白面板。

应在输入区组装层统一计算：

```dart
final hasAvailableAttachmentAction =
    menu.enabled && effectiveActions.isNotEmpty;
```

然后：

- `hasAvailableAttachmentAction == false`：不构建“+”按钮。
- 配置刷新前菜单已经打开，刷新后变为无可用入口：立即关闭当前面板。
- 后台关闭当前已选中的阅后即焚时：清理 `_burnAfterReadEnabled` 本地状态，现有逻辑继续保留。

### 6.4 平台和会话类型

有效入口必须同时满足：

```text
后台开关开启
AND 当前平台支持
AND 当前会话类型支持
AND 当前用户/群权限允许
```

后台开关不应覆盖已有会话权限。例如群聊禁止成员发送媒体时，即使后台“相册”开关开启，仍应执行原有的群权限拦截。

## 7. 配置刷新与生效时间

### 7.1 现状问题

Flutter `SystemSettingsService` 当前本地缓存时间为 30 分钟。如果只增加字段而不调整刷新机制，会出现：

```text
后台已关闭 → 在线客户端最长仍显示 30 分钟
```

这会让管理员误以为保存失败。

### 7.2 推荐机制

采用“事件刷新 + 前台刷新 + 缓存兜底”：

1. 后台保存成功后，后端广播 `system.settings.updated` WebSocket 事件。
2. 在线 Flutter 客户端收到事件后，执行 `getSettings(forceRefresh: true)`。
3. 获取成功后更新本地缓存并 `invalidate(systemSettingsProvider)`。
4. App 从后台回到前台时再强制刷新一次，防止 WebSocket 事件丢失。
5. 网络异常时继续使用最后一份成功缓存，不将菜单突然清空。

建议生效目标：

| 客户端状态 | 目标生效时间 |
| --- | --- |
| 在线且 WebSocket 正常 | 5 秒内 |
| 从后台回到前台 | 本次恢复时 |
| 离线 | 下次启动/联网时 |

如果本期不实现 WebSocket 广播，必须在发布说明中明确“重新进入 App 或回到前台后生效”，不得宣称为实时生效。

## 8. 旧版客户端与服务端兜底

### 8.1 必须明确的限制

旧版 App 不认识 `chat_attachment_menu`，所以：

- 无法通过后台配置隐藏旧版 App 的菜单图标。
- 只能通过发布新 App 版本完成 UI 隐藏。
- 强制服务端拦截可以让旧版“点了也不能用”，但不能让图标消失。

### 8.2 入口开关与全局功能开关的边界

| 入口 | 服务端能否精准拦截 | 说明 |
| --- | --- | --- |
| 相册 | 不能按来源精准拦截 | 相册和摄像头最终都发送图片/视频消息 |
| 摄像头 | 不能按来源精准拦截 | 后端不知道文件来自相册还是摄像头 |
| 通话/会议 | 可拦截发起 | 会同时影响其他页面的发起入口 |
| 位置 | 可按消息类型拦截 | 会成为全局禁止发送位置 |
| 红包 | 可拦截发送 | 不影响查看和领取已有红包 |
| 转账 | 可拦截发起 | 不影响查看已有转账 |
| 收藏 | 无需服务端拦截 | 当前是客户端本地收藏入口 |
| 文件 | 可按消息类型拦截 | 会成为全局禁止发送文件 |
| 阅后即焚 | 已有兜底 | 后端已会清除禁用后的阅后即焚标记 |

推荐分两期：

- P0：实现本文的菜单显示开关，完成后台、配置接口和新版客户端闭环。
- P1：如果确实需要全局禁用功能，再增加独立的 capability 权限，并在通话、会议、消息、红包和转账接口统一拦截。

这样可以避免“只想隐藏加号菜单，却误伤了其他页面的功能”。

## 11. 测试方案

### 11.1 后端测试

- 数据库不存在 `chat_attachment_menu`：返回全部开启。
- 只保存部分字段：未出现字段默认开启。
- 保存显式 `false`：后台回显和 `/app/settings` 都返回 `false`。
- 提交非布尔值：返回 400，不写入错误配置。
- 提交未知字段：返回 400。
- JSON 存量损坏：App 接口仍成功，菜单回退全开并记录日志。
- 阅后即焚关闭：现有后端消息发送兜底仍通过。

### 11.2 管理后台测试

- 9 个开关都能加载、修改、保存和回显。
- 总开关关闭后子开关置灰。
- 总开关重新开启后，子开关的原值保留。
- 不修改其他客户端功能配置。
- 演示管理员无法修改。
- 刷新页面后不出现开关反转或恢复默认的问题。

### 11.3 Flutter 自动化测试

- 9 项全开：第一页 8 项，第二页阅后即焚。
- 关闭中间任意一项：后续项目向前补位。
- 关闭前 8 项：阅后即焚位于第一页第一位，不显示分页圆点。
- 关闭阅后即焚：只有第一页 8 项，不显示分页圆点。
- 总开关关闭：“+”按钮消失。
- 子开关全关，阅后即焚也关闭：“+”按钮消失。
- 私聊：开启时显示通话和转账。
- 群聊：开启时显示会议，不显示转账。
- 旧缓存不含新字段：菜单保持现状。
- 远程获取失败：使用本地缓存，不闪烁、不空白。

### 11.4 真机/模拟器验收

## 13. 发布、兼容和回滚

### 13.1 发布顺序

1. 先发布 Go 后端，但保持新开关默认全开。
2. 再发布管理后台。
3. 最后发布 Android、iOS、Windows 等 Flutter 客户端。
4. 等主要客户端升级后，管理员再开始关闭需要隐藏的入口。

这个顺序可以保证旧客户端不会因后端提前上线新字段而异常。

### 13.2 回滚

- 紧急情况先把总开关和所有子开关恢复为开启。
- 旧客户端会忽略新 JSON 字段，无需数据库回滚。
- 如需回滚客户端代码，保留 `system_settings` 中的 JSON 记录也不影响旧版。
- 不在回滚时删除系统设置记录，避免丢失管理员配置。
