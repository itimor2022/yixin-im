# 退出与账号边界缓存治理开发方案

> 状态：待实施
> 适用端：iOS、Android、macOS、Windows、Web
> 主体范围：Flutter 前端账号边界、缓存隔离与退出资源治理
> 联合范围：历史消息恢复、E2EE 跨设备恢复、长期消息幂等

## 1. 背景

当前应用已经具备聊天、联系人、钱包、VIP、设备管理、推送、通话、会议、离线消息和 E2EE 等能力，但账号相关状态并没有统一依赖同一个账号上下文。退出或快速切换账号时，旧账号的内存状态、持久缓存或延迟异步响应可能继续被新账号页面读取，从而产生以下风险：

- 账号 B 短暂看到账号 A 的联系人、钱包、VIP、设备数或聊天状态；
- 账号 A 发起的请求在退出后返回，并覆盖账号 B 的 Provider；
- 全局离线消息队列使用账号 B 的 Token 重发账号 A 的消息；
- 旧 WebSocket、推送点击、通话、会议、录音或延迟任务在退出后继续回调；
- 为了防止串号而误删本地聊天或 E2EE 私钥，破坏同设备历史恢复能力；
- 产品把“服务器能返回消息”误宣传成“所有历史聊天都能完整恢复”。

本方案的核心不是“退出时删除一切”，而是：

> 可见运行态立即清空，账号持久数据严格隔离，本地唯一数据按账号冻结，高风险删除必须由用户单独确认。

## 2. 范围与承诺

### 2.1 前端 P0 可以承诺

- 手动退出、Token 失效、强制下线进入同一套本地退出流程；
- 退出或切换账号后，新账号不能读取旧账号的内存状态和持久缓存；
- 旧账号的异步请求、WebSocket、推送和延迟任务不能写入新账号状态；
- 普通退出保留本机按账号隔离的聊天、消息和 E2EE 私钥；
- 离线消息、草稿和待上传资源不会跨账号发送；
- 清缓存、清账号数据、重置加密身份是三个相互独立的操作。

### 2.2 前端 P0 不能承诺

- 清除本地数据后恢复服务器查询窗口之外的消息；
- 恢复服务器已经删除、用户主动删除、撤回、阅后即焚或过期的内容；
- 恢复未成功进入服务器的消息和已经失效的远程媒体；
- 新设备在没有旧设备、密钥备份或用户主密钥的情况下解密旧 E2EE 消息；
- 断网退出时立即完成服务端 Token 撤销和推送解绑。

### 2.3 后端联合能力完成后的准确承诺

只有在后端明确消息保留期限、历史查询覆盖完整保留期，并完成 E2EE 密钥恢复设计后，产品才可以表述为：

> 可以恢复服务器保留期限内、用户仍有权访问且当前设备具备解密条件的聊天记录。

不得使用无条件的“清除本地后可恢复全部聊天记录”。

## 3. 当前仓库事实

### 3.1 已有能力

- `ChatModel`、`MessageModel` 已包含 `accountId`，主键也组合了账号和业务 ID；
- 消息窗口的部分内存缓存和 Web SharedPreferences 已使用 `accountId + chatId`；
- E2EE 公私钥已按 `userId + deviceId` 生成安全存储命名空间；
- 普通退出当前不会删除 Isar 聊天、消息和 E2EE 私钥；
- `/auth/logout` 已支持提交精确推送 binding，并删除当前 Token 对应会话、撤销当前 Token；
- 前端发送消息时已提交稳定 `msg_id`，后端已有重复查询、唯一索引和 duplicate ACK。

### 3.2 主要缺口

- `UserModel` 联系人缓存没有 `accountId`，查询和覆盖均可能跨账号；
- 钱包、VIP 状态、VIP 订单、设备数等 Provider 是全局实例，退出时没有统一重建；
- 隐私设置、聊天文件夹、通知设置等 SharedPreferences 同时混有账号设置和设备设置；
- 红包、转账状态单例只按业务 ID 缓存；
- 收藏服务存在扫描其他账号键并回退合并的路径；
- 自定义表情使用全局键和全局目录；
- 离线消息队列使用全局键 `offline_message_queue`，队列项没有 `accountId`，当前退出会直接清空；
- `_authVersion` 只保护认证服务内的部分请求，无法阻止钱包、联系人、VIP 等旧请求回写；
- Token 失效路径直接改变认证状态，没有经过完整的资源 teardown；
- 强制下线当前复用普通 `logout()`，但没有区分旧 Token 是否已经被服务端撤销；
- 通话、会议、录音、上传、推送延迟回调缺少统一退出清理入口；
- 服务端主消息查询只遍历最近 12 个自然月分表；
- 当前消息幂等查询也只遍历最近 12 个月，唯一索引则存在于各月集合内。

## 4. 设计原则

1. **退出原因与数据操作解耦**：Token 失效不等于用户授权清数据。
2. **先隔离，再远端收尾**：网络请求不能阻塞旧账号从界面消失。
3. **账号为空时拒绝读取**：账号级缓存不得使用 `anonymous`、空字符串或最近账号作为回退。
4. **旧响应默认不可信**：所有账号级异步结果写入前必须验证账号上下文。
5. **完整刷新成功后的空列表是权威结果**：应覆盖当前账号旧状态；分页末尾的空页不能用于删除更早历史。
6. **网络失败只回退当前账号缓存**：禁止扫描或合并其他账号缓存。
7. **可重建数据与本地唯一数据分开处理**：未发送消息、草稿、未上传文件不能按普通缓存删除。
8. **E2EE 私钥不属于缓存**：普通退出、Token 失效、强制下线和清缓存均不得删除。
9. **清理按目标账号执行**：禁止全量清 SharedPreferences、整个 Isar 或全部 Secure Storage。
10. **共享 Dart 逻辑，平台能力适配**：五个平台共用协调器，仅推送、文件、RTC、Secure Storage 等由平台适配器处理。

## 5. 数据归属与默认策略

| 数据类别 | 典型数据 | 普通退出/失效/强退 | 清缓存 | 清本机账号数据 | 重置加密身份 |
| --- | --- | --- | --- | --- | --- |
| 凭证 | JWT、用户快照、ApiClient Token | 清除 | 不涉及 | 清除 | 清除 |
| 账号运行态 | 联系人、钱包、VIP、设备数、当前聊天、动态 | 立即清空 | 不涉及 | 清空 | 清空 |
| 账号持久缓存 | 聊天、消息、联系人、收藏、表情、文件夹 | 按账号保留 | 保留 | 仅删目标账号 | 保留 |
| 本地唯一数据 | 待发消息、草稿、未上传媒体 | 按账号冻结 | 保留 | 提示后删目标账号 | 保留 |
| 可再下载媒体 | 头像、图片、视频、语音缩略图 | 保留 | 删除 | 删除目标账号引用和文件 | 不涉及 |
| 设备偏好 | 语言、主题、窗口大小、下载策略、快捷键 | 保留 | 保留 | 保留 | 保留 |
| 公共配置 | 系统设置、VIP 套餐、发现页配置 | 保留 | 可刷新 | 保留 | 保留 |
| 加密身份 | E2EE 公私钥、注册标识 | 保留 | 保留 | 默认保留 | 单独确认后轮换或删除 |

## 6. 统一账号上下文

### 6.1 数据结构

新增统一账号上下文，所有账号级 Provider、异步任务和持久层入口都依赖它：

```dart
class AccountContext {
  final String accountId;
  final int epoch;

  const AccountContext({
    required this.accountId,
    required this.epoch,
  });

  bool get isValid => accountId.isNotEmpty;
}
```

`epoch` 是当前登录世代。以下事件必须产生新世代：

- 登录成功，包括重新登录同一账号；
- 手动退出开始；
- Token 失效；
- 强制下线；
- 设备会话被终止；
- 切换账号。

### 6.2 异步写入规则

每个账号级异步操作开始时捕获 `AccountContext`，在以下位置重新校验：

- 网络响应返回后；
- 写 Provider 前；
- 写 SharedPreferences、Isar 或文件前；
- WebSocket、推送、定时器和后台任务回调开始时；
- 上传完成、消息 ACK 和离线队列状态迁移前。

```dart
final captured = ref.read(accountContextProvider);
final response = await service.load();

if (!ref.read(accountSessionCoordinatorProvider).isCurrent(captured)) {
  return;
}

state = response;
```

仅判断 Widget `mounted` 或 Notifier `_isDisposed` 不足以防串号，因为旧 Provider 可能仍然存活。

### 6.3 Provider 规则

账号级 Provider 应采用以下任一方式：

- `family(accountId)`；
- `watch(accountContextProvider)`，账号或 epoch 变化时重建；
- 由账号级 `ProviderScope` 统一销毁。

禁止依赖开发人员在退出函数里手工记住所有 Provider。协调器仍保留一份显式清理清单，用于单例和平台资源，但普通业务 Provider 应通过依赖关系自动重建。

## 7. 统一退出协调器

### 7.1 强类型参数

```dart
enum SessionExitReason {
  manual,
  tokenExpired,
  forcedOffline,
  deviceTerminated,
  accountDeleted,
}

enum LocalDataAction {
  keepAccountData,
  clearDownloadableCache,
  purgeAccountData,
  resetEncryptionIdentity,
}
```

退出原因和本地数据操作不得通过多个布尔值组合。除用户单独确认外，所有退出原因默认使用 `keepAccountData`。

### 7.2 并发与幂等

`AccountSessionCoordinator` 必须：

- 对同一退出事件加锁；
- 多个调用者共享同一个进行中的 Future；
- 允许手动退出、401 回调和 WebSocket 强退同时到达；
- 每个 teardown 方法可以重复执行；
- 收集单项错误，但不允许错误阻止本地凭证清除；
- 退出完成后才允许下一次登录建立新上下文。

普通退出不需要把所有内存清理阶段落盘。仅以下任务需要持久化进度：

- 用户主动执行的破坏性“清除本机账号数据”；
- 服务端提供安全重试协议后，尚未确认完成的远端撤销任务。

### 7.3 三段式退出流程

#### 第一段：立即隔离，不等待网络

1. 捕获旧 `accountId`、Token、设备 ID 和当前资源状态；
2. 状态切换为 `exiting`，禁止新业务请求和新离线发送；
3. `accountEpoch++`，使旧请求、旧 WS、旧推送和旧延迟任务失效；
4. 暂停离线队列 worker，冻结旧账号队列；
5. 立即清空联系人、钱包、VIP、设备数、聊天选中态等可见运行态；
6. 清除旧推送点击、深链和导航待处理任务；
7. 登录页显示前不得重新读取任何账号级缓存。

#### 第二段：使用旧凭证尽力远端收尾

1. 活跃通话按产品策略发送挂断并释放 RTC；
2. 活跃会议发送离会并释放房间资源；
3. 手动退出时调用 `/auth/logout`，由现有接口统一执行精确推送解绑、会话删除和 Token 撤销；
4. 设置 2～3 秒短超时；
5. Token 已失效、设备已被终止或服务端已强退时，不强制重复调用 `/auth/logout`；
6. 远端失败只记录降级结果，本地退出继续执行。

断网退出时，客户端无法凭空保证服务端 Token 已撤销。若产品要求强保证，需要后端提供不依赖已经失效访问 Token 的安全撤销协议。

#### 第三段：保证本地完成

1. 断开 WebSocket，并禁止旧 Token 自动重连；
2. 取消通话、会议、录音、上传、下载、定时器和后台订阅；
3. 清理推送本地待处理状态，但不删除系统级推送能力；
4. 清除 TokenStorage、用户快照和 ApiClient Token；
5. invalidate 账号级 Provider 和 family 实例；
6. 清空旧账号内存单例；
7. 保留按账号隔离的 Isar 聊天、消息和 E2EE 私钥；
8. 状态切换为 `unauthenticated` 并进入登录页。

### 7.4 不同退出原因的远端行为

| 原因 | 本地隔离 | `/auth/logout` | 本地持久聊天 | E2EE 私钥 |
| --- | --- | --- | --- | --- |
| 手动退出 | 必须 | 有网时调用 | 保留 | 保留 |
| Token 失效 | 必须 | 默认跳过或尽力调用 | 保留 | 保留 |
| 强制下线 | 必须 | 不依赖其成功 | 保留 | 保留 |
| 设备终止 | 必须 | 服务端通常已处理 | 保留，除非产品另有明确策略 | 默认保留本地副本 |
| 删除账号完成 | 必须 | 按删除账号协议 | 由独立删除策略决定 | 由独立确认决定 |

## 8. 持久数据隔离

### 8.1 Isar

#### 已有账号隔离

- `ChatModel`：保持 `fastHash('$accountId:$id')`；
- `MessageModel`：保持 `fastHash('$accountId:$id')`；
- 所有查询必须同时包含 `accountId` 和业务条件。

#### 联系人改造

`UserModel` 增加 `accountId`：

```dart
Id get isarId => fastHash('$accountId:$id');

@Index(composite: [CompositeIndex('id')], unique: true)
late String accountId;
```

联系人读取、写入、删除和空列表覆盖都必须限定目标账号。

旧版 `UserModel` 无法可靠判断数据属于哪个账号，升级时不得展示给当前账号。最安全策略是删除旧联系人缓存并从服务器重新拉取，不迁移联系人业务数据。

#### 清理限制

- 普通退出禁止 `isar.clear()`；
- 清账号数据只能删除 `accountId == targetAccountId` 的记录；
- 账号 ID 为空时直接返回，不执行读取或删除；
- 完整刷新成功返回空联系人时，必须删除该账号旧联系人索引并显示空列表。

### 8.2 SharedPreferences

统一账号级命名规则：

```text
acct_v1_<accountHash>_<feature>_<key>
```

`accountHash` 使用账号 UUID 的不可逆摘要，避免原始 UUID 大量出现在偏好文件和日志中。

需要账号化的内容包括：

- 隐私服务端设置缓存；
- 聊天文件夹；
- 收藏消息；
- 自定义表情和最近使用的账号级表情；
- 钱包页面删除的订单 ID；
- 消息窗口、删除状态和已读游标；
- 离线消息队列；
- 其他包含服务端账号业务数据的键。

继续使用设备级全局键的内容包括：

- 语言、主题、窗口大小、快捷键；
- 下载网络策略；
- 本机音效、振动等纯设备偏好；
- API 入口和公共系统配置缓存。

既有全局键只有在能证明所属账号时才能迁移；无法证明的旧数据不得自动挂到当前账号。

### 8.3 文件目录

账号私有文件统一放入：

```text
accounts/<accountHash>/
  emojis/
  drafts/
  pending_uploads/
  private_media/
```

公共可再下载媒体可以继续使用全局内容寻址缓存，但账号消息只能通过自己的索引引用。若要支持“清除指定账号媒体”，需要维护账号到缓存对象的引用清单，不能直接删除整个媒体缓存目录。

### 8.4 禁止跨账号 fallback

禁止以下行为：

- 当前账号缓存为空时扫描其他 `acct_*` 键；
- 使用上一次 `TokenStorage.userId` 猜测当前账号；
- 把所有收藏、表情或文件夹合并后写入当前账号；
- 网络失败时返回任意最近缓存；
- 为兼容旧版而读取无账号 Isar 数据并展示。

## 9. 离线队列与本地唯一数据

### 9.1 队列模型

队列项至少包含：

```dart
class OfflineMessage {
  final String accountId;
  final String clientMsgId;
  final String chatId;
  final OfflineMessageType type;
  final String? content;
  final String? localPath;
  final DateTime createdAt;
  final OfflineMessageState state;
}
```

持久键使用：

```text
acct_v1_<accountHash>_offline_message_queue
```

### 9.2 状态与处理规则

推荐状态：`queued、sending、frozen、acknowledged、failed`。

- 入队时写入确定的 `accountId` 和稳定 `clientMsgId`；
- worker 只加载当前账号队列；
- 每次发送前、响应后和状态落盘前校验当前账号；
- 退出时把 `queued/sending` 变为 `frozen`；
- 同账号重新登录后先查询或依赖稳定消息 ID 幂等，再恢复发送；
- ACK 丢失时允许用同一 `clientMsgId` 重试；
- 登录 B 时，A 的队列不得注册回调或产生网络请求；
- 清账号数据前统计未发送消息、草稿和待上传文件，并要求用户确认。

### 9.3 旧队列迁移

旧版全局队列没有账号归属，不能安全迁移给当前账号：

- 可以记录不含正文的待迁移数量；
- 删除旧消息正文和附件引用；
- 不发送、不自动挂到当前登录账号；
- 新版本只创建带账号归属的队列项。

### 9.4 后端幂等边界

当前后端已经支持客户端 `msg_id`、重复查询、唯一索引和 duplicate ACK，因此短期离线重发不需要重新设计一套幂等协议。

但现有重复查询只覆盖最近 12 个月，唯一索引位于各月集合。如果产品允许队列冻结超过该范围，需要二选一：

- 增加跨分表的全局客户端消息 ID 幂等记录；
- 明确离线待发队列的最大保留和恢复发送期限。

## 10. 三种本地数据操作

### 10.1 清除缓存

只删除可重建内容：

- Flutter ImageCache；
- 临时目录；
- 可重新下载的头像、缩略图和媒体缓存；
- 已完成任务的临时上传文件。

不得删除：

- ChatModel、MessageModel；
- 联系人、收藏、表情元数据；
- 离线消息和草稿；
- E2EE 私钥；
- Token 和登录状态。

### 10.2 清除本机账号数据

目标必须是明确的 `targetAccountId`：

- 删除目标账号 Isar 聊天、消息、联系人等记录；
- 删除目标账号 SharedPreferences 键；
- 删除目标账号文件目录；
- 清除目标账号内存 Provider 和单例；
- 提示并删除目标账号离线消息、草稿和未上传文件；
- 默认保留该账号当前设备 E2EE 私钥；
- 不影响其他账号和设备级偏好。

该操作需要展示删除统计，执行阶段落盘，并能在 App 被杀后幂等续做。

### 10.3 重置或删除加密身份

这是独立高风险操作：

- 展示不可逆警告：旧 E2EE 消息可能永久无法解密；
- 明确账号和当前设备；
- 要求二次确认或验证登录密码；
- 先与服务端完成设备公钥撤销或原子轮换，再删除本地旧密钥；
- 若服务端不能撤销旧公钥，禁止只删本地私钥后继续正常收取 E2EE 消息；
- 删除后不承诺恢复旧 E2EE 历史。

当前后端只有设备公钥注册/更新能力。若产品需要“删除加密身份”而不是立即生成新身份，需要补充服务端公钥撤销协议。

## 11. E2EE 与聊天恢复边界

### 11.1 同设备恢复

当前每条 E2EE 消息包含发送时面向各设备公钥生成的密钥信封。只要满足以下条件，同设备重新登录后可以解密对应历史：

- 原设备 ID 未改变；
- 原设备私钥仍在 Secure Storage；
- 消息包含该设备的密钥信封；
- 服务端仍保存并允许返回该消息。

普通退出和清缓存必须保留 E2EE 私钥。“清本机账号数据”也默认保留私钥，以便从线上重新拉取后继续解密。

### 11.2 新设备恢复

新设备的新公钥通常不存在于旧消息信封中。可选建设方案：

1. 使用用户口令加密的私钥或用户主密钥备份；
2. 由旧可信设备为新设备重新封装消息密钥；
3. 引入用户级主密钥，消息密钥先面向主密钥封装，再由主密钥授权设备。

服务端不得保存明文私钥。若旧设备不可用且此前没有备份或主密钥设计，旧 E2EE 消息无法事后恢复。

### 11.3 历史消息查询

当前主消息列表、断档补偿以及多项历史消息操作存在最近 12 个月查询范围。后端联合阶段应：

- 明确消息实际保留期限；
- 建立统一的消息集合目录与分页游标；
- 让消息列表、同步、搜索、编辑、撤回、删除、表情回应等复用同一历史定位组件；
- 避免仅把常量 `12` 改成更大的数字；
- 为历史查询建立可监控的延迟、错误率和扫描量指标。

统一协调器需要调用各模块的幂等 teardown：

| 模块 | 退出动作 |
| --- | --- |
| WebSocket | 禁止旧 Token 重连，注销账号事件处理器并断开 |

| 上传/下载 | 取消账号任务；禁止完成回调写入新账号 |

| 定时器/延迟任务 | 取消或在回调中校验 accountEpoch |

## 15. 测试方案

### 15.1 单元测试

- 同一退出事件并发触发只执行一次；
- accountEpoch 变化后旧 Future 不得写状态或落盘；
- 账号 ID 为空时所有账号缓存读取返回空；
- Provider 切换账号时先清空，再加载新账号；
- 完整刷新成功的空列表覆盖当前账号旧缓存；
- 网络失败只返回当前账号缓存；
- WalletStatusCache、收藏、表情和文件夹不跨账号回退；
- 离线队列只处理当前账号，ACK 丢失后使用相同 clientMsgId；
- 清账号数据只生成目标账号删除集合；
- 重置密钥不能由普通退出间接触发。

### 15.2 集成场景

1. A 联系人非空，B 联系人为空，切到 B 后第一帧不能出现 A 联系人；
2. A 钱包和 VIP 请求延迟，登录 B 后旧响应不能覆盖 B；
3. A 设备数请求失败，不能回退到 B 或上一账号设备数；
4. A 有红包、转账缓存，B 打开同业务 ID 时不能读取 A 状态；
5. A 离线发送消息后退出，登录 B 绝不发送；重新登录 A 最多发送一次；
6. A 上传媒体过程中退出，上传完成回调不能插入 B 的消息；
7. A 的旧 WebSocket 事件、推送点击和延迟导航不能在 B 登录后触发；
8. 活跃通话、会议、录音过程中退出，RTC、铃声、Wakelock 和临时文件被释放；
9. 手动退出、Token 失效、强制下线得到相同本地隔离结果；
10. A 普通退出再登录，A 的 Isar 聊天、消息和 E2EE 私钥仍可使用；
11. 清缓存后文字历史、离线草稿和 E2EE 私钥仍在；
12. 清除 A 本机数据不影响 B；
13. 删除 E2EE 私钥必须独立确认，并显示旧密文不可恢复提示；
14. 清账号数据过程中强杀 App，下次启动继续清理且不展示旧账号数据。

## 16. 验收标准

### 16.1 P0 发布门槛

- 五个平台的共享 Dart 逻辑使用同一协调器；
- 手动退出、Token 失效、强制下线均执行统一本地 teardown；
- A 登录 B 后无任何 A 的联系人、钱包、VIP、设备数、聊天或业务单例状态；
- 所有账号级异步写入均有账号世代保护；
- 离线消息不会跨账号发送；
- 普通退出不删除 Isar 聊天、消息、草稿和 E2EE 私钥；
- 通话、会议、录音、上传、推送和后台任务退出后无残留；
- 不存在 SharedPreferences 全量清理、Isar 全量清理或 Secure Storage 全量清理。

### 16.2 P1 发布门槛

- 三种数据操作入口、范围和风险提示完全分离；
- 清账号数据只影响目标账号；
- 删除前准确统计本地唯一数据；
- 破坏性清理支持中断后幂等继续；
- E2EE 私钥删除前完成服务端公钥撤销或轮换；
- UI 不使用“全部历史一定恢复”等越界文案。

### 16.3 P2 发布门槛

- 消息保留期限有明确产品和运维配置；
- 历史查询覆盖完整承诺期限；
- 长期消息幂等边界经过测试；
- 新设备 E2EE 恢复方案有安全评审；
- 无旧设备、无备份、密钥丢失等不可恢复场景有准确提示；
- 清本地数据后恢复测试覆盖普通消息、媒体、E2EE、删除消息和阅后即焚边界。

## 17. 可观测性

每次退出生成 `traceId`，仅记录：

- 退出原因；
- 旧账号不可逆哈希；
- accountEpoch；
- 执行阶段和耗时；
- 失败组件；
- 远端退出、推送解绑是否获得确认；
- 本地 teardown 是否完成。

日志禁止记录 JWT、推送 Token、消息正文、E2EE 私钥、完整手机号和原始账号 UUID。

建议指标：

- `account_exit_total{reason}`；
- `account_exit_local_failure_total{component}`；
- `account_exit_remote_unconfirmed_total`；
- `stale_account_write_blocked_total{source}`；
- `offline_queue_frozen_total`；
- `offline_queue_cross_account_blocked_total`；
- `account_data_purge_failure_total{phase}`。

## 18. 明确禁止

- 禁止退出时调用 SharedPreferences 全量 `clear()`；
- 禁止退出时清空整个 Isar 实例；
- 禁止删除全部 FlutterSecureStorage；
- 禁止 Token 失效时自动删除账号聊天、媒体或私钥；
- 禁止为了防串号而删除所有账号的本地记录；
- 禁止在新账号缓存为空时读取其他账号缓存；
- 禁止在账号 ID 为空时读取账号级缓存；
- 禁止让旧请求、旧 WebSocket、旧推送或旧离线队列在 epoch 变化后写入；
- 禁止把“服务器有密文”描述成“客户端一定能解密”；
- 禁止在服务端保留期限未明确前承诺恢复全部历史。

## 19. 最终决策

1. 默认退出、Token 失效和强制下线只清凭证与运行态，不删除账号持久聊天和 E2EE 私钥；
2. 账号数据通过 `accountId + accountEpoch` 同时解决持久隔离和异步竞态；
3. 离线消息和草稿作为本地唯一数据按账号冻结，不当作普通缓存；
4. 清缓存、清账号数据、重置加密身份是三个独立操作；
5. 当前后端已有短期消息 ID 幂等和精确退出基础，不重复建设；
6. 历史消息完整恢复和 E2EE 跨设备恢复列为前后端联合阶段；
7. 对外只承诺可验证的恢复范围，不使用无条件“恢复所有聊天记录”。
