# 全局黑白深色模式配色改造方案

## 1. 背景与目标

当前 Flutter 客户端已经在主题层建立了黑灰主色和深色模式，但页面级代码里还存在大量局部硬编码颜色，导致深色模式下部分按钮、链接、协议文字、输入框图标和弱提示文字不可读。

本次改造目标不是继续扩大灰色比例，而是把视觉主轴调整为清晰的黑白体系：

- 浅色模式：主色是黑色，主按钮黑底白字。
- 深色模式：页面接近纯黑，主按钮白底黑字。
- 输入框、卡片、列表使用深灰黑分层，不让页面灰蒙蒙。
- 链接、协议、找回密码、弱提示在深色模式下必须可读。
- Flutter App 深色登录体验向当前 H5 截图风格对齐：黑背景、深灰输入框、白色主按钮、清晰文字层级。

## 2. 当前扫描结论

### 2.1 主题层现状

`lib/core/theme/app_colors.dart` 已有这些基础色：

- `AppColors.primary = #0B0D12`
- `AppColors.darkBackground = #050505`
- `AppColors.darkSurface = #0B0B0C`
- `AppColors.darkInputBackground = #1F1F23`
- `AppColors.primaryDarkMode = #F3F4F6`
- `AppColors.onPrimaryDarkMode = #050505`

`lib/core/theme/app_theme.dart` 的深色按钮方向已经正确：

- `ElevatedButton` 深色模式背景为 `AppColors.primaryDarkMode`
- `FilledButton` 深色模式背景为 `AppColors.primaryDarkMode`
- 深色按钮文字为 `AppColors.onPrimaryDarkMode`
- 即深色模式主按钮是接近白底黑字

问题主要不在主题层，而在页面局部硬编码绕开了主题。

### 2.2 高风险硬编码

扫描到的高风险模式包括：

- `AppColors.primary` 直接用于深色模式链接、图标、勾选态、按钮前景色。
- `Colors.white30` / `Colors.white38` 用在深色背景上的提示、协议、输入框图标，亮度过低。
- `Colors.black38` / `Colors.black45` 在浅色模式可用，但没有统一映射到深色模式 token。
- `TextButton.styleFrom(foregroundColor: AppColors.primary)` 在深色模式下会变成黑色链接。
- `Checkbox(activeColor: AppColors.primary)` 在深色模式下选中态偏黑。
- `AppColors.primary.withOpacity(...)` 在深色模式下作为浅色强调背景会变成黑色透明层，和黑背景混在一起。

### 2.3 首批受影响页面

优先处理这些页面和组件：

- `lib/features/auth/pages/login_page.dart`
- `lib/features/auth/pages/register_page.dart`
- `lib/features/auth/pages/forgot_password_page.dart`
- `lib/features/auth/pages/agreement_page.dart`
- `lib/features/settings/pages/bind_phone_page.dart`
- `lib/features/settings/pages/settings_page.dart`
- `lib/features/settings/pages/profile_page.dart`
- `lib/features/settings/pages/privacy_settings_page.dart`
- `lib/features/wallet/pages/wallet_page.dart`
- `lib/features/wallet/pages/transfer_page.dart`
- `lib/features/wallet/pages/recharge_page.dart`
- `lib/features/chat/widgets/chat_list_item.dart`

## 3. 目标色板

### 3.1 浅色模式

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#F6F7F9` | 保持干净浅灰背景 |
| 卡片/列表 | `#FFFFFF` | 保持白色内容面 |
| 主色 | `#0B0D12` | 主品牌黑，不再偏灰 |
| 主按钮背景 | `#0B0D12` | 黑底 |
| 主按钮文字 | `#FFFFFF` | 白字 |
| 一级文字 | `#111827` | 主要标题和正文 |
| 二级文字 | `#6B7280` | 副标题、说明 |
| 三级文字 | `#9CA3AF` | 占位、弱提示 |
| 输入框背景 | `#F1F2F4` | 浅灰输入面 |
| 分割线 | `#E5E7EB` | 浅色边界 |
| 链接文字 | `#0B0D12` | 与品牌黑一致 |

### 3.2 深色模式

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#050505` | 接近纯黑，匹配 H5 截图气质 |
| 次级背景 | `#0B0B0C` | AppBar、底部导航 |
| 卡片背景 | `#111113` | 内容卡片 |
| 输入框背景 | `#1F1F23` | 深灰输入面，和黑背景拉开 |
| 主按钮背景 | `#F3F4F6` | 近白主按钮 |
| 主按钮文字 | `#050505` | 黑字 |
| 一级文字 | `#FFFFFF` | 标题、主要正文 |
| 二级文字 | `#A1A1AA` | 副标题、提示 |
| 三级文字 | `#8B8B93` | 弱提示最低可读线 |
| 禁用文字 | `#71717A` | 禁用态，不用于重要可读文案 |
| 输入框图标 | `#A1A1AA` | 不再使用 `white30` |
| 链接文字 | `#E4E4E7` | 深色模式协议、找回、注册链接 |
| 链接强调 | `#93C5FD` | 必要时用于更明显的文本链接 |
| 分割线 | `#2A2A2E` | 深色边界 |
| 选中控件背景 | `#F3F4F6` | checkbox/switch 选中 |
| 选中控件前景 | `#050505` | checkbox 勾、开关图标 |

### 3.3 不再使用的深色写法

深色模式页面中不要再直接使用：

- `AppColors.primary` 作为文字或图标色。
- `Colors.white30` 作为输入框图标、协议文字、提示文字。
- `Colors.white38` 作为可点击链接、协议、找回密码、注册入口。
- `AppColors.primary.withOpacity(...)` 作为深色强调底色。
- `Checkbox(activeColor: AppColors.primary)`。

## 4. 全局 Token 设计

在 `AppColors` 中补充语义方法，避免每个页面手写 `isDark ? ... : ...`。

### 4.1 文本 token

建议新增：

```dart
static Color textPrimaryFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? darkTextPrimary
      : lightTextPrimary;
}

static Color textSecondaryFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? darkTextSecondary
      : lightTextSecondary;
}

static Color textTertiaryFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? const Color(0xFF8B8B93)
      : lightTextTertiary;
}
```

### 4.2 链接 token

建议新增：

```dart
static Color linkFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? const Color(0xFFE4E4E7)
      : primary;
}

static Color linkEmphasisFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? const Color(0xFF93C5FD)
      : primary;
}
```

默认链接用 `linkFor`，只有需要明显强调的找回、客服、外链入口才用 `linkEmphasisFor`。

### 4.3 输入框 token

建议新增：

```dart
static Color inputBackgroundFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? darkInputBackground
      : lightInputBackground;
}

static Color inputIconFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? darkTextSecondary
      : lightTextSecondary;
}

static Color inputHintFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? darkTextSecondary
      : lightTextSecondary;
}
```

输入框图标和 hint 不再用 `white30`，最低使用 `darkTextSecondary`。

### 4.4 控件 token

建议新增：

```dart
static Color controlActiveFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? primaryDarkMode
      : primary;
}

static Color onControlActiveFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? onPrimaryDarkMode
      : Colors.white;
}

static Color controlBorderFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? primaryDarkModeBorder
      : lightDivider;
}
```

用于 `Checkbox`、`Switch`、分段按钮、选中态边框。

### 4.5 轻强调背景 token

建议新增：

```dart
static Color emphasisSoftFor(BuildContext context) {
  return Theme.of(context).brightness == Brightness.dark
      ? const Color(0xFF242428)
      : primary.withOpacity(0.08);
}
```

深色模式不能继续用黑色透明度叠黑背景，应直接给一个可见深灰面。

## 5. 改造阶段

### 阶段 1：主题与 token 收敛

目标：先建立统一可复用语义色，减少后续页面继续手写颜色。

改动文件：

- `lib/core/theme/app_colors.dart`
- `lib/core/theme/app_theme.dart`
- `test/core/theme/app_theme_test.dart`

改动内容：

- 新增文本、链接、输入框、控件、轻强调背景 token。
- 确认深色按钮仍为白底黑字。
- 确认浅色按钮仍为黑底白字。
- 深色 `TextButtonTheme` 使用 `linkFor` 或 `primaryDarkMode`，不再让局部链接默认黑色。
- 深色 `CheckboxTheme` 的 active/check 色保持白底黑勾。

验收：

- 浅色主按钮：黑底白字。
- 深色主按钮：白底黑字。
- 深色 TextButton 可见。
- 深色 checkbox 选中和未选中都可见。

### 阶段 2：认证入口优先修复

目标：先解决用户截图里最明显的登录页不可读问题，并同步注册、找回、协议、绑定手机号。

改动文件：

- `lib/features/auth/pages/login_page.dart`
- `lib/features/auth/pages/register_page.dart`
- `lib/features/auth/pages/forgot_password_page.dart`
- `lib/features/auth/pages/agreement_page.dart`
- `lib/features/settings/pages/bind_phone_page.dart`

改动规则：

- 背景使用 `AppColors.darkBackground` / `AppColors.lightBackground`。
- 输入框背景使用 `AppColors.inputBackgroundFor(context)`。
- 输入框图标使用 `AppColors.inputIconFor(context)`。
- hint 使用 `AppColors.inputHintFor(context)`。
- 标题使用 `AppColors.textPrimaryFor(context)`。
- 副标题使用 `AppColors.textSecondaryFor(context)`。
- 协议普通文案使用 `textSecondaryFor`，不要用 `white38`。
- 协议链接、注册入口、找回入口使用 `AppColors.linkFor(context)` 或 `linkEmphasisFor(context)`。
- `Checkbox(activeColor: AppColors.primary)` 改为 `AppColors.controlActiveFor(context)`。
- `Checkbox.checkColor` 明确使用 `AppColors.onControlActiveFor(context)`。
- 主按钮继续使用 `AppColors.primaryFor(context)` 和 `AppColors.onPrimaryFor(context)`。

登录页重点修复点：

- 找回密码入口当前 `TextButton.styleFrom(foregroundColor: AppColors.primary)` 在深色下会黑，改为 `linkFor`。
- 协议链接当前 `color: AppColors.primary` 在深色下会黑，改为 `linkFor`。
- checkbox active 当前 `AppColors.primary` 在深色下会黑，改为 `controlActiveFor`。
- 输入框图标当前 `Colors.white30` 太弱，改为 `inputIconFor`。
- 输入框 hint 当前 `Colors.white30` 太弱，改为 `inputHintFor`。

注册页重点修复点：

- 步骤条选中态、协议链接、checkbox、输入框图标统一迁移到 token。
- 深色弱提示从 `white30/white38` 提升到 `darkTextSecondary/darkTextTertiary`。

找回密码页重点修复点：

- 手机号、验证码、密码输入框图标和 hint 统一迁移到 token。
- 发送验证码按钮/文本链接深色可见。

### 阶段 3：设置与资料页修复

目标：修复高频设置页中的图标、选中态、链接文字和说明文字。

改动文件：

- `lib/features/settings/pages/settings_page.dart`
- `lib/features/settings/pages/profile_page.dart`
- `lib/features/settings/pages/privacy_settings_page.dart`
- `lib/features/settings/pages/chat_settings_page.dart`
- `lib/features/settings/pages/notification_settings_page.dart`
- `lib/features/settings/pages/devices_page.dart`
- `lib/features/settings/pages/stickers_page.dart`

改动规则：

- 功能图标如果是主题强调色，使用 `linkFor` 或 `controlActiveFor`。
- `Switch` / `Checkbox` activeColor 不再使用 `AppColors.primary`。
- `Icon(Icons.check, color: AppColors.primary)` 改为 `controlActiveFor`。
- 深色说明文案不再用 `white38`，可读说明用 `textSecondaryFor`，极弱注释才用 `textTertiaryFor`。
- 弹窗里的 TextButton 前景色使用主题或 `linkFor`。

验收：

- 设置页每个入口图标可见。
- 选中的选项、勾选、开关在深色模式清晰可见。
- 删除、退出等危险按钮保留红色语义，不受主色影响。

### 阶段 4：钱包与支付页修复

目标：避免金额、确认按钮、选择框、支付密码输入在深色模式下出现灰黑不可读。

改动文件：

- `lib/features/wallet/pages/wallet_page.dart`
- `lib/features/wallet/pages/transfer_page.dart`
- `lib/features/wallet/pages/recharge_page.dart`
- `lib/features/wallet/pages/withdraw_page.dart`
- `lib/features/wallet/pages/send_red_packet_page.dart`
- `lib/features/wallet/pages/set_pay_password_page.dart`
- `lib/features/wallet/widgets/pay_password_input.dart`
- `lib/features/wallet/widgets/amount_input.dart`

改动规则：

- 主操作按钮使用 `primaryFor/onPrimaryFor`。
- 选择金额、支付方式、银行卡等选中态使用 `controlActiveFor`。
- 深色背景上的金额辅助说明用 `textSecondaryFor`。
- 低透明黑色背景替换为 `emphasisSoftFor` 或深色卡片色。
- 支付密码圆点/边框选中态用 `controlActiveFor`，未选中边框用 `controlBorderFor`。

验收：

- 钱包首页余额、按钮、入口图标可见。
- 转账/充值/提现确认按钮深色白底黑字。
- 支付密码弹窗深色模式下输入格、文字、关闭按钮可见。

### 阶段 5：聊天列表与聊天组件修复

目标：修复聊天高频组件中的未读、选中、操作菜单、表情面板等深色可读性。

改动文件：

- `lib/features/chat/widgets/message_context_menu.dart`
- `lib/features/chat/widgets/chat_input_bar.dart`
- `lib/features/chat/widgets/create_sheets.dart`
- `lib/features/chat/widgets/message_bubble_text.dart`
- `lib/features/chat/widgets/message_bubble_voice.dart`
- `lib/features/chat/widgets/message_bubble_wallet_transfer_detail.dart`

改动规则：

- 聊天列表未读/置顶/选中背景不能使用黑色透明叠黑背景，改用 `emphasisSoftFor` 或明确深灰。
- 操作菜单图标和文字使用 `textPrimaryFor/textSecondaryFor`。
- 表情面板选中态使用 `controlActiveFor` 或 `emphasisSoftFor`。
- 消息气泡内的链接或强调文字在深色模式下不使用黑色主色。

验收：

- 深色聊天列表未读、时间、摘要、置顶标记清晰。
- 长按菜单文字和图标可见。
- 表情面板分类、选中态、搜索/空状态可读。

## 6. H5 对齐标准

当前 H5 源码 `h5/src/styles.css` 的认证页是浅色变量体系，但用户提供的深色截图已经明确了目标视觉。Flutter App 不需要逐像素复制 H5，但应满足以下视觉关系：

- 登录页背景接近 `#050505`。
- Logo 区域保持白底，突出品牌图。
- 标题白色，字号和字重接近 H5。
- 副标题使用中灰，不低于 `#A1A1AA`。
- 输入框使用 `#1F1F23` 左右的深灰，不使用纯黑。
- 输入框图标和 placeholder 使用 `#A1A1AA` 或接近值，不使用 `white30`。
- 主按钮使用 `#F3F4F6` 近白背景，文字 `#050505`。
- 注册、找回、协议链接在黑背景上必须可读。

## 7. 代码替换规则

### 7.1 必须替换

| 当前写法 | 替换为 |
| --- | --- |
| `color: AppColors.primary` 用于链接/协议 | `color: AppColors.linkFor(context)` |
| `foregroundColor: AppColors.primary` | `foregroundColor: AppColors.linkFor(context)` 或主题默认 |
| `activeColor: AppColors.primary` | `activeColor: AppColors.controlActiveFor(context)` |
| `checkColor: Colors.white` | `checkColor: AppColors.onControlActiveFor(context)` |
| `Colors.white30` 输入框图标 | `AppColors.inputIconFor(context)` |
| `Colors.white30` hint | `AppColors.inputHintFor(context)` |
| `Colors.white38` 协议/说明 | `AppColors.textSecondaryFor(context)` |
| `AppColors.primary.withOpacity(...)` 深色强调底 | `AppColors.emphasisSoftFor(context)` |

### 7.2 可以保留

这些场景可以保留固定黑白：

- 图片预览黑色背景。
- 视频播放黑色背景。
- 遮罩层 `Colors.black54` / `Colors.black87`。
- 白色图标叠在深色媒体遮罩上。
- 红色错误、绿色成功、黄色警告等语义颜色。
- 钱包金额等强语义品牌色，如果经深色验证可读。

### 7.3 需要人工判断

这些不做机械替换：

- 头像渐变色。
- 聊天气泡内的自己/对方消息颜色。
- 红包、转账、支付结果的业务色。
- 会员、装扮、个性化背景。
- 图片、视频、地图、文件预览的叠层文字。

## 8. 验收清单

### 8.1 静态检查

每个阶段完成后执行：

```powershell
pwsh -NoLogo -NoProfile -Command "dart analyze <改动文件列表>"
```

主题改动后执行：

```powershell
pwsh -NoLogo -NoProfile -Command "flutter test test/core/theme/app_theme_test.dart"
```

检查格式和空白：

```powershell
pwsh -NoLogo -NoProfile -Command "git diff --check"
```

### 8.2 页面验收

深色模式必须人工看以下页面：

- 登录页
- 注册页
- 找回密码页
- 协议页
- 绑定手机号页
- 设置首页

如果遇到签名冲突：

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"

```

然后重新安装。

## 9. 风险与控制

### 9.1 风险

- 全局机械替换 `AppColors.primary` 可能误伤浅色品牌强调。
- 钱包、红包、会员等业务色可能有独立视觉含义。
- 聊天消息气泡内颜色需要结合发送方、背景和媒体类型判断。
- H5 源码与截图不是同一套运行态颜色，不能直接照搬 CSS。
- 当前仓库有其他窗口开发，开工前需要重新看 `git status -sb`，避免覆盖他人改动。

### 9.2 控制方式

- 按阶段小步提交改动，不一次性全仓替换。
- 每阶段只处理一类语义色。
- 认证页先做完整样板，再扩散到设置/钱包/聊天。
- 每次改完跑 touched files 的 `dart analyze`。
- 能截图时做模拟器深色截图对照。
- 不改无关业务逻辑，不碰正在开发的通话服务、后端、资源导入等文件。

## 10. 推荐开工顺序

1. 新增 `AppColors` 语义 token，并补主题测试。
2. 改登录页，让它成为 H5 深色风格样板。
3. 同步注册、找回、协议、绑定手机号。
4. 修设置页和资料页高频入口。
5. 修钱包和支付密码相关页面。
6. 修聊天列表、表情面板、消息菜单。
7. 跑静态检查和主题测试。
8. 等其他窗口开发稳定后，再做 Android 模拟器打包安装和截图验收。

## 11. 完成标准

本次改色完成后，应满足：

- 浅色模式不再灰蒙蒙，主色明确是黑色。
- 深色模式页面接近纯黑，但内容层次清楚。
- 深色主按钮统一白底黑字。
- 浅色主按钮统一黑底白字。
- 登录、注册、找回、协议页面没有不可读文字。
- 设置、钱包、聊天高频页面没有按钮或链接消失。
- `AppColors.primary` 不再被当作深色模式通用文字色直接使用。
- 后续新增页面优先使用语义 token，而不是手写 `isDark ? Colors.white30 : Colors.black38`。
