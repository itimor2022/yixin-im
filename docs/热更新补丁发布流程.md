# 热更新补丁发布流程

本文档只说明当前项目已经落地的两条热更新链路：

- `self_hosted`：自托管整包更新
- `shorebird`：Dart 补丁热更新

如果你要直接照着操作，优先看这两份分拆 SOP：

- [安卓整包更新SOP.md](e:\yi-xin-ai2k\docs\安卓整包更新SOP.md)
- [Shorebird不重装补丁SOP.md](e:\yi-xin-ai2k\docs\Shorebird不重装补丁SOP.md)

## 1. 两种模式的边界

### 1.1 `self_hosted`

适用场景：

- Android APK 整包更新
- iOS 企业签名 / 分发页 / manifest 安装更新
- 需要修改原生代码、权限、插件原生部分、签名配置时

特点：

- 本质仍然是下载安装包
- Android 和 iOS 需要分别建补丁记录
- 后台现在已限制：`self_hosted` 不支持 `全平台`

### 1.2 `shorebird`

适用场景：

- 只修改 Flutter Dart 层代码
- 不改 `android/**`、`ios/**`
- 不改原生权限、原生插件实现、签名和包名

特点：

- 用户不需要重新安装
- 补丁会在客户端下载后，于下次重启生效
- 后台 `channel` 字段会映射到 Shorebird 的 `track`

## 2. 哪些改动能走补丁

可以走 `shorebird` 的改动：

- `lib/**` 下的 Dart 业务代码
- Dart 侧页面、状态、接口调用、文案
- 不涉及原生侧的纯 Flutter 逻辑

不能走 `shorebird` 的改动：

- `backend/**`
- `android/**`
- `ios/**`
- 权限变更
- 包名 / 签名 / 渠道包配置
- 原生插件代码
- 依赖里带原生二进制变更的改动

这些改动必须重新发包，必要时同时配合 `self_hosted` 或应用商店更新。

## 3. 当前版本号怎么看

当前 Flutter 应用版本号看项目根目录 `pubspec.yaml` 的 `version` 字段。

格式通常是：

```yaml
version: 4.0.1+10
```

含义：

- `4.0.1`：版本名
- `10`：构建号

这个版本号同时决定：

- 商店包版本
- Shorebird release 所绑定的 release version
- 后台热更新筛选时的版本匹配范围

## 4. 后台字段怎么填

### 4.1 通用字段

- `平台`
  - `self_hosted`：只能选 `android` 或 `ios`
  - `shorebird`：建议按实际平台分别建，也可用 `all` 做统一灰度开关
- `渠道`
  - 默认 `stable`
  - `shorebird` 下这里会映射到客户端 `track`
- `补丁版本`
  - 这是本项目后台里的业务标签
  - 仅用于后台展示、日志和上报查询
  - 不是 Shorebird 的官方 patch number
- `目标版本`
  - 可选
  - 客户端当前版本达到或超过该值后，不再命中这个补丁
- `App 版本范围 / Build 范围`
  - 用于控制哪些客户端能命中补丁
- `灰度比例`
  - 0-100
  - 按用户 / 设备 / IP 做稳定灰度命中

### 4.2 `self_hosted` 填写规则

- `补丁地址`
  - Android：直接可下载的 `.apk` 地址
  - iOS：`.plist` 地址，或 `itms-services://` 链接
- `补丁哈希`
  - 可选
  - 建议填 `sha256:...`

建议：

- Android 和 iOS 分开建两条记录
- 不要把下载页地址当作 APK / plist 地址

### 4.3 `shorebird` 填写规则

- `补丁地址`
  - 留空
- `补丁哈希`
  - 留空
- `渠道`
  - 填 Shorebird track，例如：
    - `stable`
    - `beta`
    - `staging`
    - 自定义 track 名

建议：

- `补丁版本` 用业务可读标签，例如：
  - `2026.05.10.1`
  - `4.0.1+10-p1`

## 5. `self_hosted` 发布流程

### 5.1 Android

1. 构建新的 APK
2. 上传到可直接下载的 HTTPS 地址
3. 在后台新建热更新补丁
4. `投递模式` 选择 `self_hosted`
5. `平台` 选择 `android`
6. 填入 APK 直链
7. 按需要设置灰度、版本范围、是否强制
8. 发布补丁

### 5.2 iOS

1. 准备 `.ipa`
2. 准备指向 `.ipa` 的 `manifest.plist`
3. 将 `plist` 和 `ipa` 放到可访问地址
4. 在后台新建热更新补丁
5. `投递模式` 选择 `self_hosted`
6. `平台` 选择 `ios`
7. 填入 `.plist` 地址或 `itms-services://` 链接
8. 发布补丁

## 6. `shorebird` 发布流程

以下命令基于 Shorebird 官方工作流：先做 release，再做 patch；patch 会绑定到既有 release version。

### 6.1 首次接入或新商店版本

当你准备发新的商店版本时，先做 Shorebird release，再提交到商店。

示例：

```bash
shorebird release android
shorebird release ios
```

前提：

- 这里使用的应用版本号，就是 `pubspec.yaml` 里的 `version`
- 商店里实际发出去的包，必须来自对应的 Shorebird release

### 6.2 对已上线版本发 Dart 补丁

确认本次改动只在 `lib/**` 后，再发 patch。

示例：

```bash
shorebird patch android --track=stable
shorebird patch ios --track=stable
```

如果要先灰度测试：

```bash
shorebird patch android --track=staging
shorebird patch ios --track=staging
```

验证没问题后，再把同一补丁切到正式 track。

根据 Shorebird 官方文档，可以用下面方式把补丁切到 `stable`：

```bash
shorebird patches set-track --release-version 4.0.1+10 --patch-number 1 --track stable
```

### 6.3 本项目后台如何配合 Shorebird

Shorebird 发完补丁后，还需要在本项目后台新增一条补丁记录，作用是：

- 控制灰度比例
- 控制哪些版本命中
- 控制是否强制
- 提供命中 / 应用上报查询

后台填写建议：

- `投递模式`：`shorebird`
- `渠道`：与实际 Shorebird track 一致
- `补丁版本`：填你自己的业务标签
- `补丁地址`：留空
- `补丁哈希`：留空

## 7. 推荐发布策略

### 7.1 紧急 Dart 修复

适合：

- 文案修正
- Flutter 页面 bug
- Dart 逻辑 bug

做法：

1. 改 `lib/**`
2. 走 Shorebird patch 到 `staging`
3. 小范围验证
4. 切到 `stable`
5. 后台建 `shorebird` 补丁记录做灰度和上报管理

### 7.2 原生或权限改动

适合：

- 相机 / 定位 / 通知权限调整
- 原生插件改动
- Android / iOS 工程配置改动

做法：

1. 正常重新发商店包或企业包
2. 如需站外整包更新，走 `self_hosted`

## 8. 当前项目里的实际生效方式

### 8.1 客户端

- `shorebird`
  - 启动时检查补丁
  - 下载完成后下次重启生效
- `self_hosted`
  - Android 下载 APK 后拉起安装器
  - iOS 打开 manifest / 安装页面

### 8.2 后台

当前后台已支持：

- 补丁列表
- 补丁发布 / 暂停 / 回滚
- `delivery_mode` 区分
- 补丁命中与应用结果上报
- `delivery_mode` 维度筛选

### 8.3 后端

当前后端已支持：

- 自动迁移 `delivery_mode`
- 历史空值回填为 `self_hosted`
- 查询时兼容历史空值
- 阻止 `self_hosted + 全平台`

## 9. 部署注意事项

- 改 `backend/**`：必须重新编译并重启后端
- 改 `admin/**`：必须重新构建并重新部署后台前端
- 改 Flutter `lib/**`：
  - 如果走 Shorebird，可不重装客户端
  - 但仍要确保现网包本身是 Shorebird release 构建出来的
- 改 `android/**`、`ios/**`：必须重新发包

## 10. 这套流程里最容易出错的地方

- 用普通 `flutter build` 发出去的包，想直接吃 Shorebird patch
- `self_hosted` 填下载页地址而不是 APK / plist 直链
- Android / iOS 共用一条 `self_hosted` 补丁
- 改了原生代码却还想走 Dart 补丁
- 后台 `channel` 和实际 Shorebird `track` 不一致
