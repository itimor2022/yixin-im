# 通用 IM 小白核心功能人工测试流程

> 适用对象：第一次参加 App 测试、不会使用命令行的测试人员。  
> 测试目标：用两台手机验证“能登录、能聊天、能收消息、能打电话、重开后不丢数据”等核心功能。  
> 建议耗时：60～90 分钟。

## 一、先记住 4 个测试结果

每一项只能填写下面一种结果：

| 结果 | 什么时候填写 |
| --- | --- |
| 通过 | 按步骤操作后，实际结果和预期结果完全一致 |
| 失败 | 能操作，但出现错误、闪退、白屏、数据不一致或结果不符合预期 |
| 阻塞 | 因服务器不可用、账号不可用、没有第三个账号等原因，无法开始测试 |
| 跳过 | 本轮明确不测，例如短信、真实支付、注销账号 |

注意：

- “阻塞”和“跳过”不能写成“通过”。
- 只要出现闪退、白屏、消息丢失、重复扣款或通话无法结束，立即停止并报告。
- 不要为了继续测试而自行卸载 App、清除数据、充值、注销账号或修改服务器。

## 二、测试前准备

### 1. 需要准备的东西

- 两台 Android 手机，下面称为“A 手机”和“B 手机”。
- A、B 两个测试账号，最好已经互为好友。
- 可选的 C 账号，用于创建三人群聊。
- 两台手机安装同一个版本的 App，并连接可用网络。
- 手机电量高于 30%，音量和麦克风可正常使用。
- 一个小于 10 MB 的图片和一个小文件，用于发送测试。

建议账号分工：

| 手机 | 账号 | 主要用途 |
| --- | --- | --- |
| A 手机 | 测试账号 A | 主动发送、发起通话、修改设置 |
| B 手机 | 测试账号 B | 接收、回复、离线、接听通话 |
| 可选账号 | 测试账号 C | 创建群聊、验证第三个群成员 |

### 2. 开始前必须记录

| 项目 | 填写内容 |
| --- | --- |
| 测试日期和时间 |  |
| 测试人员 |  |
| App 版本号 |  |
| A 手机品牌、型号、系统版本 |  |
| B 手机品牌、型号、系统版本 |  |
| A 测试账号 |  |
| B 测试账号 |  |
| 使用的网络 | Wi-Fi / 4G / 5G |
| 服务器环境 | 本地测试 / 测试环境 / 正式环境 |

### 3. 截图规则

- 每个失败至少保存 2 张图：操作前一张、出错后一张。
- 问题会动或一闪而过时，直接录屏。
- 截图文件建议命名为：`编号-手机-现象.png`，例如 `T08-B手机-消息未收到.png`。
- 测试聊天内容要带时间，建议使用：`A测试-1530-第1条`。

## 三、核心测试流程

请严格按编号顺序执行。P0 是“核心生死线”，任何一项失败都要先停止测试并报告；P1 可以记录问题后继续完成其他不受影响的项目。

### 第一阶段：启动和登录（P0，约 10 分钟）

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T01 | 完全关闭 A、B 两台手机上的 App，再重新打开 | 30 秒内进入登录页或首页；没有白屏、黑屏、闪退、一直转圈 |  |
| T02 | 如果未登录，A、B 分别输入正确账号和密码，点击“登录” | 两台手机都进入首页；头像、昵称和底部导航正常显示 |  |
| T03 | 在 A 手机上退出到登录页，故意输入一次错误密码 | 不会进入首页；页面给出明确的密码错误提示；App 不闪退 |  |
| T04 | A 使用正确密码重新登录 | 登录成功；会话列表能够正常加载 |  |
| T05 | 依次点击首页底部的“消息、联系人、发现/工作台、我的/设置”等入口 | 每个页面都能打开和返回；没有空白页、明显错字、按钮被遮挡 |  |

如果 T01、T02 或 T04 失败，不要继续测试聊天，先提交问题。

### 第二阶段：联系人和单聊入口（P1，约 5 分钟）

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T06 | A 进入“联系人”，搜索 B 的昵称或账号 | 能找到正确的 B；头像、昵称、账号没有串到其他人 |  |
| T07 | 点击 B 的资料，再点击“发消息” | 进入与 B 的单聊页面；顶部显示的是 B 的资料 |  |
| T08 | 如果 A、B 还不是好友，A 发好友申请，B 同意 | A、B 联系人列表都出现对方，并且可以进入聊天；如果账号已是好友，填写“跳过：已是好友” |  |

### 第三阶段：文字消息可靠性（P0，约 15 分钟）

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T09 | A 给 B 发送一条带时间的中文消息，例如“人工测试-1530” | A 端立即出现该消息；B 在数秒内收到；文字完整且没有乱码 |  |
| T10 | B 回复 A 一条消息 | A 在数秒内收到；发送人方向、头像和内容正确 |  |
| T11 | A 连续发送 10 条消息，内容写成“第1条”到“第10条” | B 正好收到 10 条；顺序正确；没有缺失、重复或一直显示发送中 |  |
| T12 | A、B 同时各发送 3 条消息 | 最后两台手机看到的消息内容和顺序一致，没有覆盖或重复 |  |
| T13 | B 回到手机桌面；A 再给 B 发 2 条消息；等待 10 秒后 B 回到 App | B 回到 App 后能看到这 2 条消息；会话未读数和实际未读条数基本一致 |  |
| T14 | A、B 都返回消息列表，再重新进入同一个聊天 | 刚才的消息仍然存在；列表最后一条预览与聊天内最后一条一致 |  |
| T15 | 完全关闭 B 的 App；A 发送 2 条新消息；再打开 B 的 App | B 能补收到或加载出 2 条消息；没有丢失和重复 |  |

T09～T15 任意一项出现消息丢失、重复、错人或顺序严重错误，都按 P0 失败处理。

### 第四阶段：图片、语音和消息操作（P1，约 10 分钟）

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T16 | A 点击聊天输入区旁的“+”或附件按钮，选择一张图片并发送 | 权限弹窗文案正常；图片发送成功；B 能看到缩略图并打开大图 |  |
| T17 | A 切换到语音输入，按住说话 3～5 秒后发送；B 点击播放 | 语音发送成功；B 能听到声音；播放状态不会卡住 |  |
| T18 | A 发送一个小文件；B 点击文件 | 文件名和大小显示合理；B 能下载或打开；失败时有明确提示 |  |
| T19 | A 长按自己刚发的普通文字，分别检查“复制、回复、转发、撤回、删除”等菜单 | 菜单能正常显示；复制内容正确；回复能对应原消息；危险操作要先测试“取消” |  |
| T20 | A 撤回一条刚发出的测试消息 | A、B 都显示撤回结果；被撤回的原内容不应继续正常显示 |  |

如果某个附件入口在当前版本不存在，填写“跳过：当前版本无此入口”，不要填写“通过”。

### 第五阶段：断网、未读和恢复（P0，约 10 分钟）

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T21 | 关闭 A 手机的 Wi-Fi 和移动数据，再发送一条“断网测试” | App 显示发送中或发送失败，不应假装发送成功，也不应闪退 |  |
| T22 | 恢复 A 手机网络，点击失败消息的“重试”（如果有） | 消息最终只发送一次；B 只收到一条，不会重复 |  |
| T23 | B 停留在消息列表，A 连续发送 3 条消息 | B 的未读角标及时增加；点进会话后未读数清零 |  |
| T24 | B 按 Home 键回桌面，A 再发一条消息 | 如果本环境支持通知，B 收到正确发送人和内容的通知；不支持时填写“阻塞”并说明原因 |  |
| T25 | B 回到 App，然后完全关闭并重新打开 | App 能恢复登录状态和最新消息；没有白屏、重复消息或未读数乱跳 |  |

### 第六阶段：群聊（P1，约 10 分钟）

> 最好准备 A、B、C 三个账号。没有第三个账号时，不能证明多人群聊正常，应填写“阻塞：缺少第三账号”。

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T26 | A 创建一个测试群，邀请 B 和 C | 三个账号都出现同一个群；群名和成员人数正确 |  |
| T27 | A、B、C 分别发送一条文字 | 三端都能收到，发送人姓名和头像正确 |  |
| T28 | A 在群里发送图片，并 @B | B 能看到图片并收到 @ 提醒；C 能正常看到消息但不应显示成“被 @” |  |
| T29 | A 修改群名并发布一条群公告 | B、C 能看到新群名和公告；刷新或重开群聊后仍然存在 |  |
| T30 | 非群主账号尝试进入管理功能 | 普通成员不能执行只有群主或管理员才有权执行的操作，并有明确提示 |  |

测试结束后可保留测试群，也可由群主正常解散；不要误操作真实业务群。

### 第七阶段：语音和视频通话（P0，约 10～15 分钟）

测试前先确认手机没有静音，并允许麦克风、相机权限。

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T31 | A 向 B 发起语音通话，B 接听，双方各说一句话，保持 10 秒后挂断 | B 能收到来电；双方能听到声音；挂断后返回聊天页并出现正确通话记录 |  |
| T32 | A 再次发起语音通话，B 点击拒绝 | 第二次仍能正常呼叫；双方正确显示“已拒绝/未接听”等状态，不会卡在通话中 |  |
| T33 | B 反向向 A 发起语音通话，A 接听后挂断 | 反向呼叫正常；挂断后双方都能再次操作聊天 |  |
| T34 | A 发起视频通话，B 接听；依次测试静音、扬声器、关闭摄像头、切换前后摄像头 | 双方画面和按钮状态正确；某项不支持时有提示，不应黑屏或闪退 |  |
| T35 | 视频通话中一方按 Home 键，5 秒后回到 App，再正常挂断 | 回到 App 后通话状态正确；能正常挂断；不会一直占用通话状态 |  |
| T36 | 挂断后立刻再发起一次视频通话，然后由对方拒绝 | 可以再次发起；拒绝后双方都回到正常页面 |  |

通话无声、无画面、无法挂断、挂断后不能再次呼叫，都按 P0 失败处理。

### 第八阶段：搜索、个人资料和退出（P1，约 10 分钟）

| 编号 | 操作步骤 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| T37 | 使用首页搜索，搜索联系人昵称和刚发送过的聊天关键词 | 搜索结果正确；点击结果能进入对应联系人或定位到对应消息 |  |
| T38 | A 进入“我的/设置 → 个人资料”，修改测试昵称或签名并保存 | 保存成功；返回后仍显示新内容；B 刷新后能看到合理的最新资料 |  |
| T39 | 进入通知、隐私、通用等设置页面，各切换一个无风险开关后返回再进入 | 开关状态按设计保存；页面可正常返回；没有设置串项 |  |
| T40 | 进入“退出登录”，先在确认弹窗点击“取消”，再重新操作并确认退出 | 取消时仍保持登录；确认后回到登录页；使用原账号可再次登录 |  |

不要测试“注销账号”，除非负责人明确提供了可销毁的专用账号。

## 四、本轮默认不计入核心通过率的项目

下列项目依赖外部服务、真实资金或特殊账号，应单独安排专项测试：

- 手机号注册、短信验证码、找回密码、绑定手机号。
- 充值、提现、红包、转账和支付密码。
- 账号注销、真实账号封禁、踢出设备。
- 推送在锁屏、厂商省电模式、无后台权限下的长期稳定性。
- 会议、频道、朋友圈、直播等非即时通信核心功能。
- 长时间压力、百人群、弱网抖动、多设备同时登录。

未执行时应填写“阻塞”或“跳过”并写明原因，不能因为没有测试就判定通过。

## 五、发现问题时怎么记录

直接复制下面模板，每个问题单独填写一份：

```text
问题标题：
测试编号：例如 T15
发生时间：
手机和系统：
App 版本：
测试账号：
使用网络：

操作步骤：
1.
2.
3.

预期结果：
实际结果：
是否每次都能出现：是 / 否，出现次数 __ / __
是否影响继续测试：是 / 否
截图或录屏文件：
补充说明：
```

一个合格的问题标题应能直接说明“在哪里、做什么、出了什么问题”，例如：

```text
[T15][B手机] 离线期间收到的两条消息，重开 App 后只显示一条
```

不要只写“聊天有问题”或“不能用”。

最终结论只允许使用下面三种：

- **核心通过**：所有 P0 都通过，P1 没有影响主流程的失败。
- **有条件通过**：所有 P0 都通过，但存在已知的 P1 问题或外部阻塞，必须逐项列出。
- **不通过**：任意 P0 失败，或 App 出现闪退、白屏、消息丢失、通话无法结束等严重问题。
