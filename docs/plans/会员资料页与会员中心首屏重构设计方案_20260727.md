# 会员资料页与会员中心首屏重构设计方案

日期：2026-07-27  
范围：联系人资料页会员头图、资料卡衔接、会员中心顶部身份卡与首屏信息层级  
状态：设计方案，确认后再实施；本文不代表代码已经改造完成

## 一、结论

本轮不再围绕某一个间距反复微调，建议统一重构两个入口：

1. **联系人资料页会员头图**：改为按设备形态选择固定高度档位，进入页面后不再随昵称、徽章、在线状态和系统字体动态改变背景高度。
2. **会员中心顶部身份卡**：从当前偏高、留白过大的 244 高卡片改为紧凑的固定高度身份卡，重排身份、有效期、价格和状态信息。
3. **可读性统一**：VIP、SVIP、自定义背景均使用稳定的前景色和遮罩规则，不能再把白字直接放在浅金、浅粉或高亮图片上。
4. **资料卡正常衔接**：个人简介卡从头图下方正常开始，不悬空、不压住头图边界，也不因背景估算误差产生白色断层。

推荐视觉方向为：**深色沉浸头图 + 克制暖金点缀 + 清晰白色信息 + 浅色内容卡**。会员感通过材质、徽章和微弱光效表达，不靠大面积高亮金色和超大装饰图标堆砌。

## 二、当前问题

### 1. 联系人资料页

- 顶部背景高度根据安全区、头像、字体缩放、昵称行、在线状态和操作按钮进行估算，背景层与真实内容层不是同一个布局约束，容易产生边界偏差。
- SVIP 渐变从深棕过渡到亮金，四个操作按钮和文字位于最亮区域，白字对比度不足。
- 昵称、SVIP 徽章、钱包样式徽章、表情状态和官方认证全部挤在一行，信息竞争明显。
- 个人资料卡靠头图太近，部分尺寸下视觉上像压在头图边缘，比例不稳定。
- 不同账号背景亮度差异过大，但前景色只按 VIP 等级判断，不能覆盖自定义背景和异常图片。

### 2. 会员中心

- 顶部会员卡高度固定为 244，但有效内容主要集中在左上和左下，中间形成大面积无意义留白。
- 68 的圆形图标、26 的标题、66 的钻石装饰同时抢视觉焦点。
- 套餐、当前状态、价格和有效期的层级不明确，用户需要多看几次才能理解当前卡片代表什么。
- 会员卡、权益区和购买栏虽然功能齐全，但首屏比例更像活动页，不像稳定、可信的账户资产页面。

## 三、联系人资料页设计

### 1. 固定高度规则

“固定高度”采用**设备档位固定**，不再根据昵称、徽章数量和在线状态实时计算：

| 设备形态 | 头图内容高度（不含顶部安全区） | 头像 | 操作按钮 |
|---|---:|---:|---:|
| 紧凑手机：宽度小于 360 或可用高度小于 700 | 300 | 76 | 44 |
| 标准手机：360–479 宽度 | 312 | 84 | 48 |
| 平板、桌面窄面板 | 304 | 80 | 46 |

最终头图高度为：`顶部安全区 + 固定内容高度`。

约束：

- 页面进入后高度不跳动；
- 数据加载前后使用同一高度；
- 长昵称、徽章和字体变化只能在内部截断或降级展示，不能撑高头图；
- 横屏统一使用紧凑档位；
- 桌面端最大内容宽度保持现有 600，不把头图拉成超宽横幅。

### 2. 头图垂直结构

```text
┌────────────────────────────────┐
│ 系统安全区：背景延伸，图标按亮度显示 │
├────────────────────────────────┤
│ ←                         ···  │  52
│                                │
│             头像                │  76/84
│         昵称    官方标识          │
│         SVIP · 很久以前           │
│                                │
│   消息      通话      视频      搜索 │  固定等宽
│                                │
└────────────────────────────────┘
        16 间距
┌────────────────────────────────┐
│ 个人简介                         │
│ 高余额钱包测试账号                │
│ ────────────────────────────── │
│ 用户名              二维码        │
│ @demo_tina                     │
└────────────────────────────────┘
```

### 3. 昵称与会员身份排版

- 第一行只放：昵称、官方认证；昵称单行省略。
- 第二行放：VIP/SVIP 徽章、在线状态或最后上线时间。
- 表情状态有内容时放在第二行末尾；空间不足时优先保留会员等级和在线状态。
- 不再同时展示多个语义重复的会员徽章；后台徽章与系统 SVIP 徽章按优先级只显示一个主徽章。
- 昵称字号标准手机 22，紧凑手机 20；会员副信息 13–14。

### 4. 背景与文字对比度

- 头图统一使用白色主文字，不再根据 VIP 等级切换深蓝文字。
- 所有背景之上叠加三段式深色遮罩：
  - 导航区约 28% 黑色；
  - 头像区约 14% 黑色；
  - 操作区约 36% 黑色。
- 四个操作按钮使用半透明深色圆形底，不再使用白色透明底叠在亮金背景上。
- 背景图案透明度控制在 8%–12%，不能干扰昵称、状态和操作文案。
- 白色主要文字与背景目标对比度不低于 4.5:1；次要文字不低于 3:1。
- 自定义背景加载失败时继续使用会员等级渐变兜底，不能出现空白或闪白。

### 5. 个人资料卡

- 与头图保持固定 16 间距，不做负边距悬浮。
- 标准手机左右边距 16，圆角 18，内部水平间距 18。
- 信息顺序统一为“小标签在上、内容在下”：
  - 个人简介；
  - 分隔线；
  - 用户名与二维码。
- 简介最多 3 行，超过后省略并提供点击展开。
- 二维码点击区域至少 44×44，避免只有小图标可点。
- 加载中使用同尺寸骨架，不允许资料加载完成后整卡上下跳动。

## 四、会员中心顶部设计

### 1. 尺寸与比例

- 导航栏内容高度固定 52，顶部安全区单独计算。
- 手机会员身份卡固定高度由 244 调整为 **196**。
- 平板和桌面卡片固定高度 208，最大内容宽度 560。
- 卡片底部圆角由 32 调整为 24，减轻“巨大横幅”感觉。
- 卡片下方滑动提示和页码区域固定 30–34 高。

### 2. 身份卡信息结构

```text
┌────────────────────────────────┐
│ [56 图标]  VIP        [当前/已选择] │
│           有效期至 2027/07/27      │
│                                │
│ 当前权益状态              会员徽章水印 │
│ VIP 年卡                 $168.00 │
└────────────────────────────────┘
        左右滑动 ·  ●  ○  ○
```

- 左侧等级图标由 68 缩小到 56。
- 标题由 26 调整为 24；状态标签与标题同一基线。
- 有效期或套餐说明最多两行。
- 底部固定为“套餐名/权益状态 + 价格”，用户不需要在装饰中寻找关键信息。
- 右侧钻石改为 56–72 的低透明度水印，不再成为主视觉。
- 删除无业务含义的大面积粒子和大圆环，只保留轻微流光；系统减少动画时完全静止。

### 3. 页面信息层级

会员中心完整顺序保持为：

1. 当前会员身份卡；
2. 核心权益 2×2 信息块；
3. VIP/SVIP 等级选择；
4. 套餐时长与价格选择；
5. 钱包余额；
6. 底部固定购买栏。

要求：

- 当前等级、续费、升级、不可降级状态必须使用明确文字；
- 选择套餐后权益、价格和购买按钮同步；
- 钱包不足时展示余额与差额，并提供充值入口；
- 加载失败在对应区域就地重试，不让整个页面只显示错误；
- 无套餐时隐藏无效购买栏；
- 购买中禁用重复点击，购买结果必须明确。

## 五、兼容性设计

### 1. 屏幕与安全区

必须覆盖：

- 320、360、393、432、480 逻辑宽度；
- 640、700、800 及以上可用高度；
- Android 刘海、挖孔、状态栏；
- iPhone 安全区和底部手势区域；
- MuMu/Android Studio 模拟器；
- 平板、H5、Windows 桌面窄面板。

### 2. 字体与多语言

- 头图属于固定展示区域，文字缩放在 1.0–1.3 内完整适配；
- 超过 1.3 时昵称和操作标签单行省略，语义标签仍完整提供给辅助功能；
- 简体中文、繁体中文、英文分别检查按钮长度；
- 英文操作项优先使用短文案，例如 `Message / Call / Video / Search`。

### 3. 数据兼容

保留现有背景解析顺序：

1. `profile_background_url`、`profile_background`、`profile_card_background`；
2. `nickname_color` 中的 `bg:index`；
3. VIP/SVIP 默认背景；
4. 用户 ID 默认渐变。

不得因为 UI 改版导致旧用户背景、昵称颜色、会员徽章、官方认证和表情状态失效。

### 4. 性能与体验

- 背景 SVG、头像和徽章放入独立重绘边界，避免滚动时整页重绘；
- 网络背景提供占位和失败兜底；
- 头图和会员卡加载前后尺寸一致，避免布局跳动；
- 动画时长控制在 180–280ms，并尊重系统“减少动画”；
- 点击区域不小于 44×44；
- 页面返回后滚动位置和选中套餐保持合理状态。

## 六、实施范围

建议第一期只处理视觉与布局，不改会员计费和后台数据结构：

- `lib/features/chat/pages/user_profile_page.dart`
- `lib/features/vip/pages/vip_center_page.dart`
- 必要时拆分资料头图、会员身份卡、资料信息卡组件
- 增加尺寸、文字缩放、长昵称和多徽章组件测试

第一期不做：

- 升级补差价；
- 新支付方式；
- 修改后台会员等级逻辑；
- 删除或迁移旧用户背景字段；
- 全局主题重做。

## 七、验收标准

### 联系人资料页

- 头图高度在同一设备档位内固定，加载前后不变化；
- 资料卡与头图之间始终有 16 间距，无重叠、白条和裁切；
- SVIP 亮金背景下昵称、状态、四个操作文字清晰；
- 20 字以上昵称、多徽章、英文、1.3 倍字体无溢出；
- 返回、更多按钮与状态栏在所有背景上可见。

### 会员中心

- 196 高身份卡内没有大面积无意义空白；
- 当前等级、有效期、套餐、价格在 3 秒内可以识别；
- 普通用户、VIP、SVIP、过期、冻结状态比例一致；
- 横滑时卡片、权益、价格和购买按钮同步；
- 小屏、桌面窄面板和深浅色模式无溢出。

### 验证证据

- Flutter 目标文件静态检查和组件测试；
- 320/360/393/432/480 宽度截图对比；
- MuMu 模拟器实际页面；
- Android 真机资料页和会员中心截图；
- 至少覆盖普通用户、VIP、SVIP 三类账号；
- 用户确认视觉后再提交或发布。

## 八、推荐实施顺序

1. 先重构资料页固定头图与遮罩，解决当前最明显的白字和边界问题；
2. 重排昵称、徽章、状态和四个操作入口；
3. 重做个人资料卡衔接；
4. 压缩会员中心身份卡并重排信息；
5. 完成多尺寸、长昵称、字体缩放和三类会员状态验证；
6. 提供模拟器与真机截图，由用户确认后再进入发布流程。
