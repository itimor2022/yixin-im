# 生物识别解锁修复方案

## 背景

隐私页已有“面容/指纹解锁”开关，代码使用 `local_auth` 做生物识别验证，并把开关状态保存到 `privacy_biometric`。

当前问题是：页面开关存在，但 Android/iOS 原生配置和应用锁闭环不完整，容易出现“生物识别验证失败”，并且开启后不一定真正参与 App 启动/回前台解锁。

## 当前判断

### Android

现状：

- `pubspec.yaml` 已接入 `local_auth`。
- `privacy_settings_page.dart` 已调用 `LocalAuthentication.authenticate(...)`。
- `MainActivity` 当前继承 `FlutterActivity`。
- `AndroidManifest.xml` 未看到 `android.permission.USE_BIOMETRIC` / `android.permission.USE_FINGERPRINT`。

风险：

- `local_auth` 在 Android 上通常需要 `FlutterFragmentActivity` 才能稳定弹出系统认证。
- 缺少生物识别权限时，部分 Android 版本或设备会直接失败。
- 模拟器如果没有录入指纹，也会验证失败。

### iOS

现状：

- iOS Pod 已包含 `local_auth_darwin`。
- `Info.plist` 未看到 `NSFaceIDUsageDescription`。

风险：

- iOS 使用 Face ID 必须配置 `NSFaceIDUsageDescription`，否则可能认证失败或被系统拒绝。
- 模拟器/设备没有配置 Face ID/Touch ID 时，验证会失败。

### 业务闭环

现状：

- 开启开关时会调用一次系统认证。
- 认证成功后保存 `privacy_biometric=true`。
- 没看到完整的 App 冷启动、回前台、自动锁定后强制生物识别解锁流程。

风险：

- 用户以为开启了“应用解锁”，但实际只是在设置页验证了一次。
- 如果未和“应用锁定密码”“自动锁定”打通，功能体验不完整。

## 修复目标

P0 目标：

- Android 和 iOS 都能正常弹出生物识别验证。
- 开关失败时给出准确原因，不再只提示“生物识别验证失败”。
- 开启后至少保存状态可靠，不出现误开启。

P1 目标：

- 接入完整应用锁：App 冷启动、后台超过自动锁定时间、回前台时触发生物识别/密码解锁。
- 无生物识别能力时，自动降级为应用锁定密码。

## P0 修复方案

### 1. Android 原生配置

文件：`android/app/src/main/AndroidManifest.xml`

新增权限：

```xml
<uses-permission android:name="android.permission.USE_BIOMETRIC"/>
<uses-permission android:name="android.permission.USE_FINGERPRINT"/>
```

建议放在麦克风/音视频权限附近。

### 2. Android Activity 改造

文件：`android/app/src/main/kotlin/com/genericim/app/MainActivity.kt`

将：

```kotlin
import io.flutter.embedding.android.FlutterActivity

class MainActivity : FlutterActivity() {
```

改为：

```kotlin
import io.flutter.embedding.android.FlutterFragmentActivity

class MainActivity : FlutterFragmentActivity() {
```

注意：

- 保留现有 `configureFlutterEngine`、MethodChannel、通知逻辑。
- 改完后必须跑 Android 构建，确认插件注册和现有原生通道不受影响。

### 3. iOS Face ID 描述

文件：`ios/Runner/Info.plist`

新增：

```xml
<key>NSFaceIDUsageDescription</key>
<string>用于通过面容 ID 验证身份并解锁应用</string>
```

建议放在相机、麦克风权限描述附近。

### 4. 设置页认证前置检查

文件：`lib/features/settings/pages/privacy_settings_page.dart`

在开启生物识别前先检查：

- `isDeviceSupported()`
- `canCheckBiometrics`
- `getAvailableBiometrics()`

逻辑建议：

- 设备不支持：提示“当前设备不支持生物识别”。
- 未录入指纹/面容：提示“请先在系统设置中录入指纹或面容”。
- 系统取消：提示“已取消验证”，不要当成失败。
- 插件异常：提示“生物识别不可用，请稍后重试或使用应用锁密码”。

### 5. 异常分类

引入 `local_auth/error_codes.dart`，根据错误码处理：

- `notAvailable`
- `notEnrolled`
- `lockedOut`
- `permanentlyLockedOut`
- `passcodeNotSet`

这样用户不会只看到笼统的“生物识别验证失败”。

## P1 完整闭环方案

### 1. 新增应用锁服务

建议新增文件：

`lib/core/services/app_lock_service.dart`

职责：

- 读取 `privacy_biometric`
- 读取 `privacy_app_lock`
- 读取 `privacy_auto_lock`
- 记录 App 进入后台时间
- 判断回前台是否需要锁定
- 提供 `unlockWithBiometric()` 和 `unlockWithPasscode()`

### 2. App 生命周期接入

建议接入位置：

- `lib/app.dart`
- 或根级 `ConsumerStatefulWidget`

监听：

- `AppLifecycleState.paused`
- `AppLifecycleState.inactive`
- `AppLifecycleState.resumed`

流程：

1. App 进入后台时记录时间。
2. App 回前台时，根据 `privacy_auto_lock` 判断是否需要锁定。
3. 如果开启生物识别，优先弹系统认证。
4. 如果认证失败或不可用，降级到应用锁定密码。

### 3. 锁屏页

建议新增：

`lib/features/settings/pages/app_lock_gate_page.dart`

功能：

- 全屏遮罩，阻止进入主界面。
- 显示“使用面容/指纹解锁”按钮。
- 显示“使用密码解锁”备用入口。
- 禁止通过返回键绕过。

### 4. 与自动锁定打通

现有隐私页已有“自动锁定”选项。

建议语义：

- `immediately`：每次回前台都锁。
- `1_minute`：后台超过 1 分钟锁。
- `5_minutes`：后台超过 5 分钟锁。
- `1_hour`：后台超过 1 小时锁。
- `5_hours`：后台超过 5 小时锁。

### 5. 与应用锁定密码打通

规则建议：

- 开启生物识别前，如果没有设置应用锁密码，提示先设置密码。
- 生物识别只是快捷解锁，密码是兜底。
- 生物识别失败超过系统限制后，走应用锁密码。

## 验证清单

### Android 模拟器

1. 系统设置里录入指纹。
2. 安装本地包。
3. 进入隐私页。
4. 打开“面容/指纹解锁”。
5. 系统弹出指纹验证。
6. 验证成功后开关保持开启。
7. 关闭后开关保持关闭。

注意：

- 未录入指纹时，应提示“请先录入指纹或面容”。
- 模拟器没有生物识别配置时，失败是正常的环境问题。

### Android 真机

1. 指纹设备测试。
2. 面容设备测试。
3. 未录入生物识别测试。
4. 锁定后多次失败测试。
5. 后台超过自动锁定时间后回前台测试。

### iOS 模拟器

1. 启用 Face ID 模拟。
2. 打开“面容/指纹解锁”。
3. 触发 Face ID 成功。
4. 触发 Face ID 失败。

### iOS 真机

1. Face ID 机型测试。
2. Touch ID 机型测试。
3. 未设置 Face ID/Touch ID 测试。
4. 用户取消系统弹窗测试。
5. 后台回前台自动锁测试。

## 风险点

- `MainActivity` 改为 `FlutterFragmentActivity` 后，需要确认现有 MethodChannel、通知、厂商推送逻辑仍正常。
- 生物识别不能作为唯一解锁方式，必须保留密码兜底。
- 模拟器测试结果不能完全代表真机，尤其是 Face ID/厂商指纹。
- iOS 如果缺少 `NSFaceIDUsageDescription`，Face ID 会失败。
- Android 如果没有录入指纹或系统锁屏密码，`local_auth` 会返回不可用。

## 建议实施顺序

1. 先做 P0 原生配置修复。
2. Android 模拟器验证开关能正常弹系统认证。
3. Android 真机验证指纹/面容。
4. iOS 补 `Info.plist` 后在真机验证。
5. 再做 P1 应用锁完整闭环。
