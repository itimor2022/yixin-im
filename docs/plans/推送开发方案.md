# 通用 IM 全平台推送开发方案

## 目标

把推送能力做成统一网关，业务层只调用一个入口，不直接依赖具体厂商。

```text
业务事件 -> PushGateway -> 极光 JPush -> APNs / FCM / 国内厂商通道
```

后续如果极光不满足需求，可以替换为个推或自建厂商通道，聊天、好友申请、群通知等业务代码不用重写。

## 总体选择

P0 先接入极光 JPush，原因是落地快、厂商通道覆盖全、后台测试和日志能力成熟。

统一保留抽象：

```text
PushGateway
  JPushProvider
  GetuiProvider（预留）
  NativeProvider（预留：APNs/FCM/华为/荣耀/小米/OPPO/vivo 自建）
```

设备侧保存：

```text
platform: android / ios
brand: HUAWEI / HONOR / XIAOMI / OPPO / VIVO / APPLE
push_provider: jpush / apns / fcm / hms / honor / mi / oppo / vivo
push_token: 极光 registration_id 或厂商 token
```

## P0：打通统一推送闭环

目标：先让线上版本能稳定发测试推送、聊天离线提醒和系统通知。

当前开发状态：

```text
已完成：
后端 JPush 通道、token 注册兼容、推送日志、后台测试发送
后台推送配置页面、场景开关、最近日志展示、demo 只读
Android 可选 JPush SDK 依赖、registrationId 获取桥接、设备信息上报
初始化 SQL 增加 user_devices 扩展字段和 push_delivery_logs

待真机验收：
配置极光 AppKey/MasterSecret 后，Android 真机登录上报 jpush registrationId
后台按用户 ID/设备 ID 发送测试推送
App 杀进程后收到聊天离线提醒
```


新增服务：

```text
backend/internal/services/push_gateway.go
backend/internal/services/push_jpush.go
```

统一方法：

```go
SendToUser(ctx, userID, scene, title, body, data)
SendToDevice(ctx, deviceID, scene, title, body, data)
```

P0 支持场景：

```text
chat_message      私聊/群聊离线消息
friend_request    好友申请
group_notice      群邀请/入群审核
system_notice     系统通知
```

发送策略：

```text
用户在线：优先 WebSocket，不重复发通知
用户离线：走 JPush
发送结果：写 push_logs
失败兜底：保留未读，用户上线后主动拉取
```

### App

Flutter 端接入极光 SDK：

```text
Android 获取 registration_id
iOS 获取 registration_id，并配置 APNs
登录后上报 device_id + platform + brand + registration_id
token 变化时重新上报
退出登录时解绑当前设备
```

新增接口：

```text
POST /api/v1/devices/register-push
POST /api/v1/devices/unbind-push
```

Android 打包配置：

```properties
ENABLE_VENDOR_PUSH_SDK=true
PUSH_JPUSH_APP_KEY=极光控制台 AppKey
PUSH_JPUSH_CHANNEL=default
JPUSH_SDK=cn.jiguang.sdk:jpush:5.5.0
JCORE_SDK=cn.jiguang.sdk:jcore:5.2.0
```

### 管理后台

新增页面：`系统配置 -> 推送配置`

P0 配置项：

```text

默认通知标题
聊天消息是否推送
好友申请是否推送
```

敏感字段：


能力：

```text

```

### 验收标准

```text
Android 真机登录后能上报 registration_id
iOS 登录后能上报 registration_id

push_logs 能看到成功和失败记录
```

## P1：完善国内厂商通道和消息分类

目标：提升国内 Android 离线到达率，减少被厂商限流或降级。

当前开发状态：

```text
已完成：
后台推送配置页展示 APNs/JPush/FCM/HMS/小米/OPPO/荣耀/vivo/魅族状态
后台新增聊天消息、服务通知、运营通知三类分类配置
后端发送前自动按场景注入 push_category/message_category
JPush 下发 options.classification，区分系统类和运营类
HMS 保留已验证 data message payload，不改通知结构

待真机验收：
极光控制台完成荣耀/vivo/魅族等厂商参数后，按机型测试到达率
如果要启用自定义 channel_id，需要 App 侧先创建对应通知渠道
小米私信/公信分类和模板规则需要按小米平台审核结果继续配置
```

## P2：运营化、监控和可替换能力

目标：把推送从“能发”升级为“可运营、可监控、可替换”。

当前开发状态：

```text
已完成：
后台推送监控卡片：24小时发送数、成功率、失败数、异常通道、无效设备、Token失败
后台按通道统计成功率，并支持日志按通道/状态/用户ID/设备ID筛选
后端新增 GET /admin/push/stats 统计接口
后端新增主供应商/备用供应商配置：jpush/getui/native/fcm/hms/xiaomi/oppo/apns/none
后端新增频控配置：单用户每分钟上限、单用户每日运营推送上限
后端新增运营类夜间免打扰配置
后端发送前按策略拦截营销推送和超频推送

保留预留：
getui/native 是可替换供应商配置位，当前未接实际 SDK
推送任务列表、定时推送、模板、用户筛选群发需要单独运营任务表和调度器
点击数需要客户端点击回传接口，不能仅靠发送日志推断
```

### 推送运营

新增后台：

```text
推送任务列表
定时推送
按用户筛选推送
按平台/品牌筛选推送
推送模板
推送频控
```

频控规则：

```text
单用户每分钟最多 N 条
营销类每天最多 N 条
夜间免打扰
同会话多条消息合并
```

### 多供应商切换

保留配置：

```text
primary_provider: jpush / getui / native
fallback_provider: none / getui / native
```

失败切换策略：

```text
JPush 配置异常 -> 停止发送并报警
JPush 网络失败 -> 可切到 fallback
厂商 token 无效 -> 不切换，标记设备
```

```text

Huawei HMS
```


### 验收标准

```text
后台能创建定时推送任务

```
