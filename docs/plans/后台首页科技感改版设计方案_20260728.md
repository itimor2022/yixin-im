# 后台首页科技感改版设计方案

**日期：** 2026-07-28  
**适用端：** 管理后台 PC、窄屏浏览器  
**当前技术栈：** Vue 3、Element Plus、ECharts、Iconify  
**实施原则：** 保留现有真实数据和接口，先做首页信息架构与视觉升级，再逐步增加运营数据。

## 1. 背景与目标

当前后台首页已经具备实时指标、待审核任务、用户增长趋势、在线用户、最新注册用户、快速操作和服务器状态等模块。下一阶段目标是将它整理为一个“运营指挥中枢”：

- 首屏快速判断用户、审核、服务和存储状态。
- 保持后台工具的紧凑、专业和可扫描性。
- 通过克制的状态动画和数据动效体现科技感，不做营销式大屏。
- 兼容浅色、深色主题和不同宽度的 PC/H5 浏览器。
- 不改变现有业务接口，保证改版期间数据口径稳定。

## 2. 当前代码基础

首页入口：

- `admin/src/views/dashboard/console/index.vue`

当前首页模块：

- `modules/card-list.vue`：实时指标和系统健康
- `modules/pending-tasks-card.vue`：待审核任务
- `modules/user-growth-chart.vue`：用户增长趋势
- `modules/quick-actions.vue`：快速操作
- `modules/online-user-list.vue`：在线用户
- `modules/new-user-list.vue`：最新注册用户
- `modules/server-status-card.vue`：服务器运行状态

可继续复用的能力：

- Element Plus 布局、标签、按钮、骨架屏和加载状态
- ECharts 趋势图
- Iconify/`ArtSvgIcon` 图标
- 现有 `art-card`、主题变量和深色模式
- 现有后台统计、审核、运行状态接口

## 3. 首页信息架构

建议首页结构如下：

```text
┌─────────────────────────────────────────────────────────────┐
│ 运营中枢  系统运行正常  数据更新时间  自动刷新 / 全局刷新      │
├─────────────────────────────────────────────────────────────┤
│ 总用户  今日新增  在线用户  群/频道  待审核  系统异常           │
├───────────────────────────────────────┬─────────────────────┤
│ 核心趋势分析                           │ 系统健康状态          │
│ 用户 / 消息 / 媒体 / 流量切换           │ API / MySQL / Redis  │
│ ECharts 趋势图                         │ MongoDB / 存储服务   │
├───────────────────────────────────────┼─────────────────────┤
│ 待处理任务                             │ 快速操作              │
│ 举报 / 提现 / 充值 / 动态审核            │ 用户 / 群聊 / 消息 / 存储│
├───────────────────────────────────────┴─────────────────────┤
│ 在线用户 / 最新注册用户 / 存储与媒体处理状态                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 顶部运行栏

- 左侧显示“运营中枢”和当前环境标记，例如 `本地`、`测试`、`生产`。
- 中间显示系统总体状态、最近一次成功刷新时间。
- 右侧提供自动刷新状态、手动刷新和进入设置的入口。
- 不使用大面积欢迎语或营销式 Hero 区域，保留首屏业务密度。

### 3.2 核心指标区

保留六项核心指标：

1. 总用户数
2. 今日新增用户
3. 当前在线用户
4. 群组/频道数量
5. 待处理任务
6. 系统异常项

每个指标包含数值、辅助说明、与上一个周期的变化值和可点击跳转入口。异常和待审核数量大于 0 时显示低频边框高亮。

### 3.3 趋势与健康区

左侧使用 ECharts 展示趋势数据，提供以下切换：

- 用户增长
- 消息量
- 图片上传量
- 视频上传量
- 文件上传量

时间范围先支持近 7 天和近 30 天。右侧显示 API、MySQL、MongoDB、Redis，以及当前存储提供商的状态。

### 3.4 待处理任务与快捷操作

待处理任务按照优先级排列：

- 举报审核
- 提现审核
- 充值订单
- 动态审核

快捷操作使用图标加文字按钮，直达用户、群聊、消息、媒体存储和系统配置页面。避免将熟悉的命令做成纯文字长按钮。

### 3.5 用户与媒体运营区

保留在线用户和最新注册用户列表，同时新增“媒体与存储状态”模块：

- 当前存储提供商：S3、Aliyun OSS 或 Local
- 今日图片、视频、文件上传量
- 视频封面处理队列
- 转码失败数量
- 存储空间使用率
- 最近一次媒体处理时间

该模块可以直接反映聊天图片直传和视频处理链路的运行情况。

## 4. 视觉规范

### 4.1 色彩

采用“深石墨 + 青绿色信号色”的运维科技风格：

- 深色背景：`#0F1720`、`#111C27`
- 浅色背景：沿用现有白色和浅灰体系
- 主信号色：青绿色，例如 `#17C3B2`
- 正常：绿色
- 警告：琥珀色
- 异常：红色

不使用大面积紫色渐变、装饰性光球、粒子堆叠和高饱和背景。渐变只允许用于图表面积或极小范围的边缘状态，不作为页面主背景。

### 4.2 卡片和排版

- 卡片圆角保持 4～8px。
- 页面区块使用完整的横向布局，不使用卡片套卡片。
- 使用 1px 边框、细分割线和局部状态色增加层次。
- 数字指标使用较粗字重和紧凑数字字体。
- 标题保持 15～18px，避免后台页面出现过大的 Hero 标题。
- 正文、表格和辅助信息使用现有 Element Plus 字号体系。

### 4.3 深色模式

- 复用 `--default-bg-color`、`--default-box-color`、`--art-card-border` 等现有主题变量。
- 深色背景可增加非常浅的网格纹理，但不使用会影响文字对比度的背景动画。
- 浅色模式保持白底和浅灰分割线，青绿色只用于状态和重点数据。

## 5. 动效规范

动效只服务于数据状态和反馈，不影响操作：

- 页面加载：模块按 60～80ms 间隔依次出现。
- 指标刷新：数字使用 500～900ms 缓动变化。
- 图表：线条从左向右渐进绘制，数据切换时平滑过渡。
- 服务状态：正常状态小圆点低频呼吸，异常状态低频脉冲。
- 刷新操作：只在数据区域显示 200～500ms 的刷新反馈，不遮挡整页。
- 任务告警：使用一次性边框高亮，不连续闪烁。
- 支持 `prefers-reduced-motion`，用户关闭动画后仍然完整可用。

性能约束：

- 不引入 WebGL 粒子背景。
- 图表在可视区域初始化。
- 统一清理定时器、图表实例和监听器。
- 移动端减少阴影、模糊和动画数量。

## 6. 数据和接口策略

### P0 复用现有接口

- `getDashboardStats`
- `getRuntimeStatus`
- `getReportStats`、`getReportList`
- `getWithdrawStats`、`getWithdrawList`
- `getRechargeOrders`
- `getMomentList`
- `getUserStatsDetail`
- `getUserList`

P0 不新增后端接口，只调整数据展示、状态处理和跳转关系。接口失败时保留上一次成功数据，并明确显示失败时间。

### P1 增加运营数据

建议新增或扩展以下数据：

- 消息发送量趋势
- 图片、视频、文件上传量趋势
- S3/OSS/Local 存储容量和可用空间
- 视频封面处理队列
- 视频转码失败数量
- 媒体处理平均耗时
- 最近媒体处理异常记录

### P2 实时化和个性化

- 使用 WebSocket 或 SSE 推送关键状态。
- 支持管理员选择首页模块。
- 支持告警阈值配置。
- 支持多环境状态切换和首页数据导出。
- 增加管理员操作审计入口。

## 7. 分阶段实施计划

### P0：视觉和布局升级

- 重排首页信息架构。
- 增加顶部运行栏。
- 升级指标区和健康状态区。
- 增加数字、图表和状态动效。
- 优化待审核任务和快捷操作。
- 完成深色/浅色主题适配。
- 完成 PC、平板和窄屏浏览器适配。

### P1：运营能力增强

- 增加消息和媒体趋势。
- 增加存储提供商状态。
- 增加媒体处理队列和失败提示。
- 增加首页告警中心。
- 增加指标点击跳转和最近操作记录。

### P2：实时化和个性化

- 接入 WebSocket/SSE。
- 支持首页模块配置。
- 支持告警阈值和多环境管理。
- 支持首页数据导出和操作审计。

## 8. 验收标准

- 1366px、1920px、平板和手机宽度下布局无重叠、无横向溢出。
- PC 首屏可看到核心指标和系统健康状态。
- 深色、浅色模式下文字和状态色均清晰可读。
- 首次加载无明显布局跳动。
- 接口延迟或失败时页面不白屏，旧数据和错误状态可识别。
- 指标、待审核、在线用户和存储状态与接口数据一致。
- 点击指标和快捷操作可以进入对应管理页面。
- 动画在普通办公电脑和移动 H5 浏览器上保持流畅。
- 开启减少动画后页面仍完整可用。
- 首页定时器、图表实例和监听器在离开页面后全部清理。

## 9. 推荐实施顺序

先完成 P0，形成稳定的“科技运维控制台”视觉基线；再接入 P1 的媒体和存储运营数据；最后根据客户交付演示和实际使用频率决定是否实施 P2 实时化能力。
