# Amazon S3 图片、视频、文件上传闭环开发方案

> 项目：`genericim-tongba`  
> 日期：2026-07-27  
> 方案状态：P0 已完成；P1 Android 核心链路、媒体处理与真机韧性验收已完成  
> 目标：完成图片、视频、语音、普通文件从上传、发送、访问到删除回收的全流程闭环

## 1. 建议结论

建议分三期实施：

| 优先级 | 目标 | 上线结果 | 预计工期 |
|---|---|---|---:|
| P0 | 先把现有上传接口安全接入 S3 | 图片、视频、语音、文件、头像和后台素材可完整上传、发送、访问、删除；客户端基本无感 | 4～6 个工作日 |
| P1 | 解决大文件、弱网和私密访问 | 视频/大文件客户端直传、分片上传、断点续传、签名访问、缩略图 | 5～8 个工作日 |
| P2 | 提升安全、成本和运维能力 | 历史文件迁移、病毒扫描、转码、生命周期、灾备和成本分析 | 5～10 个工作日 |

核心建议：

1. **P0 保持现有 `/upload/*` 接口不变**，由 Go 后端统一写入 S3，先保证所有旧版本 App 可用。
2. **P1 将超过 100 MB 的视频和文件改为 S3 预签名直传**，否则业务服务器会承担双倍流量，且容易受 Nginx、Go、容器和移动网络超时影响。
3. S3 Bucket 必须保持私有，开启 Block Public Access、关闭 ACL，通过 CloudFront OAC 提供访问。
4. 不只记录一个 URL，必须新增媒体对象生命周期记录，才能处理“上传成功但消息发送失败”、孤儿文件、重复完成、删除失败重试等问题。
5. 普通文件不能继续允许任意后缀。P0 必须改成白名单，并同时校验后缀、MIME、文件头和实际文件结构。

## 2. 当前项目基线

### 2.1 已有上传入口

后端已经存在以下登录态接口：

- `/upload/image`
- `/upload/images`
- `/upload/video`
- `/upload/avatar`
- `/upload/voice`
- `/upload/file`
- 管理后台通用图片上传

现有代码已经具备：

- `local / aliyun / qiniu` 对象存储适配层；
- 图片、视频、语音的 MIME 和文件头检查；
- 按会员等级校验单文件大小；
- 上传日志；
- 根据公开 URL 反解 object key；
- 账号数据清理时删除外部对象并重试。

因此 S3 应扩展现有对象存储适配层，不另建一套孤立上传逻辑。

### 2.2 当前会员文件上限

| 等级 | 图片 | 视频 | 语音 | 普通文件 |
|---|---:|---:|---:|---:|
| 免费用户 | 10 MB | 100 MB | 20 MB | 100 MB |
| VIP | 20 MB | 300 MB | 50 MB | 500 MB |
| SVIP | 50 MB | 1 GB | 100 MB | 2 GB |

其中 VIP/SVIP 的视频和普通文件上限已经超过后端代理上传的合理范围。

**发布边界：**

- P0 可以完成 S3 闭环，但建议代理上传只承诺单文件不超过 100 MB；
- 当前套餐中超过 100 MB 的能力，应在 P1 直传和分片上传完成后正式开放；
- 如果必须在 P0 就支持 300 MB～2 GB，工期应直接包含 P1，不能只调大 Nginx 请求体和超时时间后就对外承诺稳定。

## 3. 全流程目标

```text
选择文件
   ↓
登录、会员等级、频率、大小、类型校验
   ↓
创建上传记录 pending
   ↓
上传到 S3
   ↓
校验对象大小、MIME、文件头、checksum
   ↓
标记 uploaded，返回 media_id
   ↓
发送消息时绑定 media_id
   ↓
标记 bound，接收方可查看/播放/下载
   ↓
消息/账号删除或超过保留期
   ↓
异步删除 S3 对象，失败自动重试
   ↓
标记 deleted，并完成审计
```

必须覆盖的异常：

- 用户取消选择：不创建对象；
- 已申请但未上传：到期后自动失效；
- S3 上传成功但完成确认失败：允许幂等重试；
- 上传成功但消息发送失败：对象暂存 24 小时，允许重新发送，超时后清理；
- 消息已发送但客户端超时：重复请求不能生成重复消息或重复媒体记录；
- 删除 S3 失败：业务记录进入 `deleting`，后台任务重试并告警；
- 对象不存在：删除操作仍按幂等成功处理，同时记录审计异常；
- CDN 暂未刷新：客户端短时重试，不能重新上传同一文件。

## 4. 数据模型

现有 `upload_logs` 适合记录请求结果，但不能代表媒体生命周期。建议新增 `media_objects`：

| 字段 | 用途 |
|---|---|
| `id` | 对外使用的 `media_id` |
| `user_id` | 上传者 |
| `client_request_id` | 客户端幂等键 |
| `category` | image、video、voice、file、avatar、admin_asset |
| `provider` | local、aliyun、qiniu、s3 |
| `bucket` | 存储桶 |
| `object_key` | 服务端生成的 S3 key |
| `original_name` | 原始文件名，仅用于展示 |
| `normalized_ext` | 校验后规范化后缀 |
| `declared_mime` | 客户端声明 MIME |
| `detected_mime` | 服务端识别 MIME |
| `size_bytes` | 实际大小 |
| `checksum` | 完整性校验值 |
| `status` | pending、uploading、uploaded、bound、quarantined、deleting、deleted、failed |
| `business_type` | message、avatar、discover、vip_badge 等 |
| `business_id` | 消息或业务记录 ID |
| `expires_at` | 未绑定对象失效时间 |
| `bound_at` | 完成业务绑定时间 |
| `deleted_at` | 删除完成时间 |

约束：

- `(user_id, client_request_id)` 唯一，保证上传申请幂等；
- object key 只能由后端生成，不接受客户端自定义完整路径；
- 发送消息时校验 `media_id` 属于当前用户、状态为 `uploaded`、未过期且媒体类型匹配；
- 同一对象如果允许被多个业务引用，应增加引用表或引用计数，不能删除一条消息就直接误删共享对象。

## 5. 文件类型建议

### 5.1 P0 推荐白名单

| 分类 | P0 推荐允许 | 处理建议 |
|---|---|---|
| 图片 | JPG/JPEG、PNG、WebP | App 端继续压缩；保留原图时限制分辨率和大小 |
| iPhone 图片 | HEIC/HEIF | 可接收，但建议生成 JPEG/WebP 展示版本，避免部分端无法预览 |
| 动图 | GIF | 可选开放；限制尺寸、总帧数和文件大小 |
| 视频 | MP4；必要时接收 MOV | 推荐播放格式统一为 H.264 + AAC 的 MP4 |
| 语音 | M4A/AAC、MP3 | 移动端录音优先 M4A/AAC；MP3 用于外部音频 |
| 文档 | PDF、DOCX、XLSX、PPTX、TXT、CSV | 只下载，不在服务端执行；Office 文件校验 ZIP 容器结构 |
| 压缩包 | ZIP | 可选开放；不在服务端自动解压，限制压缩后和展开后的体积 |

### 5.2 暂不建议开放

- AVI、WMV、FLV、MKV：移动端兼容性和转码成本高；
- RAR、7Z：除非客户明确需要，否则放到 P1/P2，先增加病毒扫描和压缩炸弹防护；
- DOC、XLS、PPT 老格式：兼容性、安全扫描和在线预览成本更高；
- SVG、HTML、XML：可能携带脚本或主动内容；
- DOCM、XLSM、PPTM：包含宏；
- EXE、MSI、APK、BAT、CMD、PS1、SH、COM、DLL、JAR、JS；
- PHP、JSP、ASP、ASPX 等服务端脚本；
- ISO、DMG、SCR、LNK、REG 等安装、镜像或系统控制文件；
- 双后缀、空后缀、超长文件名、控制字符文件名。

### 5.3 最终推荐

第一版建议只开放这组类型：

```text
图片：jpg、jpeg、png、webp、heic、heif
视频：mp4、mov
语音：m4a、aac、mp3
文件：pdf、docx、xlsx、pptx、txt、csv、zip
```

如果强调“各端都能稳定打开”，则优先级为：

1. 图片优先 JPG/WebP；
2. 视频优先 MP4（H.264 + AAC）；
3. 文档优先 PDF；
4. 可编辑办公文件再开放 DOCX/XLSX/PPTX；
5. 压缩包 ZIP 最后开放，并配合病毒扫描。

不能只根据文件名或请求头判断类型。服务端应按“后缀白名单 + MIME 白名单 + 文件头/文件结构 + 大小”共同校验。OWASP 也建议使用允许列表，并且不要信任客户端提供的 Content-Type：

- <https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html>
- <https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html>

## 6. P0：S3 基础接入与业务闭环

### 6.1 后端存储适配

在现有对象存储服务中新增 `s3` provider：

- AWS SDK for Go V2；
- `PutObject`/Upload Manager；
- `HeadObject`；
- `DeleteObject`；
- CloudFront URL 与 object key 双向转换；
- `Content-Type`、`Content-Disposition`、`Cache-Control`；
- checksum 记录和上传后验证；
- AWS request id、耗时和错误码日志。

object key 继续保持稳定规则：

```text
uploads/{category}/{yyyy}/{MM}/{dd}/{uuid}.{ext}
```

原始文件名只保存到数据库或安全处理后的 `Content-Disposition`，不能直接作为 key。

### 6.2 AWS 和 CDN 配置

- S3 Bucket 开启全部 Block Public Access；
- Object Ownership 使用 `Bucket owner enforced`，禁用对象 ACL；
- 默认 SSE-S3 加密；有合规要求再使用 SSE-KMS；
- CloudFront 使用 OAC 访问私有 S3 Origin；
- 后台使用的 IAM 访问密钥只允许指定 Bucket 和前缀所需的 Put、Get/Head、Delete、Multipart 权限；
- AWS Access Key ID 与 Secret Access Key 由管理后台录入，使用 AES-GCM 加密保存到数据库；管理接口只回显掩码，App、H5 和安装包不保存也不接收 AWS 密钥；
- 开发、预发布和生产使用不同 Bucket，或至少使用严格隔离的前缀和 IAM 策略；
- 生产使用独立媒体域名，例如 `media.example.com`。

AWS 官方建议保持 S3 非公开、开启 Block Public Access 并禁用 ACL；CloudFront 私有 S3 Origin 推荐使用 OAC：

- <https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html>
- <https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html>

### 6.3 上传接口兼容

P0 保留现有 `/upload/*` 路径和旧字段，同时增加：

```json
{
  "media_id": "media_xxx",
  "url": "https://media.example.com/uploads/...",
  "size": 123456,
  "mime_type": "image/jpeg",
  "checksum": "...",
  "status": "uploaded"
}
```

兼容策略：

- 老版本 App 继续使用 `url` 发消息；
- 新版本 App 优先发送 `media_id`，URL 只用于展示；
- 后端在兼容期内同时接受 URL 和 `media_id`；
- 兼容期结束后，聊天消息必须通过 `media_id` 校验所有权和状态，防止用户注入任意外链。

### 6.4 消息绑定

发送图片、视频、语音或文件消息时：

1. 查询 `media_id`；
2. 校验上传者是当前用户；
3. 校验状态为 `uploaded` 且未过期；
4. 校验 category 与消息类型一致；
5. 创建消息并将媒体标记为 `bound`；
6. 两个动作尽量放在同一数据库事务中；
7. 重复提交使用客户端消息 ID 保证幂等。

### 6.5 访问和下载

P0 为兼容现有消息结构，可以继续返回不可枚举的 CloudFront URL，但需明确：

- URL 本身相当于访问凭证；
- 它只能防止目录遍历和猜测，不能实现真正的聊天成员授权；
- 头像、发现页素材、会员徽章适合公开 CDN 缓存；
- 私聊/群聊图片、视频、语音和文件的真正私密访问应由 P1 的签名 URL 完成。

视频验收必须支持 HTTP Range，播放器请求应正确返回 `206 Partial Content`。

### 6.6 删除和回收

- 用户只上传未发送：24 小时后清理；
- 上传申请未完成：1 小时失效；
- 账号注销：沿用现有外部清理任务，按 object key 删除并重试；
- 消息撤回/删除：先按产品规则确定“仅本人不可见”还是“全局删除”，不能一律立即删 S3；
- 没有业务引用的对象进入 `deleting`；
- 删除成功标记 `deleted`；
- 删除失败按 1 分钟、10 分钟、1 小时、6 小时重试，最终进入人工处理队列；
- 每日任务核对数据库孤儿记录与 S3 对象。

### 6.7 管理后台

增加 Amazon S3 配置：

- Region；
- Bucket；
- CloudFront/媒体域名；
- 自定义 Endpoint，仅供兼容 S3 服务或本地测试；
- Path Style 开关；
- 凭证来源状态，不回显 Secret；
- “测试连接”按钮。

连接测试闭环：

1. 写入临时小文件；
2. `HeadObject` 验证；
3. 通过配置的媒体域名检查访问；
4. 删除临时对象；
5. 返回每一步结果和 AWS request id，不返回凭证。

### 6.8 P0 验收标准

- 图片、视频、语音、PDF/Office/ZIP 分别上传成功；
- 两台真机完成“发送方上传发送 → 接收方查看/播放/下载”；
- Android、iOS/H5 至少覆盖项目实际发布端；
- 视频可拖动播放，并验证 Range `206`；
- 文件名、MIME、下载文件内容一致；
- 超大文件、伪造 MIME、改后缀、双后缀、脚本文件均被拒绝；
- A 用户不能绑定 B 用户的 `media_id`；
- 上传成功后不发消息，24 小时后对象被清理；
- 发送消息失败后重试，不重复上传、不生成重复消息；
- 删除失败能进入重试队列并产生告警；
- 切回 `local` 后旧媒体和已上传 S3 媒体仍可访问；
- 日志和接口响应中无 AWS Secret。

## 7. P1：大文件直传、断点续传和私密访问

> 2026-07-28 开发状态：直传 API、100 MB 分界、16 MB multipart、持久化上传会话、
> 服务端分片查询、分片重试与恢复、complete 幂等校验、主动取消、超时回收、
> 聊天成员短期访问 URL，以及 Flutter 视频/普通文件优先直传均已实现。服务端已完成
> 图片缩略图、HEIC/HEIF 转 JPEG、MOV/WebM 转 H.264/AAC MP4、视频 JPEG 封面和
> 远端 Range 快速抽帧；Android 真机已完成断网、网络切换、退后台、杀进程恢复及
> 实际慢 S3 链路验收。部署配置与验收边界见
> `docs/deployment/AMAZON_S3_P1_DEPLOYMENT.md`。病毒扫描仍属于 P2 安全基础设施。

### 7.1 直传 API

新增统一流程：

```text
POST /media/uploads/init
PUT  S3 presigned URL 或 multipart 各分片
POST /media/uploads/{id}/complete
POST /media/uploads/{id}/abort
GET  /media/uploads/{id}
```

`init` 请求包含：

- `client_request_id`
- `category`
- `file_name`
- `size`
- `mime_type`
- `checksum`

后端先校验登录、会员等级、大小、类型和上传频率，再返回：

- `upload_id`
- `object_key`
- `mode: single | multipart`
- 预签名 URL 或分片 URL；
- 必须携带的请求头；
- 分片大小；
- 到期时间。

预签名 URL 必须短期有效、固定 object key、固定方法和必要请求头。客户端绝不持有 AWS Access Key/Secret。AWS 官方预签名上传说明：

- <https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html>
- <https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html>

### 7.2 分片规则

- 小于 100 MB：单次预签名 PUT；
- 大于等于 100 MB：multipart upload；
- 移动端建议分片 8～16 MB，按网络和总大小动态调整；
- 保存 upload id、已完成 part number、ETag 和 checksum；
- App 被杀、网络切换或请求超时后可以续传；
- `complete` 必须幂等，重复调用返回相同媒体结果；
- App 主动取消时调用 abort；
- S3 Lifecycle 在 7 天后自动中止未完成 multipart。

AWS 建议在对象达到约 100 MB 时考虑 multipart upload，并为未完成分片配置生命周期清理：

- <https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html>
- <https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpu-abort-incomplete-mpu-lifecycle-config.html>

### 7.3 完成确认

客户端直传成功不等于业务上传成功。`complete` 必须由后端执行：

1. 校验 upload id 和用户；
2. 完成 multipart；
3. `HeadObject`/对象属性校验 key、大小、MIME、checksum；
4. 必要时抽取文件头或异步安全扫描；
5. 校验通过才标记 `uploaded`；
6. 返回可发送的 `media_id`；
7. 校验失败进入 `quarantined` 或删除对象。

### 7.4 私密媒体访问

建议分类处理：

| 资产 | 访问策略 |
|---|---|
| 头像、发现页图标/横幅、VIP 徽章 | CloudFront 公共缓存 URL |
| 私聊/群聊图片、视频、语音、文件 | 后端鉴权后返回短期 CloudFront 签名 URL |
| 管理后台内部文件 | 后台权限校验后签名访问 |

签名 URL 应有较短有效期，客户端在接近过期或返回 403 时刷新，数据库继续保存 `media_id/object_key`，不保存即将过期的签名 URL。

### 7.5 媒体处理

- 图片生成缩略图和预览图，保留原图按业务开关；
- HEIC/HEIF 转 JPEG/WebP 展示版本；
- 视频抽取时长、宽高和封面；
- MOV/WebM 等输入异步规范化为 H.264 + AAC MP4；
- 转码前可先发送“处理中”消息，完成后更新可播放状态；
- 普通文件生成安全的下载文件名；
- H5 直传配置精确 CORS Origin、PUT/HEAD、必要请求头，并暴露 ETag/checksum。

### 7.6 P1 验收标准

- 100 MB、300 MB、1 GB、2 GB 对应等级文件按权益正确放行或拒绝；
- 弱网、Wi-Fi/蜂窝切换、App 退后台后可继续或恢复上传；
- 某一分片失败只重传该分片；
- complete 重试不产生重复对象；
- 未完成分片 7 天后由 S3 自动清理；
- 非聊天成员拿到 object key 也不能直接访问；
- 签名 URL 过期可刷新，转发旧 URL 在过期后不可用；
- 图片缩略图、视频封面和视频播放均正常；
- iOS、Android、H5 的真实设备或浏览器均完成验收。

## 8. P2：安全、迁移、成本和灾备

### 8.1 历史文件迁移

1. 扫描本地/OSS/七牛历史对象；
2. 生成 dry-run 清单；
3. 以相同或映射后的 object key 上传 S3；
4. 按 size + checksum 校验；
5. 建立旧 URL 到 `media_id/object_key` 映射；
6. 双读观察；
7. 数据库分批更新；
8. 保留原文件和数据库备份；
9. 抽查通过并经过保留期后再清理旧存储。

历史迁移不与 P0 上线强绑定。P0 只改变新上传文件的落盘位置，旧 URL 继续可访问。

### 8.2 安全增强

- 文档和压缩包进入隔离区，病毒扫描通过后才可下载；
- ZIP 检查层数、文件数量和解压后总大小，防止压缩炸弹；
- 图片解码后重编码，移除危险元数据；
- 视频解码/转码后再发布；
- 用户、IP、群组维度限速和并发控制；
- 异常格式、连续失败和高流量触发风控；
- 定期执行 S3 Inventory 与数据库媒体记录核对。

### 8.3 成本和生命周期

- 区分原图、缩略图、转码视频、临时对象和日志前缀；
- 未绑定临时对象 24 小时删除；
- 未完成 multipart 7 天中止；
- 长期未访问的大文件根据实际访问数据转低频存储；
- 统计上传流量、下载流量、CDN 命中率、存储增长、转码成本；
- 不直接对所有小对象启用复杂归档策略，先以 30 天真实数据决定。

### 8.4 灾备

- 生产 Bucket 开启版本控制需结合删除成本评估；
- 核心客户如需区域级灾备，再启用跨区域复制；
- 定期恢复抽查，而不是只确认“备份任务成功”；
- 配置、IAM、CloudFront 和生命周期规则纳入基础设施版本管理；
- 提供 provider 回切和媒体域名回源切换预案。

## 9. 监控指标

管理后台和告警至少覆盖：

- 上传请求数、成功率、P50/P95/P99 耗时；
- 按图片、视频、语音、文件分类的大小和失败率；
- S3 4xx/5xx、超时和限流；
- presigned init、complete、abort 数量；
- multipart 未完成数量和占用空间；
- `uploaded` 超过 24 小时未绑定数量；
- 删除重试数、最终失败数；
- CDN 命中率、403、404、5xx；
- 用户上传流量和存储增长；
- 每日 S3、CloudFront 和转码估算成本。

告警建议：

- 5 分钟上传失败率超过 5%；
- S3 连续错误或签名错误；
- 删除失败累计超过阈值；
- 孤儿对象增长异常；
- 单用户短时大流量；
- CDN 403/404 异常上升。

## 11. 上线顺序和回滚

### P0 上线

1. 合并数据库 migration 和后端代码，但 provider 保持 `local`；
2. 创建私有 S3 Bucket、专用最小权限 IAM Access Key、CloudFront OAC 和媒体域名；
3. 管理后台执行连接测试；
4. 预发布验证全部媒体类型；
5. 生产切到 `s3`；
6. 两台真机和 H5 进行上传、发送、播放、下载、删除冒烟测试；
7. 观察 24～48 小时；
8. 不删除原上传目录和旧对象。

### 回滚

- 将 provider 切回 `local`；
- 保持 CloudFront 和 S3 继续在线，确保已经发出的 S3 URL 可访问；
- 不回滚或删除已经创建的 `media_objects`；
- 失败期间的新对象通过对账任务补偿；
- 数据库 migration 采用向前兼容，不在紧急回滚时直接删表删字段。

## 12. 需要客户确认的边界

开发前只需确认以下事项：

1. AWS Region 和生产媒体域名；
2. 私聊/群聊媒体是否要求“只有会话成员可访问”；
3. P0 是否接受单文件 100 MB 的临时代理上传上限；
4. 是否必须首期就兑现 VIP 500 MB、SVIP 2 GB 文件上传；如必须，应把 P0+P1 合并上线；
5. 是否开放 ZIP，以及是否需要 RAR/7Z；
6. 视频是否统一转成 MP4，原视频是否保留；
7. 消息撤回/删除后文件保留多久；
8. 历史本地/OSS/七牛文件是否需要迁移到 S3。

## 13. 推荐实施口径

建议对客户承诺为：

> 第一阶段完成 Amazon S3 私有对象存储接入，覆盖图片、视频、语音、文档上传、发送、播放/下载、删除和异常重试；第二阶段完成大文件直传、分片续传和私密媒体授权访问；第三阶段根据实际用量完成历史迁移、病毒扫描、转码、生命周期和成本优化。首版文件类型采用安全白名单，视频以 MP4 为主，文档以 PDF 和新版 Office 格式为主。

不建议承诺：

- 只做 S3 配置就能稳定上传 2 GB 文件；
- 所有视频格式无需转码都能跨端播放；
- 私有 Bucket 加随机 URL 就等于会话成员鉴权；
- 删除一条消息就一定应立即物理删除文件；
- 未做真实设备和弱网测试即可认定全链路完成。
