# 聊天位置选择与 Docker 线上覆盖更新计划

日期：2026-07-23

## 目标

将聊天附件中的“位置”改造成可操作的地点选择流程：

1. 点击“位置”后获取系统当前经纬度。
2. 通过后端代理 Google Places API，展示“当前位置 + 附近地点”列表。
3. 用户确认地点后发送位置消息。
4. 位置消息在当前聊天页立即显示，并在重新进入聊天后保持一致。
5. 生成适用于现有线上 Docker 环境的一键覆盖更新包。

## 实施范围

### 后端

- 新增登录用户可访问的附近地点接口。
- 后端读取 `GOOGLE_MAPS_API_KEY`，客户端和 H5 不包含 Google 密钥。
- 调用 Google Geocoding API 获取当前位置地址。
- 调用 Places API (New) Nearby Search 获取附近地点。
- 对请求参数、超时、上游错误和未配置密钥提供明确响应。
- 仅向客户端返回地点名称、地址、经纬度和 Google 来源标记。

### Flutter

- 保留现有 `geolocator` 系统定位。
- 新增微信式底部地点选择页，包含加载、失败、空列表和重试状态。
- 第一项显示当前地址，其后显示附近地点。
- 点击地点后发送已有类型 `6` 的位置消息。
- 修复发送成功后当前消息列表未即时刷新的问题。
- 保持 Android、iOS、H5 和 Windows 的安全降级；无法定位的平台显示明确提示。

### Docker 线上更新

- `.env.bt` 增加或保留 `GOOGLE_MAPS_API_KEY` 配置。
- Compose API 服务透传该变量。
- 更新脚本在覆盖前执行既有静态文件、后端、MySQL、MongoDB 和 Redis 备份。
- 不执行 `docker compose down -v`，不删除线上数据卷。
- 包含最新 API Linux amd64 二进制、管理后台、客服后台和 H5 静态文件。

## 验证

- 后端单元测试覆盖：参数校验、未配置密钥、Google 响应解析和上游失败。
- `go test ./...`。
- Flutter 定向测试及 `flutter analyze --no-pub`。
- 管理后台与客服后台构建。
- Flutter H5 release 构建。
- 更新包条目、脚本换行、SHA256、敏感密钥缺失和必需文件检查。
- 本地构建/自动化结果不替代线上服务器和真实设备验收；线上更新后仍需检查 API、H5 和手机端位置选择、发送及接收。

## 交付

- 一键更新 ZIP。
- SHA256 校验值。
- 线上执行命令。
- `GOOGLE_MAPS_API_KEY` 配置位置和更新后检查清单。
