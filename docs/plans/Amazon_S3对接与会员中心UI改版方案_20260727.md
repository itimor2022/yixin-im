# Amazon S3 对接与会员中心 UI 改版方案

> 项目：`genericim-tongba`  
> 日期：2026-07-27  
> 范围：后端对象存储、管理后台云存储配置、Flutter 会员中心 UI  
> 本文是开发方案，不代表 S3 已经接通或会员页已经改版。

## 1. 结论

本次建议拆成两条并行但可独立上线的工作：

1. **Amazon S3 接入**：复用现有 `local / aliyun / qiniu` 存储适配层，新增 `s3` provider。第一期保持 Flutter、H5 和管理后台现有上传接口不变，由 Go 后端把文件流写入 S3；客户端不持有 AWS 密钥。
2. **会员中心 UI 改版**：保留现有 VIP 状态、套餐、钱包购买和订单接口，重做信息层级与购买交互。页面改为“会员身份卡 → 核心权益 → 套餐选择 → 固定购买栏”，而不是继续使用当前的普通设置列表样式。

第一期不建议直接让全部客户端上传到 S3。当前图片、视频、语音、文件、头像、发现页素材和会员徽章都已统一进入 `UploadHandler.saveUploadedObject()`，从后端切换 provider 可以用最小改动覆盖全部上传类型，也便于继续执行现有的文件类型、大小、登录态和 VIP 权益校验。

## 2. 当前代码基线

### 2.1 对象存储现状

当前项目已经具备对象存储抽象，不需要重写整套上传系统：

- `backend/internal/services/object_storage.go`
  - 已支持 `local`、阿里云 OSS、七牛云。
  - 已有运行时配置合并、配置校验、上传、删除、公开 URL 反解 object key。
- `backend/internal/handlers/upload_handler.go`
  - 图片、视频、头像、语音、文件、发现页素材、会员徽章均经过 `saveUploadedObject()`。
  - 云存储开启后，现有上传接口可以直接返回远端 URL。
- `backend/internal/services/external_cleanup_service.go`
  - 删除业务数据时会尝试根据公开 URL 反解 object key，并清理云端对象。
- `admin/src/views/system/settings/index.vue`
  - 已有本地、阿里云、七牛云配置面板。
- `backend/internal/models/system_setting.go`
  - `cloud_storage` 是数据库运行时配置来源。
- `scripts/baota_docker_deploy*.sh`、`scripts/online_update.sh`
  - 已传递现有存储环境变量，但尚无 S3 配置。

因此 S3 应接入现有适配层，不能另建一套只给某几个页面使用的上传代码。

### 2.2 会员中心现状

当前用户端会员中心位于：

- `lib/features/vip/pages/vip_center_page.dart`
- `lib/features/vip/services/vip_service.dart`
- `lib/features/vip/providers/vip_provider.dart`

已有能力：

- 查询当前会员状态和到期时间；
- 查询后端启用的 VIP/SVIP 套餐；
- 展示建群、频道、成员数、上传大小等权益；
- 使用钱包余额购买；
- 查询购买记录；
- 支持简体中文、繁体中文、英文；
- 已有深色模式；
- iOS 合规开关关闭 VIP 时，入口、路由和后端购买接口均有限制。

当前页面主要问题：

- 会员身份区仍像普通设置列表，视觉上缺少会员中心的识别度；
- 权益被压缩成一行摘要，用户难以快速理解购买价值；
- 套餐行点击后立即弹确认框，没有明确的“先选套餐、再购买”过程；
- 购买按钮不明显，页面底部没有价格与操作汇总；
- 当前等级、续费、升级和不可降级状态区分不够直观；
- 空数据和加载失败只有占位文字，缺少就地重试；
- 钱包余额与会员价值处于同一视觉层级，页面更像钱包附属页；
- 当前购买接口只有 `plan_id`，网络超时重试时缺少服务端幂等保障。

## 3. 目标架构

```text
Flutter / H5 / 管理后台
          |
          | 继续调用现有 /upload/* 接口
          v
Go UploadHandler
  - 登录和权限校验
  - MIME/后缀/大小校验
  - VIP 上传额度校验
  - 生成 uploads/... object key
          |
          v
Object Storage Adapter
  local | aliyun | qiniu | s3
                              |
                              v
                   Amazon S3 私有 Bucket
                              |
                              v
                   CloudFront + 自定义媒体域名
```

核心原则：

- AWS Access Key/Secret 不进入 Flutter、H5、安装包或浏览器；
- 对 App 保持现有上传 API 和返回字段兼容；
- S3 object key 继续使用当前 `uploads/{type}/...` 结构；
- 数据库继续保存可访问的媒体 URL，不保存本地磁盘绝对路径；
- Bucket 保持私有，通过 CloudFront Origin Access Control 访问；
- 第一期开启 S3 后只改变“新上传文件”的落盘位置，旧文件继续可访问；
- 切换失败可以把 provider 改回 `local`，不删除本地目录和旧数据。

## 4. Amazon S3 接入设计

### 4.1 后端配置模型

在 `StorageConfig` 增加：

```yaml
storage:
  provider: s3
  s3:
    region: ap-southeast-1
    bucket: genericim-media-prod
    public_base_url: https://media.example.com
    endpoint: ""
    use_path_style: false
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `region` | 是 | S3 Bucket 所在 Region |
| `bucket` | 是 | Bucket 名称 |
| `access_key_id` | 是 | 管理后台录入，加密写入数据库 |
| `secret_access_key` | 是 | 管理后台录入，加密写入数据库 |
| `public_base_url` | 是 | 推荐填写 CloudFront/CDN 自定义域名 |
| `endpoint` | 否 | Amazon S3 留空；仅为本地测试或 S3 兼容服务保留 |
| `use_path_style` | 否 | Amazon S3 默认 `false` |

AWS Access Key ID 与 Secret Access Key 由管理后台统一维护。保存时使用
AES-GCM 加密后写入 `system_settings.cloud_storage`，读取配置时仅在 Go
后端进程内解密并交给 AWS SDK。管理接口与页面只显示 `******`，App、H5
和安装包不返回、不保存 AWS 密钥。生产环境使用
`GENERIC_IM_SETTINGS_ENCRYPTION_KEY` 作为独立加密主密钥。

### 4.2 SDK 与存储适配

使用 AWS SDK for Go V2：

- `github.com/aws/aws-sdk-go-v2/config`
- `github.com/aws/aws-sdk-go-v2/service/s3`
- 大文件代理上传需要时使用 S3 Upload Manager。

在现有服务中扩展：

- `StorageProviderS3 = "s3"`；
- `NormalizeStorageProvider()` 识别 `s3`、`aws_s3`、`amazon_s3`；
- `ValidateStorageConfig()` 校验 region、bucket、public URL；
- `UploadObject()` 增加 `PutObject`/Upload Manager 分支；
- `DeleteObject()` 增加 `DeleteObject` 分支；
- `ObjectKeyFromPublicURL()` 支持 CloudFront 域名和 S3 默认域名；
- 上传时保留当前 `Content-Type` 和
  `Cache-Control: public, max-age=31536000, immutable`；
- 错误日志只记录 provider、object key、HTTP 状态和 AWS request id，不记录凭证。

第一期不改以下客户端接口：

- 图片上传；
- 视频上传；
- 头像上传；
- 语音上传；
- 文件上传；
- 发现页图标/横幅上传；
- 会员徽章上传；
- 管理后台通用图片上传。

### 4.3 管理后台配置

在“系统设置 → 云存储”增加“Amazon S3”：

- Region；
- Bucket；
- CloudFront/公开访问域名；
- 可选自定义 Endpoint；
- Path Style 开关，仅在自定义 Endpoint 时显示；
- 凭证来源说明和凭证状态；
- “测试连接”按钮；
- 保存前表单校验。

新增管理接口建议：

`POST /api/v1/admin/settings/cloud-storage/test`

测试流程：

1. 用临时 key 写入一个小文本对象；
2. `HeadObject` 验证对象存在和元数据；
3. 删除临时对象；
4. 如果配置了公开域名，额外检查 URL 格式；CDN 未完成部署时不把公开 URL 检查失败等同于 S3 写入失败；
5. 返回分步骤结果，不返回任何凭证。

### 4.4 AWS 侧安全配置

推荐配置：

- Bucket 开启全部 Block Public Access；
- Object Ownership 使用 `Bucket owner enforced`，不使用对象 ACL；
- CloudFront 使用 OAC 读取私有 S3 Origin；
- 强制 HTTPS；
- 开启默认 SSE-S3；有合规要求时再使用 SSE-KMS；
- 后端 IAM 权限只覆盖目标 Bucket 的 `uploads/*` 前缀；
- 开启 CloudTrail/S3 访问审计或至少保留错误监控；
- 配置生命周期规则，7 天后中止未完成的 multipart upload；
- 生产、预发布、开发使用不同 Bucket 或至少不同前缀。

Bucket 仍保持非公开、关闭 ACL 并启用 Block Public Access。本项目按确认需求使用
数据库加密保存的 IAM 访问密钥，因此必须限制权限、定期轮换并保留后台安全审计：

- <https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html>
- <https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-gosdk.html>
- <https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html>

### 4.5 大文件直传作为第二期

图片、头像、徽章等小文件继续通过后端代理上传即可。视频和大文件在第一期稳定后，可增加预签名直传：

1. 客户端向后端申请上传；
2. 后端先校验用户、文件类型、文件大小和 VIP 权益；
3. 后端生成受限时效、受限 key 的预签名请求；
4. 客户端直传 S3；
5. 客户端调用 complete 接口；
6. 后端 `HeadObject` 验证大小、类型和 key 后才返回可发送的媒体 URL。

直传不能只返回一个任意 key 的预签名 URL，也不能绕过现有上传额度校验。超过约 100 MB 的对象再考虑 multipart upload，并配置未完成分片自动清理。

### 4.6 历史文件与切换策略

第一期不立即批量改写历史 URL：

1. 上线 S3 代码但 provider 仍为 `local`；
2. 管理后台测试 S3 连接；
3. 预发布环境开启 `s3`，验证所有上传类型；
4. 生产切换后，新文件进入 S3；
5. 原 `backend/uploads` 和 Nginx `/uploads/` 继续保留；
6. 观察 24–48 小时后再决定是否迁移历史文件。

如需迁移历史文件，另提供可恢复脚本：

- 扫描本地 `uploads/`；
- 使用相同 object key 上传到 S3；
- 校验对象大小、类型和 checksum；
- 只对上传校验成功的对象建立 URL 映射；
- 先生成 dry-run 报告，再更新 MySQL/MongoDB 中的媒体 URL；
- 保留本地文件和数据库备份，完成抽查后再设置清理期限。

严禁在切换存储时删除 Docker volume 或直接清空原上传目录。

## 5. 会员中心 UI 改版

### 5.1 产品定位

视觉建议采用“克制的深色会员卡 + 金色点缀”，但页面内容区仍遵循现有 App 主题，不做大面积纯黑背景。VIP 和 SVIP 使用同一套布局，通过徽章、渐变和强调色区分等级，保证浅色、深色模式都可读。

页面要优先回答四个问题：

1. 我现在是什么等级，什么时候到期？
2. 开通后能获得什么？
3. 有哪些套餐，价格和时长是什么？
4. 我选中了什么，点击后会扣多少钱？

### 5.2 页面结构

```text
┌──────────────────────────────────┐
│ ←             会员中心        订单 │
├──────────────────────────────────┤
│ 会员身份卡                        │
│ [头像] 普通用户 / VIP / SVIP       │
│ 到期时间、会员徽章、状态提示         │
│                           查看记录 > │
├──────────────────────────────────┤
│ 我的权益                          │
│ [建群数] [频道数] [成员上限] [置顶数] │
│ [图片]  [视频]  [语音]   [文件]     │
│                         查看全部权益 │
├──────────────────────────────────┤
│ 选择等级       [VIP] [SVIP]        │
│ 选择套餐                          │
│ ┌ 30天 ┐  ┌ 90天/推荐 ┐  ┌ 365天 ┐ │
│ │价格   │  │价格/原价  │  │价格    │ │
│ └──────┘  └──────────┘  └────────┘ │
│ 套餐说明与本次获得的权益             │
├──────────────────────────────────┤
│ 钱包余额 ¥xx.xx  [去充值]            │
├──────────────────────────────────┤
│ ¥xx.xx          [立即开通/续费]      │  固定底栏
└──────────────────────────────────┘
```

### 5.3 关键交互

#### 会员身份卡

- 普通用户：展示“开通会员，解锁群聊与更高上传容量”；
- 有效会员：展示等级、徽章、到期时间；
- 即将到期：到期前 7 天显示提醒，但不使用强干扰弹窗；
- 已冻结/已过期：使用明确状态和处理说明；
- 会员背景使用 Flutter 渐变和图形，不依赖一张必须联网加载的大背景图；
- 徽章图标仍使用后台上传的 `badge_icon`，S3 开启后会自动返回 CDN URL。

#### 权益区

首屏显示用户最容易理解的 4 项：

- 可创建群数；
- 可创建频道数；
- 群/频道成员上限；
- 文件上传上限。

点击“查看全部权益”展开：

- 会话置顶数；
- 图片、视频、语音、文件上传上限；
- 公开群号；
- 成员保护；
- 其他后端后续增加的权益。

普通用户也显示当前免费额度，避免把 `0` 误解为接口加载失败。

#### 套餐选择

- 先按 `level` 分组显示 VIP/SVIP；
- 再按 `duration_days` 显示可选时长；
- 默认选择后台标记的推荐套餐；第一期如不扩展字段，则默认选择 `sort` 最靠前的可用套餐；
- 明确显示售价、原价、天数和套餐说明；
- 当前为更高等级时，低等级套餐置灰并说明“当前等级更高”；
- 当前同等级显示“续费”，更高等级显示“切换至 SVIP”，不使用“补差价升级”等当前后端不支持的文案。

#### 固定购买栏

- 左侧显示所选套餐实付价格；
- 右侧按钮根据状态显示“立即开通 / 续费 / 切换至 SVIP”；
- 未选择套餐时按钮禁用；
- 购买请求中禁止重复点击，并显示加载状态；
- 钱包不足时不直接失败结束，提示余额和差额，再引导去充值；
- iOS 合规开关关闭 VIP 时，入口和路由继续隐藏，不以空套餐页代替合规限制。

#### 购买确认

用底部确认面板替代普通 AlertDialog，显示：

- 套餐名和等级；
- 有效期；
- 实付金额；
- 钱包余额；
- 购买后的预计到期时间；
- 当前后端规则下的续费/切换说明；
- 最终确认按钮。

本次 UI 改版不改变“钱包余额购买 VIP”的支付边界，也不宣称已接入会员订单直连微信/支付宝。iOS 若要销售数字会员，需要单独完成 Apple In-App Purchase，不属于本方案。

### 5.4 交易安全补强

UI 防重复点击不能替代服务端幂等。建议购买请求增加：

```json
{
  "plan_id": 1,
  "client_request_id": "uuid"
}
```

后端为 `client_request_id + user_id` 建唯一约束。相同请求重试时返回原订单，不能再次扣钱包余额。

暂不在此次改版中实现“升级补差价”。现有后端在购买更高等级时按整套价格扣款，UI 必须明确展示实际扣款与预计到期时间。若产品需要按剩余价值折算，应单独设计报价接口、折算规则和退款规则。

### 5.5 响应式与状态设计

适配范围：

- 手机：单列，底部固定购买栏；
- 平板/H5：内容最大宽度 720px；
- 桌面端：最大宽度约 960px，身份/权益与套餐区域可双列；
- 安全区、底部手势区域和键盘弹出；
- 简中、繁中、英文；
- 浅色、深色模式；
- 系统字体放大至 1.3 倍时不溢出。

必须覆盖的页面状态：

- 状态和套餐均加载中：骨架屏；
- 状态成功、套餐失败：保留身份卡，套餐区就地重试；
- 套餐为空：说明暂无可售套餐，不显示无效购买栏；
- 钱包未创建或余额为 0；
- 钱包锁定；
- 会员有效、即将到期、过期、冻结；
- 低等级不可购买；
- 购买成功；
- 请求超时后幂等重试；
- 切换账号时取消旧账号页面状态。

## 7. 实施顺序

### 阶段 A：S3 基础能力

## 8. 验收标准

### 8.1 S3

- 管理后台能选择 Amazon S3、保存非敏感配置并测试连接；
- 管理 API、日志、Flutter 包和 H5 资源中不存在 AWS Secret；
- 头像、图片、视频、语音、文件、发现页素材、会员徽章均能上传；
- 新 URL 使用配置的 CloudFront/媒体域名；
- 图片可显示，视频/语音可播放，文件可下载；
- Content-Type 和长缓存头正确；
- 业务删除触发 S3 对象删除，其他域名 URL 不会被误删；
- 上传失败不会生成成功日志或不可用业务 URL；
- provider 切回 `local` 后旧本地文件仍可访问；
- 真实 AWS Bucket、IAM、CloudFront 和生产域名验证完成后，才能标记“S3 已对接”。

### 8.2 会员中心

- 普通、VIP、SVIP 的身份和权益一眼可区分；
- 套餐必须先选中，再通过固定购买栏确认；
- 当前等级、续费、更高等级切换、低等级不可买状态正确；
- 钱包余额、扣款金额和预计到期时间在确认前清晰可见；
- 重复点击或超时重试不会重复扣款；
- 加载失败、无套餐、余额不足、钱包锁定均有明确处理；
- 简中、繁中、英文无硬编码“天”等遗漏；
- 浅色、深色、手机、H5、桌面无溢出；
- iOS 合规开关关闭时无法通过入口、深链或直接接口购买；
- Flutter 静态分析、后端测试、管理后台类型检查通过；
- 至少完成 Android 真实界面截图、H5 界面截图和一笔测试钱包购买闭环。

## 10. 开工前需要提供

- AWS Region；
- S3 Bucket 名称；

- 会员页主色偏好，如无指定则使用“深灰黑 + 暖金”；
- 本期是否同时做“购买请求幂等”，建议做；
- 本期是否仅保持钱包支付，默认保持现状。
