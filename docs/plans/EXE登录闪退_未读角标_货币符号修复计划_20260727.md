# EXE 登录闪退、未读角标与货币符号修复计划

日期：2026-07-27

## 用户反馈

1. Windows EXE 登录成功后闪退。
2. 已经阅读的聊天，重新登录后会再次出现未读数 `1`，会话行和底部“消息”入口都受影响。
3. 后台把钱包货币符号设置为 `$` 后，客户端钱包余额仍显示 `¥`。
4. 在修复上述问题的同时，检查相同数据流中是否还有明显的跨端、缓存或配置同步问题。

## 排查范围

### Windows 登录

- 追踪登录成功后的统一初始化、页面跳转、窗口/托盘、WebView、推送、音视频和平台插件初始化。
- 检查 Windows 构建及运行日志，区分 Dart 未捕获异常、原生进程崩溃和安装环境依赖问题。
- 确保 Windows 不会执行只支持移动端的平台能力；非关键初始化失败不得终止主进程。

### 未读状态

- 追踪服务端 `user_chats.unread_count`、已读接口、WebSocket 已读同步、客户端本地缓存和登录后的会话列表合并。
- 以服务端状态为最终依据，避免旧缓存或“手动标为未读”状态在重新登录后覆盖已读结果。
- 同步检查会话行角标、底部总角标、桌面托盘/系统角标是否由同一权威状态计算。

### 钱包货币

- 追踪后台保存的 `wallet_currency` / `wallet_currency_name` 到客户端钱包设置接口和页面渲染。
- 清除页面硬编码的人民币符号，所有金额展示统一消费服务端设置，并保留设置缺失时的安全默认值。
- 检查充值、提现、转账、红包、账单等相关页面是否仍存在用户可见的 `¥` 硬编码。

## 实施原则

- 保留当前工作区已有的所有修改，不回滚、不覆盖无关文件。
- 先补可复现或防回归测试，再做最小范围修复。
- 后端和 Flutter 分别执行针对性测试；条件允许时构建并短时运行 Windows Release。
- 构建成功、进程存活和真实账号登录验收分别记录，不用其中一项替代另一项。

## 验收标准

1. Windows Release 可以构建并启动；使用真实账号登录后进程持续存活、进入主页且无未处理崩溃日志。
2. 打开未读会话后退出并重新登录，会话角标和底部总角标均为 `0`；另一个账号新发消息后才重新增加。
3. 后台设置 `$` 后，客户端刷新/重新进入钱包即可显示 `$0.00`，不需要重新安装应用。
4. 充值、提现、转账、红包及账单中使用同一个当前货币符号；发现未纳入本轮的风险时单独列出，不伪报已修复。
