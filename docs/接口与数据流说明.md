# 接口与数据流说明

> 更新时间：2026-05-06  
> 适用范围：Flutter 客户端、管理后台、客服后台、Go 后端

## 1. 整体架构

系统整体链路为：

1. 客户端或后台发起 HTTP / WebSocket 请求
2. Go 后端处理业务逻辑
3. 数据写入 MySQL / MongoDB
4. Redis 负责缓存、限流与部分状态协同
5. 异步任务通过消息队列 worker 处理
6. 需要实时同步的场景通过 WebSocket 广播到在线设备

## 2. 主要接口域划分

## 2.1 用户端认证接口

前缀：`/api/v1/auth`

主要用途：

- 登录
- 注册
- 刷新登录态
- 修改密码
- 忘记密码
- 短信验证码重置密码
- 设备锁验证
- 二维码登录相关流程

主要客户端调用点：

- `lib/core/services/api/auth_service.dart`

## 2.2 用户资料与设备接口

常见前缀：

- `/api/v1/user`
- `/api/v1/contact`

主要用途：

- 获取和更新个人资料
- 隐私设置
- 黑名单
- 联系人增删查
- 设备列表
- 终止设备会话
- 终止其他全部设备

## 2.3 聊天与消息接口

常见前缀：

- `/api/v1/chat`
- `/api/v1/message`

主要用途：

- 创建或查询会话
- 聊天历史拉取
- 消息发送
- 消息编辑、撤回、删除
- 回复消息
- 表情回应
- 已读同步
- 清空聊天记录
- 群权限变更

当前明确可见的消息回应接口包括：

- `/message/reaction/add`
- `/message/reaction/remove`

主要客户端调用点：

- `lib/core/services/api/chat_service.dart`

## 2.4 消息加密与设备密钥接口

主要用途：

- 设备公钥注册
- 拉取会话成员设备密钥
- 严格加密模式下构造密文消息包

主要客户端调用点：

- `lib/core/services/e2ee/e2ee_service.dart`

## 2.5 动态接口

主要用途：

- 动态列表
- 发布动态
- 删除动态
- 点赞/取消点赞
- 评论与回复
- 举报
- 屏蔽动态
- 屏蔽用户动态

## 2.6 钱包与会员接口

前缀：`/api/v1/wallet`

主要用途：

- 钱包信息
- 支付密码设置与验证
- 充值
- 提现
- 红包
- 转账
- 交易记录
- 会员购买

## 2.7 音视频与会议接口

常见前缀：

- `/api/v1/call`
- `/api/v1/meeting`

主要用途：

- 发起通话
- 接听/拒绝/取消
- 获取通话能力配置
- 创建会议

- 成员管理

- `/app/settings`

## 3. 核心数据流说明

## 3.1 登录数据流

1. 客户端调用登录接口
2. 后端校验账号密码
3. 生成登录态与设备会话信息
4. 客户端保存 Token
5. 客户端建立 WebSocket 连接
6. 如启用设备锁或强制绑定手机号，则继续进入对应校验链路

## 3.2 注册与邀请码归属数据流

1. 用户提交注册信息
2. 后端判断当前是否允许注册
3. 如开启邀请码必填，则校验邀请码
4. 若邀请码绑定了官方客服，则建立归属关系
5. 按后台策略决定是否：
   - 自动添加官方客服
   - 只添加邀请码绑定客服
   - 自动加入官方群
   - 自动订阅官方频道

## 3.3 消息发送数据流

1. 客户端构造消息内容
2. 根据当前消息模式判断走明文还是加密流程
3. 调用消息发送接口
4. 后端落库
5. 后端将消息投递到广播/异步处理链路
6. 在线设备通过 WebSocket 收到新消息
7. 会话列表、聊天页、未读数同步刷新

## 3.4 加密消息数据流

当处于兼容模式或严格加密模式时：

1. 客户端先拉取会话成员设备密钥
2. 本机为每个目标设备构造加密信封
3. 消息体以密文方式发送
4. 接收端根据本机设备密钥解密
5. 聊天层恢复文本、回复信息、位置等原始结构

严格加密模式下，如果目标成员缺少可用设备密钥，消息发送会被阻止。

## 3.5 多设备同步数据流

1. 同一账号在多个设备登录
2. 某设备执行会话隐藏、已读同步、资料更新等动作
3. 后端广播对应同步事件
4. 其他设备收到事件后刷新本地状态

当前已覆盖的同步方向包括：

- 已读同步
- 资料更新
- 会话隐藏/删除
- 表情回应

## 3.6 自定义网站栏目数据流

1. 管理后台保存栏目开关、标题、图标、网址
2. 后端将其纳入客户端公共设置返回
3. 客户端进入首页时拉取并缓存设置
4. 主导航根据配置决定是否展示该栏目
5. 用户点击后进入网站内容页

## 3.7 发现页入口数据流

1. 管理后台创建或编辑发现页入口
2. 后端保存入口数据
3. 如有广播更新机制，则向在线客户端下发入口变更通知
4. 客户端刷新发现页后展示新的入口卡片

## 3.8 钱包数据流

### 充值

1. 客户端创建充值订单
2. 后端返回支付信息或二维码信息
3. 用户完成支付
4. 后端回调或人工审核后入账
5. 钱包余额与交易记录更新

### 提现

1. 客户端提交提现申请
2. 后台进入提现审核列表
3. 管理员审核通过或拒绝
4. 钱包冻结或回退逻辑同步更新

### 红包与转账

1. 发送方校验支付密码与余额
2. 后端冻结或扣减金额
3. 聊天消息写入会话
4. 接收方领取或接收后再变更最终余额
5. 相关记录写入流水

## 3.9 热更新数据流

1. 客户端启动后请求热更新检查接口
2. 后端根据平台、版本、渠道、灰度比例返回补丁信息
3. 客户端下载并应用补丁
4. 客户端上报补丁执行结果
5. 后台查看补丁命中与执行情况

## 3.10 推送数据流

1. 客户端上报推送标识
2. 后台保存对应平台通道配置
3. 后端按消息或通知场景投递到具体推送通道
4. 设备收到系统通知后再唤起客户端

## 4. 后端存储职责划分

## 4.1 MySQL

主要存放：

- 用户
- 联系人
- 群组/频道基础信息
- 系统设置
- 钱包
- 会员
- 提现/充值/转账/红包业务记录
- 管理后台配置数据

## 4.2 MongoDB

主要用于承载消息或内容类数据支撑，适合高频写入和灵活结构存储。

## 4.3 Redis

主要用于：

- 缓存
- 限流
- 短时状态
- 会话协同

## 5. WebSocket 与异步链路

## 5.1 WebSocket

主要用于：

- 在线连接维护
- 新消息推送
- 状态同步
- 用户上下线通知
- 部分配置变更广播

## 5.2 消息队列

主要用于：

- 消息异步处理
- 推送通知
- 后台任务分发
- 队列统计与异常隔离

## 6. 管理后台与客户端的配置关系

配置链路大致为：

1. 管理后台写入系统设置或配置表
2. 后端在管理接口中保存配置
3. App 通过公共设置接口拉取对客户端可见的部分
4. 客户端根据返回内容调整页面、开关与业务行为

典型例子：

- 是否允许注册
- 是否必须邀请码注册
- 是否强制绑定手机号
- 是否显示网站栏目
- 消息加密模式
- 上传大小限制
- 热更新提示

## 7. 联调建议

前后端联调时，建议按以下顺序排：

1. 先确认反向代理与 CORS
2. 再确认登录与 Token
3. 再确认 WebSocket 是否成功连接
4. 再确认系统设置是否已正确下发
5. 最后排查单个业务模块

最容易影响全局体验的链路通常是：

- 登录态
- WebSocket
- 系统设置下发
- 推送配置
- 钱包审核链路
