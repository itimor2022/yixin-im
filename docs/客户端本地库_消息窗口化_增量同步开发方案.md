# 客户端本地库 + 消息窗口化 + 增量同步开发方案

## 1. 背景与目标

Android 登录后消息加载慢，核心不是 Android 性能问题，而是客户端加载策略偏全量：

- 登出时清空本地 Isar，导致下次登录没有本地会话和消息可用。
- 登录后会话列表依赖服务端返回，首屏等待网络。
- 进入聊天页时，即使本地已有消息，也会重新拉最近消息窗口。
- WebSocket 重连后会对较多会话做同步预取。
- 本地缓存缺少账号隔离，不能安全长期保留。

目标：

- 登录后会话列表本地优先，先秒显缓存，再后台对齐服务端。
- 聊天页消息窗口化，只加载当前窗口，历史消息按需翻页。
- 已有本地消息时使用 `seq` 做增量同步，只拉新消息。
- 本地缓存按账号隔离，登出不清空消息库。
- 重连后只同步重点会话，避免大量并发请求。

## 2. 当前代码基础

客户端已经有 Isar：

- `lib/bootstrap/bootstrap_native.dart`：初始化 Isar。
- `lib/core/services/storage/isar_service.dart`：Isar 单例。
- `lib/core/services/storage/models/chat_model.dart`：会话缓存。
- `lib/core/services/storage/models/message_model.dart`：消息缓存。
- `lib/features/chat/providers/chat_provider.dart`：会话列表、重连预取。
- `lib/features/chat/providers/message_provider.dart`：聊天页消息加载、写入本地缓存。

现有服务端接口：

- `GET /api/v1/chat/list?page=1&page_size=50`
- `GET /api/v1/message/list?chat_id=xxx&limit=30`
- `GET /api/v1/message/list?chat_id=xxx&before_seq=123&limit=30`
- `POST /api/v1/message/sync`

## 3. 总体设计

### 3.1 登录后流程

1. 读取当前账号的本地 `ChatModel`。
2. 立即渲染本地会话列表。
3. 后台请求服务端第一页会话列表。
4. 服务端结果 upsert 到 Isar。
5. WebSocket 只订阅置顶、未读、最近会话窗口。

### 3.2 进入聊天页流程

1. 读取当前账号 + 当前 chatId 的本地 `MessageModel`，limit 50。
2. 如果本地没有消息，拉 `GET /message/list?limit=30`。
3. 如果本地已有消息，取本地最大 `seq`，调用 `POST /message/sync`。
4. 增量返回非空时合并并写入 Isar。
5. 增量返回空时保留本地 state，不清空 UI。

### 3.3 向上翻历史流程

1. 取当前窗口最旧消息的 `seq`。
2. 请求 `GET /message/list?before_seq=xxx&limit=30`。
3. 去重后追加到当前窗口。
4. 写入 Isar。

### 3.4 重连流程

1. 静默刷新会话第一页。
2. 只对当前打开、未读、置顶、最近的少量会话调用 `/message/sync`。
3. 每个会话之间加短延迟，避免瞬时打爆服务端。

## 4. 本地数据模型

### 4.1 ChatModel 改造

建议字段：

```dart
@collection
class ChatModel {
  Id get isarId => fastHash('$accountId:$id');

  @Index(composite: [CompositeIndex('id')], unique: true)
  late String accountId;

  @Index()
  late String id;

  @enumerated
  late ChatType type;

  late String name;
  late String? avatar;
  late String? lastMessage;

  @enumerated
  late MessageType lastMessageType;

  late String? lastMessageSender;

  @Index()
  late DateTime? lastMessageTime;

  late int unreadCount;
  late bool isMuted;

  @Index()
  late bool isPinned;

  late bool isArchived;
  late String? draft;
  late int? memberCount;
  late String? peerUserId;
  late String? premiumType;

  late int lastMessageSeq;
  late int lastSyncedSeq;
  late DateTime? lastSyncedAt;
  late bool hasMessageGap;

  late DateTime createdAt;

  @Index()
  late DateTime updatedAt;
}
```

字段说明：

- `accountId`：当前登录账号 UUID，所有本地查询必须带上。
- `lastMessageSeq`：服务端会话最新消息 seq。
- `lastSyncedSeq`：本地已经同步到的最大 seq。
- `lastSyncedAt`：最近一次同步时间。
- `hasMessageGap`：本地窗口是否存在缺口，缺口时需要重新拉最近窗口。

### 4.2 MessageModel 改造

建议字段：

```dart
@collection
class MessageModel {
  Id get isarId => fastHash('$accountId:$id');

  @Index(composite: [CompositeIndex('id')], unique: true)
  late String accountId;

  @Index()
  late String id;

  @Index(composite: [CompositeIndex('createdAt')])
  late String chatId;

  @Index()
  late String senderId;

  late String senderName;
  late String? senderAvatar;

  @enumerated
  late MsgType type;

  late String content;

  @Index()
  late int seq;

  late String? localPath;
  late String? remoteUrl;
  late String? thumbnail;
  late int? mediaWidth;
  late int? mediaHeight;
  late int? mediaSize;
  late int? mediaDuration;
  late String? fileName;

  late bool isOutgoing;

  @enumerated
  late MsgStatus status;

  late bool isRead;
  late String? replyToId;
  late String? replyToPreview;
  late String? forwardFrom;
  late String? reactions;

  @Index()
  late DateTime createdAt;

  late DateTime cachedAt;
  late DateTime? editedAt;
  late bool isDeleted;
  late bool burnAfterRead;
  late int burnAfterSeconds;
}
```

字段说明：

- `accountId`：账号隔离。
- `seq`：分页和增量同步游标。
- `cachedAt`：本地写入时间，后续用于 LRU 清理。
- `status`：保留本地发送状态，避免服务端旧状态覆盖发送中/发送失败。

## 5. 客户端开发任务

### 5.1 账号隔离

任务：

- `ChatModel`、`MessageModel` 新增 `accountId`。
- `isarId` 改为 `fastHash('$accountId:$id')`。
- 本地读写、删除、搜索全部带当前账号过滤。

涉及位置：

- `chat_provider.dart`：会话缓存读取、写入、删除。
- `message_provider.dart`：消息缓存读取、写入、删除、清空历史。
- `search_page.dart`：本地消息搜索。
- `app.dart`：离线消息失败状态回写。

验收：

- A 账号登录看不到 B 账号本地消息。
- 切账号后本地搜索不串数据。
- 删除会话只删当前账号本地数据。

### 5.2 登出保留缓存

任务：

- 移除 `AuthService.logout()` 中的 `isar.clear()`。
- 保留 token 清理、运行态 provider reset、离线发送队列清理。

注意：

- 离线发送队列仍要清理，避免旧账号消息用新 token 代发。
- 保留缓存的前提是所有查询都已经按 `accountId` 隔离。

验收：

- 登出再登录同一账号，会话列表能先显示本地缓存。
- 登出登录另一个账号，不显示上一个账号缓存。

### 5.3 会话列表本地优先

任务：

- `_loadChatListFromCache()` 按 `accountId` 查询，按 `lastMessageTime` 降序，limit 200。
- `loadFromServer()` 首次进入先读本地缓存。
- 服务端请求使用 `getChatListPage(page: 1, pageSize: 50)`。
- `silentRefresh()` 不允许 `chatModels.clear()`，只 upsert 当前账号会话。

验收：

- 登录后日志只出现 `GET /chat/list?page=1&page_size=50`。
- 不出现 page=2、page=3 的自动翻页请求。
- 已有缓存时会话列表先显示本地数据。

### 5.4 WebSocket 订阅窗口化

任务：

- 新增 `_subscriptionChatIds(chats, limit: 30)`。
- 优先级：未读 > 置顶 > 最近消息时间。
- 登录和静默刷新后只订阅这 30 个会话。
- 用户进入某个会话时单独订阅该会话。

验收：

- 登录后不会订阅全部会话。
- 当前打开会话能收到实时消息。
- 重连后订阅数量受控。

### 5.5 聊天页消息窗口化

任务：

- `_loadFromLocal()` 按 `accountId + chatId` 查询，limit 50。
- `loadMessages()` 先加载本地窗口。
- 本地为空：请求 `GET /message/list?limit=30`。
- 本地不为空：请求 `POST /message/sync`。
- `/message/sync` 返回空时不能清空本地 state。

验收：

- 首次打开会话请求 `/message/list`。
- 第二次打开同一会话请求 `/message/sync`。
- 第二次打开不再请求 `/message/list`。
- 增量为空时 UI 仍显示本地已有消息。

### 5.6 历史消息分页

任务：

- `loadMoreMessages()` 使用当前窗口最旧 `seq` 作为 `beforeSeq`。
- 每次最多拉 30 条。
- 和当前 state 去重合并。
- 写入 Isar。

验收：

- 上滑加载历史不重复。
- 消息顺序稳定。
- 没有更多历史时停止继续请求。

### 5.7 重连增量预取

任务：

- `_prefetchMissedMessagesAfterReconnect()` 限制最多 10 个会话。
- 优先当前会话、未读、置顶、最近活跃。
- 每个会话用本地最大 `seq` 调 `/message/sync`。
- 每个请求之间 delay 30 到 50ms。

验收：

- 重连后不会对所有会话发起同步。
- 弱网下没有明显卡顿。
- 日志中 `/message/sync` 数量受控。

## 6. 后端配合任务

### 6.1 message/list

要求：

- 支持最近窗口：`limit=30`。
- 支持历史窗口：`before_seq`。
- 返回稳定排序。
- 尊重当前用户 `cleared_at`，清空聊天后不再拉回旧消息。

### 6.2 message/sync

建议请求：

```json
{
  "chat_id": "xxx",
  "last_seq": 123
}
```

建议响应：

```json
{
  "messages": [],
  "latest_seq": 123,
  "has_more": false,
  "gap": false
}
```

要求：

- 只返回 `last_seq` 之后的新消息。
- 单次最大建议 100 条。
- 如果 `last_seq` 太旧，返回 `gap=true`，客户端重新拉最近窗口。

### 6.3 chat/list

要求：

- 支持分页。
- 首屏使用 `page=1&page_size=50`。
- 返回 `last_msg_seq`，客户端用于判断是否需要同步。

## 7. 缓存清理策略

第一阶段不做主动清理，只做账号隔离和窗口加载。

第二阶段增加 LRU：

- 每账号最多保留 500 个会话摘要。
- 每会话默认保留最近 200 到 500 条消息。
- 发送中、发送失败、收藏、置顶相关消息不自动清理。
- 清理任务延迟到 App 空闲后执行，不能阻塞首屏。

## 8. 迁移策略

老缓存没有 `accountId`。

策略：

- 新字段默认空字符串。
- 新版本只查当前账号，所以旧缓存不会被误读。
- 登录后重新写入当前账号的新缓存。
- 后续如果需要，可做一次性迁移，把单账号旧缓存补上 `accountId`。

修改 model 后执行：

```bash
flutter pub run build_runner build --delete-conflicting-outputs
dart format lib/core/services/storage/models lib/features/chat/providers
flutter analyze
```

## 9. 分阶段开发计划

### 阶段 1：最小可交付版本

目标：

- 解决每次登录重新从服务端拉导致的明显慢。

任务：

- 增加 `accountId`。
- 登出不清空 Isar。
- 会话列表本地优先。
- 会话列表服务端只拉第一页。
- WS 订阅限制到 30 个会话。
- 聊天页本地有消息时走 `/message/sync`。
- 修复增量为空清空 UI 的问题。

验收：

- `flutter analyze` 通过。
- 登录后只请求 `chat/list?page=1&page_size=50`。
- 第二次打开会话走 `/message/sync`。
- 增量为空不清空本地消息。

### 阶段 2：完整窗口和 gap

目标：

- 完善历史分页、清空历史、游标过旧恢复。

任务：

- 后端 `/message/sync` 返回 `gap`。
- 客户端记录 `hasMessageGap`。
- gap 时重新拉最近窗口。
- 历史翻页稳定去重。

验收：

- 清空聊天后旧消息不回流。
- 游标过旧时能恢复。
- 历史消息不重复不乱序。

### 阶段 3：缓存治理和埋点

目标：

- 长期使用不让本地库无限增长。

任务：

- 消息缓存 LRU。
- 会话缓存上限。
- 登录首屏耗时埋点。
- 本地缓存命中率埋点。
- `/message/sync` 请求数量埋点。

验收：

- 大账号本地消息很多时仍能快速打开。
- 弱网重连没有大量同步风暴。

## 11. 风险与处理

### 11.1 多账号串数据

处理：

- 所有 Isar 查询必须加 `accountId`。
- 搜索、删除、离线消息失败回写也必须加。

### 11.2 增量为空清空 UI

处理：

- 只有首次窗口拉取或增量非空时才合并覆盖 state。
- 增量为空只更新同步时间和游标。

### 11.3 本地发送状态被覆盖

处理：

- 合并服务端消息时保留本地 `sending/failed`。
- 本地临时消息和服务端正式消息需要做映射或去重。

### 11.4 清空历史后旧消息回流

处理：

- 后端 `message/list` 和 `message/sync` 都按当前用户 `cleared_at` 过滤。
- 客户端收到清空事件后删除当前账号 + chatId 的本地消息。

## 12. 最终验收标准

- 登录后会话列表可先展示本地缓存。
- 登出再登录同一账号不丢本地缓存。
- 切账号不串消息。
- 登录后不会自动翻完整个会话列表。
- WS 不订阅全部会话。
- 聊天页二次打开走 `/message/sync`。
- `/message/sync` 空返回不清空 UI。
- 重连后最多同步少量重点会话。
- `flutter analyze` 通过。
