# H5 公开资料页与好友深链开发方案

## 背景

目标是实现类似 TG 的体验：用户分享一个网页链接后，别人可以直接在浏览器打开用户资料页；如果已登录，可以直接添加好友或发消息；如果安装了 App，则优先唤起 App；未安装时留在 H5 页面完成查看、登录、注册或下载引导。

当前项目已经具备一部分基础能力：

- H5 已有用户资料路由：`h5/src/router/index.ts` 中 `/user/:id`。
- H5 用户资料页已有资料展示、发消息、添加联系人、备注、拉黑、共同群组等能力：`h5/src/views/UserProfileView.vue`。
- App 端个人名片分享已能生成 `.../user/{uuid}` 链接：`lib/features/chat/pages/user_profile_page.dart`。
- 后端 `GetUser` 已能返回用户公开字段：`backend/internal/handlers/user_handler.go`。

主要差距：

- H5 `/user/:id` 当前要求登录，游客打开会跳转登录页。
- 后端 `/api/v1/user/:id` 当前挂在鉴权路由组下，游客无法访问。
- 分享链接主要使用 UUID，不像 TG 一样天然支持 `@username` 风格短链接。
- 还没有统一的 App Links / Universal Links / Web fallback 策略。

## 目标

1. 游客打开用户链接时，可以看到公开资料页。
2. 已登录用户打开链接时，可以直接添加联系人、发消息、备注、拉黑。
3. 未登录用户点击“添加联系人 / 发消息”时，跳转登录，登录后回到原资料页并继续操作。
4. 支持短链接形式，例如：
   - `https://example.com/u/alice`
   - `https://example.com/user/{uuid}`
5. App 已安装时优先打开 App 内资料页；未安装时保留 H5 页面。
6. 后端严格遵守隐私设置，公开接口只返回允许公开的字段。

## 非目标

以下能力不在第一期实现范围：

- 公开展示某个用户的好友列表。
- 公开展示用户朋友圈或动态时间线。
- 公开展示手机号、精确在线状态、共同群组等需要登录关系判断的数据。
- 完整 SEO 落地页和搜索引擎收录策略。

## 总体方案

采用“一套公开预览页 + 登录态增强”的方式：

- 游客访问公开 H5 资料页，只看到头像、昵称、用户名、简介、短 ID 等公开字段。
- 已登录访问同一页面，额外加载关系状态、共同群组、拉黑状态，并显示完整操作。
- 敏感操作仍走现有鉴权接口，例如添加联系人、创建私聊、设置备注、拉黑。
- App 分享、二维码、复制链接统一生成 H5 公共链接。
- App Links / Universal Links 命中时进入原生 App 资料页；失败时继续展示 H5。

## 路由设计

### H5 页面路由

新增公开路由：

```ts
{
  path: '/u/:username',
  name: 'public-user-profile-by-username',
  component: () => import('@/views/PublicUserProfileView.vue'),
  meta: { title: '用户资料' },
}

{
  path: '/user/:id',
  name: 'public-user-profile',
  component: () => import('@/views/PublicUserProfileView.vue'),
  meta: { title: '用户资料' },
}
```

保留现有登录态用户资料页逻辑，但建议将页面整合为同一个组件：

- 未登录：公开预览模式。
- 已登录：完整互动模式。

### App 内深链

建议统一约定：

- H5 链接：`https://example.com/u/{username}`
- UUID 链接：`https://example.com/user/{uuid}`
- App scheme：`genericim://user/{uuid}`

App 收到深链后：

1. 如果本地已登录，直接打开用户资料页。
2. 如果未登录，先进入登录页。
3. 登录成功后恢复目标资料页。

## 后端接口设计

### 公开用户资料接口

新增：

```http
GET /api/v1/public/user/:idOrUsername
```

支持查询：

- UUID
- username
- short_id

返回示例：

```json
{
  "id": "user-uuid",
  "short_id": "10001",
  "nickname": "Alice",
  "username": "alice",
  "avatar": "/uploads/avatar.png",
  "bio": "Hello",
  "emoji_avatar": "",
  "nickname_color": ""
}
```

公开接口默认不返回：

- 手机号
- 精确在线状态
- last_seen
- 是否好友
- 共同群组
- 黑名单状态
- 钱包、设备、推送、隐私设置等任何敏感数据

### 登录态增强接口

保留现有接口：

```http
GET /api/v1/user/:id
GET /api/v1/user/:id/common-groups
GET /api/v1/user/blocked/check
POST /api/v1/contact/add
POST /api/v1/chat/create
```

H5 页面逻辑：

- 未登录只调用 `/api/v1/public/user/:idOrUsername`。
- 已登录先调用公开接口展示基础信息，再调用登录态接口补齐关系能力。

### 可选：关系状态聚合接口

为了减少 H5 请求数量，可新增：

```http
GET /api/v1/user/:id/relation-summary
```

返回：

```json
{
  "is_self": false,
  "is_contact": true,
  "is_blocked": false,
  "contact_remark": "客户A",
  "common_groups_count": 2
}
```

第一期可以不做，复用现有接口即可。

## 前端开发任务

### 1. 新增公开资料服务

文件建议：

- `h5/src/services/publicUser.ts`

方法：

```ts
export function fetchPublicUserProfile(idOrUsername: string) {
  return api.get<PublicUserProfile>(`/public/user/${encodeURIComponent(idOrUsername)}`);
}
```

### 2. 新增或改造资料页组件

推荐新增：

- `h5/src/views/PublicUserProfileView.vue`

页面状态：

- `loading`
- `profile`
- `isAuthenticated`
- `relationLoaded`
- `isContact`
- `isBlocked`
- `contactRemark`

未登录按钮：

- 打开 App
- 登录后添加联系人
- 登录后发消息

已登录按钮：

- 发消息
- 添加联系人
- 设置备注
- 屏蔽 / 解除屏蔽
- 删除联系人

### 3. 登录后回跳

当前 H5 路由已经支持 `redirect` 查询参数。需要保证以下流程：

1. 游客访问 `/u/alice`。
2. 点击“添加联系人”。
3. 跳转 `/login?redirect=/u/alice&intent=add_contact`。
4. 登录成功回到 `/u/alice`。
5. 页面识别 `intent=add_contact` 或从临时存储读取意图，弹出确认或直接执行添加。

建议第一期先登录后回到页面，由用户再次点击按钮；第二期再做意图恢复。

### 4. 分享链接生成统一

App 端当前 `_buildAccountLink()` 使用 `registerBaseUrl` 拼 `/user/{uuid}`。建议新增或复用后台配置字段：

- `webBaseUrl`
- 或明确将 `registerBaseUrl` 作为 H5 入口域名

优先生成：

```text
{webBaseUrl}/u/{username}
```

如果 username 为空，则降级：

```text
{webBaseUrl}/user/{uuid}
```

## App 深链任务

### iOS Universal Links

服务端提供：

```text
https://example.com/.well-known/apple-app-site-association
```

示例：

```json
{
  "applinks": {
    "apps": [],
    "details": [
      {
        "appID": "TEAM_ID.com.genericim.app",
        "paths": ["/u/*", "/user/*"]
      }
    ]
  }
}
```

iOS 工程开启 Associated Domains：

```text
applinks:example.com
```

### Android App Links

服务端提供：

```text
https://example.com/.well-known/assetlinks.json
```

Android Manifest 增加 intent-filter：

```xml
<intent-filter android:autoVerify="true">
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data
        android:scheme="https"
        android:host="example.com"
        android:pathPrefix="/u/" />
    <data
        android:scheme="https"
        android:host="example.com"
        android:pathPrefix="/user/" />
</intent-filter>
```

Flutter 端处理收到的链接后跳转到用户资料页。

## 隐私与安全

必须遵守以下规则：

1. 公开接口只返回公开字段。
2. 手机号永不通过公开接口返回。
3. 游客不返回共同群组。
4. 游客不返回精确在线状态和 last_seen。
5. 公开接口增加基础限流，避免被批量扫用户资料。
6. username、short_id 查询要避免泄露被禁用或注销账号。
7. 用户被拉黑、隐私限制等关系判断只在登录态接口中处理。
8. 添加好友、发消息、拉黑等行为必须继续要求登录。

## 开发步骤

### 第一期：H5 公开资料页

1. 后端新增 `/api/v1/public/user/:idOrUsername`。
2. H5 新增公开路由 `/u/:username` 和 `/user/:id`。
3. H5 新增公开资料页，未登录可查看基础资料。
4. 已登录时复用现有 `UserProfileView.vue` 的操作逻辑。
5. App 分享名片链接改成 H5 公开链接。

预计：1 到 2 天。

### 第二期：登录后增强体验

1. 登录后回跳原资料页。
2. 支持 `intent=add_contact` 或 `intent=message`。
3. 已登录用户打开链接时自动加载关系状态。
4. 优化错误态：用户不存在、账号注销、资料不可见。

预计：1 到 2 天。

### 第三期：App Links

1. 配置 iOS Universal Links。
2. 配置 Android App Links。
3. Flutter 端处理深链跳转。
4. H5 页面增加“打开 App”按钮和下载 fallback。

预计：1 到 3 天。

## 验收标准

### 游客访问

- 打开 `/u/alice` 能看到头像、昵称、用户名、简介。
- 不会被强制跳转登录页。
- 页面不展示手机号、共同群组、在线时间等敏感信息。
- 点击“添加联系人 / 发消息”会引导登录。

### 登录用户访问

- 打开 `/u/alice` 能看到完整资料页。
- 可以添加联系人。
- 可以发消息。
- 已经是联系人时可以设置备注和删除联系人。
- 被拉黑时不能发消息或添加联系人。

### 分享链路

- App 分享名片生成 H5 公开链接。
- H5 复制链接和二维码使用同一套链接。
- username 存在时优先使用 `/u/{username}`。
- username 不存在时降级使用 `/user/{uuid}`。

### App 深链

- iOS 已安装 App 时，链接能进入 App 资料页。
- Android 已安装 App 时，链接能进入 App 资料页。
- 未安装 App 时，链接正常打开 H5 页面。
- 未登录 App 打开深链后，登录完成能回到目标资料页。

## 风险点

1. 公开资料接口如果字段控制不严，可能造成隐私泄露。
2. Universal Links 和 Android App Links 依赖域名、证书、包名、签名配置，联调容易反复。
3. 如果现有 `registerBaseUrl` 同时承担注册链接和 H5 域名，后续配置语义可能混乱。
4. `/user/:id` 既是公开路由又是登录态资料页时，需要小心路由守卫不要误拦截。
5. username 可修改时，旧链接可能失效；UUID 链接需要作为稳定降级方案。

## 推荐落地顺序

优先做第一期。它可以最快补齐“网页直接打开资料页”的核心体验，也能立刻让当前分享名片变成真实可用链接。App Links 可以放到第二步或第三步做，因为它涉及证书、域名和原生工程配置，调试成本更高。
