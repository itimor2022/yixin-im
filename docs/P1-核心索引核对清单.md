# P1 核心索引核对清单

日期：2026-06-27

## 目标

确认聊天、成员、消息、推送、登录审计和钱包高频查询具备基础索引，避免线上数据量增长后后台列表和消息同步变慢。

## 已在代码中自动保障

MySQL 启动迁移会执行 `ensureP0DatabaseIndexes`，缺失时自动创建：

| 表 | 索引 | 用途 |
| --- | --- | --- |
| `user_chats` | `idx_user_chats_user_pin_sort(user_id, is_pinned, sort_time, id)` | 会话列表按置顶和时间排序 |
| `chat_members` | `idx_chat_members_user_chat(user_id, chat_id)` | 用户参与群/频道查询 |
| `chat_members` | `idx_chat_members_chat_role_joined(chat_id, role, joined_at, user_id)` | 群成员列表和角色筛选 |
| `moments` | `idx_moments_status_visibility_created(status, visibility, created_at, id)` | 动态发现流 |
| `moments` | `idx_moments_user_status_created(user_id, status, created_at, id)` | 用户动态列表 |
| `moments` | `idx_moments_status_created(status, created_at, id)` | 后台动态管理 |
| `transactions` | `idx_transactions_user_created(user_id, created_at, id)` | 用户流水列表 |
| `transactions` | `idx_transactions_user_type_created(user_id, type, created_at, id)` | 用户分类流水 |

MongoDB 消息集合会在消息服务首次使用时自动创建：

| 集合 | 索引 | 用途 |
| --- | --- | --- |
| `messages_*` | `uniq_chat_msg_id(chat_id, msg_id)` | 消息幂等 |
| `messages_*` | `uniq_chat_seq(chat_id, seq)` | 断线补拉、顺序同步 |

模型字段已覆盖的基础索引：

| 表 | 字段/索引 | 用途 |
| --- | --- | --- |
| `push_delivery_logs` | `occurred_at`、`success`、`channel`、`user_id`、`device_id` | 推送报表和失败日志 |
| `admin_login_logs` | `created_at`、`status`、`ip`、`username` | 安全审计和登录失败筛选 |
| `user_devices` | `user_id`、`device_id`、`last_active` | 在线设备、推送 token 和活跃状态 |
| `admins` | `username` unique | 后台登录 |
| `users` | `uuid`、`username`、`phone` 等模型索引 | 登录、搜索和用户管理 |

## P1 手动迁移 SQL

诊断类索引不放进启动自动迁移，避免线上大表在服务重启时被动建索引。上线时建议先在低峰核对现有索引，再按需执行：

```text
backend/scripts/p1_diagnostic_indexes.sql
```

覆盖范围：

| 表 | 索引 | 用途 |
| --- | --- | --- |
| `admin_login_logs` | `idx_admin_login_logs_created_id(created_at, id)` | 安全审计日志倒序分页 |
| `admin_login_logs` | `idx_admin_login_logs_status_created(status, created_at, id)` | 24 小时成功/失败统计和筛选 |
| `admin_login_logs` | `idx_admin_login_logs_throttle_created(throttle_applied, created_at, id)` | 登录限流统计和筛选 |
| `push_delivery_logs` | `idx_push_delivery_logs_occurred_id(occurred_at, id)` | 推送日志倒序分页和时间窗口统计 |
| `push_delivery_logs` | `idx_push_delivery_logs_success_occurred(success, occurred_at, id)` | 推送失败列表和成功率统计 |
| `push_delivery_logs` | `idx_push_delivery_logs_user_occurred(user_id, occurred_at, id)` | 用户诊断中的最近推送记录 |
| `push_delivery_logs` | `idx_push_delivery_logs_device_occurred(device_id, occurred_at, id)` | 设备维度推送日志筛选 |
| `push_delivery_logs` | `idx_push_delivery_logs_channel_occurred(channel, occurred_at, id)` | 渠道维度推送日志筛选 |
| `user_devices` | `idx_user_devices_user_last_active(user_id, last_active, id)` | 用户设备列表按活跃时间排序 |

## 线上核对 SQL

在 MySQL 执行：

```sql
SHOW INDEX FROM user_chats;
SHOW INDEX FROM chat_members;
SHOW INDEX FROM moments;
SHOW INDEX FROM transactions;
SHOW INDEX FROM push_delivery_logs;
SHOW INDEX FROM admin_login_logs;
SHOW INDEX FROM user_devices;
SHOW INDEX FROM admins;
SHOW INDEX FROM users;
```

如需补 P1 诊断索引，先核对是否已存在同名或等效索引，再执行：

```bash
mysql -u <user> -p <database> < backend/scripts/p1_diagnostic_indexes.sql
```

在 MongoDB 执行：

```javascript
db.getCollectionNames()
  .filter(function (name) { return name.indexOf('messages') === 0; })
  .forEach(function (name) {
    print(name);
    printjson(db.getCollection(name).getIndexes());
  });
```

## P1 验收口径

- 后台用户会话列表、群成员列表、推送日志、登录审计日志都有可用索引。
- 消息集合存在 `chat_id + msg_id` 和 `chat_id + seq` 唯一索引。
- 新部署启动日志中不再反复出现创建索引失败。
- 若线上已有大表，创建索引应安排低峰执行，并先备份数据库。
