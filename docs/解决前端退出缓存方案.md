# 解决前端退出缓存方案

## 1. 文档目的

本文解决 Flutter 客户端在退出账号、Token 失效、管理员强制下线和切换账号后，仍可能展示或复用上一账号数据的问题。

排查范围包括：

- Riverpod Provider 和页面内存状态；
- SharedPreferences、FlutterSecureStorage；
- Isar 本地数据库；
- 静态单例和进程级内存缓存；
- 图片、媒体、临时文件缓存；
- WebSocket、推送、后台保活、通话和会议状态；
- 手动退出、Token 失效、强制下线三条退出路径；
- iOS、Android、macOS、Windows 和 Web 的共用逻辑。

本文主要设计前端账号边界与缓存治理。服务端代码仅用于确认线上恢复边界；服务端删除账号数据和消息保留策略的具体改造不在本方案实施范围内。

## 2. 核心结论

当前问题不是单一的 `clear()` 遗漏，而是以下四类问题叠加：

1. 账号级 Provider 没有依赖当前账号 UUID，ProviderContainer 在整个 App 生命周期内复用，切换账号后仍保留旧状态。
2. 部分 SharedPreferences 和 Isar 数据没有 `accountId`，多个账号共用同一份本地数据。
3. 手动退出、Token 失效和强制下线没有经过同一套本地清理流程。
4. 部分异步请求没有账号世代校验，账号 A 发出的请求可能在账号 B 登录后回写状态。

已确认的最高风险问题：

- 联系人 Provider 和 Isar 联系人表未按账号隔离；
- 新账号联系人为空时不会用空列表覆盖旧联系人；
- 钱包、交易记录、VIP 状态和 VIP 订单 Provider 未按账号重建；
- 收藏消息的兜底迁移会扫描其他账号的收藏键并合并到当前账号；
- 自定义表情、收藏表情和表情云同步使用全局键，可能把账号 A 的表情上传到账号 B；
- Token 失效路径不会执行手动退出中的完整清理，离线发送队列等状态可能残留；
- 红包、转账状态缓存仅以业务 ID 为键，没有账号维度；
- 隐私设置和设备数 Provider 会复用上一账号状态。

### 2.1 最终方案选择

最稳妥的方向不是“退出时清空所有本地数据”，而是“可见运行态立即清空，持久数据严格按账号隔离”。最终采用四级操作模型：

| 操作 | 默认处理 | 聊天记录 | E2EE 私钥 |
| --- | --- | --- | --- |
| 普通退出、Token 失效、强制下线 | 清会话和账号运行态 | 按账号保留 | 保留 |
| 清除缓存 | 清临时文件和可重新下载媒体 | 保留文本和索引 | 保留 |
| 清除本机账号数据 | 仅删除指定账号的数据库、偏好和私有媒体 | 删除本机副本，可尝试从线上重建 | 默认保留 |
| 删除加密身份 | 单独的高风险操作，二次确认 | 线上密文可能无法再解密 | 删除 |

必须坚持以下边界：

- 普通退出不能删除 `ChatModel`、`MessageModel` 和 E2EE 私钥；
- 账号 B 登录后不能读取账号 A 的任何持久缓存，即使账号 A 的数据仍保留在本机；
- “清除缓存”不能等同于“清除聊天记录”；
- “线上能拉到消息”不能等同于“消息一定可以完整恢复和解密”；
- 删除加密私钥必须和退出、清缓存、清账号数据三个操作彻底解耦。

## 3. 数据分级原则

退出时不应简单地清空全部缓存。缓存必须先按数据归属分类。

| 数据级别 | 示例 | 退出行为 |
| --- | --- | --- |
| 凭证级 | JWT、用户 UUID、用户资料快照、推送绑定 | 必须立即清除或解绑 |
| 账号运行态 | 好友、钱包、VIP、动态、设备数、当前聊天、会议、通话 | 必须立即从内存移除 |
| 账号持久缓存 | 聊天、消息、联系人、收藏、表情、文件夹 | 普通退出保留，但必须按账号 UUID 隔离 |
| 设备偏好 | 语言、主题、下载策略、窗口大小、快捷键 | 默认保留，不随账号清除 |
| 公共配置 | 系统设置、官方账号列表、发现页配置、VIP 套餐 | 可以跨账号复用 |
| 可再下载媒体 | 头像、图片、视频、语音缓存 | “清除缓存”可以删除，使用时从有效远程地址重下 |
| 本地唯一数据 | 未发送消息、离线草稿、尚未上传的媒体 | 不能当缓存删除，必须按账号冻结或明确提示用户 |
| 加密身份 | E2EE 公私钥、设备注册标识 | 普通退出和清缓存必须保留；删除必须单独确认 |

账号级缓存的基本规则：

- 所有内存键、磁盘键和数据库索引都必须包含稳定的账号 UUID；
- 空账号和 `anonymous` 不能读取任何已登录账号数据；
- 服务端返回空列表时，空列表是权威结果，必须覆盖旧状态和旧索引；
- 网络失败可以回退到“当前账号自己的缓存”，不能回退到其他账号缓存；
- 切换账号时先清空可见状态，再发起新账号请求，不能等请求成功后才覆盖。
- 每一项持久数据都必须明确标注为“可重建”或“本地唯一”，未标注的数据禁止被批量清理。

## 4. 当前退出流程

### 4.1 手动退出

当前 `AuthService.logout()` 大致执行：

1. 向 `/auth/logout` 提交推送 bindings；
2. 清除本地推送 Token；
3. 重置朋友圈 Provider；
4. 清除 TokenStorage；
5. 清除离线发送队列；
6. 将认证状态改为 `unauthenticated`。

App 根节点监听到未登录后仅额外执行：

- 重置聊天列表；
- 清零未读角标。

相关代码：

- `lib/core/services/api/auth_service.dart`
- `lib/app.dart`

缺口是联系人、钱包、VIP、设备数、隐私、收藏、表情、聊天文件夹、红包/转账缓存、通话和会议运行态都没有进入统一清理。

### 4.2 Token 失效

`ApiClient._triggerLogout()` 会清除 TokenStorage，再调用 `AuthService._handleTokenExpired()` 改认证状态。

这条路径不会执行 `AuthService.logout()` 中的：

- 服务端登出；
- 推送本地状态清理；
- 朋友圈 reset；
- 离线发送队列 clear。

App 根节点仍然只重置聊天列表和未读角标。因此 Token 失效后再登录新账号，比手动退出更容易残留账号 A 的运行态。

### 4.3 管理员强制下线

WebSocket `force_logout` 当前会调用 `AuthService.logout()`，行为接近手动退出。

但是只要未来出现其他直接写入 `AuthStatus.unauthenticated` 的路径，仍会绕过手动退出逻辑。清理不能继续依赖每个调用点自行记住所有步骤。

### 4.4 WebSocket

WebSocket Provider 已监听认证状态，离开已登录态时执行 `disconnect(clearToken: true)`，这一部分处理正确。

### 5.1 P0：联系人列表跨账号泄漏

文件：`lib/features/contacts/providers/contact_provider.dart`

已确认问题：

1. `contactListProvider` 不依赖 `authServiceProvider.user.uuid`，切换账号不会重建。
2. `ContactListNotifier.reset()` 虽然存在，但退出流程没有调用。
3. `_isInitialized` 在账号 A 初始化后保持为 `true`；账号 B 打开联系人页时，`initialize()` 会直接返回。
4. 本地 `UserModel` 没有 `accountId` 字段，所有账号共用 `isContact=true` 的记录。
5. `_loadContactListFromCache()` 会读取全部账号的联系人。
6. `loadFromServer()` 和 `silentRefresh()` 只在服务端列表非空时更新状态；账号 B 返回空列表时，账号 A 的联系人不会被清除。
7. 联系人异步请求没有捕获账号世代，旧请求可能跨账号回写。

影响：

- 新注册空账号可能直接看到旧账号好友；
- 完全重启 App 后仍可能从 Isar 读出旧好友；
- 联系人搜索、名片选择、建群成员选择等依赖 `contactListProvider` 的功能也可能使用旧好友。

修复要求：

- Provider 必须 watch 当前账号 UUID；
- `UserModel` 增加 `accountId`，主键改为 `fastHash('$accountId:$id')`，建立 `(accountId, id)` 唯一索引；
- 所有联系人查询和删除必须带 `accountId`；
- 服务端成功返回空列表时执行 `state = []`，并删除当前账号旧联系人缓存；
- `_fetchAllContacts()` 应返回带 `requestSucceeded` 的结果对象，明确区分“成功空列表”和“网络失败”，不能继续用空 List 同时表达两种状态；
- 账号切换后旧请求不得回写新 Provider；
- 旧版无账号联系人缓存不可信，升级迁移时直接删除并从服务端重拉。

### 5.2 P0：钱包与交易记录

文件：`lib/features/wallet/providers/wallet_provider.dart`

已确认问题：

- `walletProvider` 不依赖账号 UUID，也没有 reset；
- 余额、冻结金额、支付密码状态和交易记录会留在 StateNotifier 中；
- 新账号请求完成前会继续展示旧账号余额；
- 如果新请求失败，旧钱包数据可能持续显示；
- `redPacketProvider`、`redPacketClaimsProvider`、`transferProvider` 的缓存键只有业务 ID，没有账号 UUID。

修复要求：

- `walletProvider` watch 当前账号 UUID并在变更时创建全新 notifier；
- WalletState 增加可以显式清空 nullable 字段的 copyWith，或直接使用 `const WalletState()` reset；
- 红包、领取记录、转账详情 Provider 参数改成 `(accountId, id)`，并使用 autoDispose；
- 退出瞬间清空钱包和交易列表，不等待新账号请求。

### 5.3 P0：收藏消息错误兜底

文件：`lib/features/chat/services/favorite_message_service.dart`

收藏主键表面上已经包含账号 UUID，但 `loadFavorites()` 在当前账号没有收藏时会：

1. 枚举所有 `favorite_messages_v1_*` 键；
2. 合并所有账号的收藏；
3. 将合并结果保存到当前账号。

这是确定的跨账号数据复制，不是单纯的显示缓存。

修复要求：

- 删除 `_fallbackScopedKeys()` 的跨账号扫描；
- 旧全局键 `favorite_messages_v1` 只允许在“已确认的首次迁移账号”中迁移一次；
- 迁移完成写入 `favorite_messages_migrated_to_<accountId>` 标志并删除旧全局键；
- 当前账号键为空时必须返回空列表。

### 5.4 P0：表情商店与自定义表情

文件：`lib/features/chat/services/emoji_store_service.dart`

以下键目前是全局键：

- `installed_sticker_packs`；
- `favorite_emoji_codes`；
- `custom_emoji_items`；
- `recent_emojis`；
- `emoji_store_cloud_updated_at`。

其中安装包、收藏表情、自定义表情和云版本属于账号数据。当前逻辑还会把本地自定义表情与服务端数据合并，随后可能同步回服务器。

影响：

- 账号 B 看到账号 A 的自定义表情；
- 账号 A 的本地表情可能被上传或合并到账号 B；
- 两个账号的 `updated_at` 冲突，产生错误的 409 合并结果；
- 自定义表情文件保存在全局 `custom_emojis` 目录。

修复要求：

- 账号级键统一改为 `<accountId>:emoji_store:<suffix>`；
- 自定义表情目录改为 `custom_emojis/<accountId>/`；
- 静态方法必须显式接收 accountId，禁止通过晚到的 Token 猜测账号；
- 云同步任务捕获启动时 accountId，回写前再次校验；
- 旧全局数据只迁移给一次性确认的原账号，不能在多个账号之间自动合并。

`recent_emojis` 是否跨账号共享需要产品决策。为避免隐私串号，建议也按账号隔离。

### 5.5 P1：设备数量

文件：`lib/features/settings/pages/settings_page.dart`

`deviceCountProvider` 是非 autoDispose FutureProvider，不依赖账号 UUID。请求一次后结果会在 ProviderContainer 中复用。

另外，当前 UI 把 `/user/devices` 返回的所有设备数量显示为“已登录设备/活跃会话”，没有根据 `has_active_session` 过滤，文案和数据含义不一致。

修复要求：

- Provider watch 当前账号 UUID；
- 账号为空时返回 0；
- 根据产品定义决定显示“历史设备数”还是 `has_active_session=true` 的“活跃设备数”；
- 登录、注册、一键注册和账号切换后必须请求当前账号数据。

### 5.6 P1：VIP 状态与订单

文件：`lib/features/vip/providers/vip_provider.dart`

已确认问题：

- `vipStatusProvider` 是全局 FutureProvider，不依赖账号；
- `vipOrdersProvider` 不依赖账号且没有 reset；
- `vipPlansProvider` 是公共套餐，可以跨账号复用。

修复要求：

- VIP 状态和订单 watch 当前账号 UUID；
- VIP 状态使用 autoDispose 或 `(accountId)` family；
- 退出时清空订单列表；
- 保留公共套餐缓存。

### 5.7 P1：隐私设置

文件：`lib/features/settings/pages/privacy_settings_page.dart`

当前一个 Provider 同时混合两类数据：

- 服务端账号设置：在线状态可见性、手机号可见性、群邀请权限、手机号搜索、短号搜索、设备锁、自动注销；
- 设备本地设置：生物识别、App 锁、自动锁定、部分两步验证状态。

SharedPreferences 键均未包含账号 UUID，Provider 也不依赖账号。账号切换后不会重新执行构造和 `_loadSettings()`。

修复要求：

- 拆成 `AccountPrivacySettingsProvider(accountId)` 与 `DeviceSecuritySettingsProvider`；
- 账号设置以服务端为权威，本地缓存键带 accountId；
- App 锁、生物识别等设备设置明确保留为设备级；
- `two_step_password_hash`、`privacy_two_step` 如果仍代表账号安全能力，必须改为账号级或移到服务端；
- 账号切换时账号设置先恢复默认加载态，不能展示旧账号值。

### 5.8 P1：通知预览设置

文件：`lib/core/services/notification_sound_service.dart`

通知服务是全局 Provider，所有设置使用全局 SharedPreferences。登录成功后，App 会调用 `syncSettingsToServer()`，把当前本地 `showPreview` 写到新账号后端。

这可能不是“读到旧设置”，而是用账号 A 的设置覆盖账号 B。

修复要求：

- 声音、振动、铃声可以定义为设备级；
- `show_preview` 等服务端账号设置必须从设备设置中拆开；
- 登录后应先拉取账号服务端值，不能先把旧本地值上传；
- 用户主动修改时才向服务器写入。

### 5.9 P1：离线发送队列

文件：`lib/core/services/offline_message_queue.dart`

当前离线队列使用单一全局键 `offline_message_queue`，队列项没有强制账号边界。手动退出会 clear，但 Token 失效路径不会经过手动退出。

风险：

- 账号 A 的待发送草稿可能在账号 B 登录并恢复网络后，以账号 B 的 Token 重发；
- 异步发送正在进行时退出，可能继续完成或回写状态。

修复要求：

- OfflineMessage 增加 `accountId`；
- 持久键改为 `offline_message_queue_<accountId>`；
- 发送前校验当前账号与消息 accountId；
- 所有退出路径立即取消处理并清空内存队列；
- 新版磁盘队列按账号冻结，只能在同账号再次登录后恢复；
- 无法确认归属的旧版全局队列安全优先删除，绝不能迁移给当前账号。

### 5.10 P1：红包和转账状态单例

文件：`lib/features/chat/widgets/message_bubble_wallet.dart`

`WalletStatusCache` 是进程级单例：

- 内存键只有 red packet ID 或 transfer ID；
- SharedPreferences 键为 `rp_status_<id>`、`tf_status_<id>`；
- 没有 clear/reset API。

修复要求：

- 缓存键加入 accountId；
- 增加 `clearMemoryForAccount()` 和 `clearAllMemory()`；
- Provider/组件传入当前账号 UUID；
- 账号切换时清空进程级 Map。

### 5.11 P1：通话、会议和录音运行态

相关文件：

- `lib/core/services/call_service.dart`
- `lib/core/services/meeting_session_service.dart`
- `lib/core/services/voice_record_service.dart`

这些 Provider 不依赖账号 UUID，退出流程没有统一执行结束通话、离开会议、清除悬浮会议或取消录音。

修复要求：

- 退出前结束或安全离开当前通话/会议；
- 清空 `MeetingSessionState`；
- 取消正在进行的录音并删除临时录音；
- 关闭铃声、Wakelock、RTC/LiveKit/Agora 资源；
- 以上步骤设置超时，不能阻塞本地凭证清除。

### 5.12 P1：推送状态和待处理导航

文件：`lib/core/services/push_notification_service.dart`

手动退出会调用 `clearToken()`，但 Token 失效路径只改变认证状态，没有执行同等清理。推送服务还持有：

- 厂商 Token 和 channel 映射；
- 本地 binding 快照；
- 上传重试 Timer；
- `_pendingNotificationTap`；
- 最近一次通知点击签名。

风险：

- 旧账号通知点击可能在新账号登录后被 flush 并导航；
- Token 上传重试可能跨账号继续；
- 服务端绑定来不及解除时，设备短时间继续收到旧账号推送。

修复要求：

- 增加 `clearAccountRuntimeState()`，所有退出路径执行；
- 清 pending tap、点击去重状态、上传重试和本地 binding；
- 推送回调处理前校验 payload 中的 user/account 标识；
- 新账号注册推送时以账号世代为条件，旧任务完成后不得回写；
- 服务端解绑失败不阻止本地退出，但应记录并在下次注册时做唯一绑定修复。

### 5.13 P2：后台保活

文件：`lib/core/services/background_service.dart`

后台保活策略属于设备偏好，可以跨账号保留；但通知栏标题、最后消息内容、未读数和 keepAlive handler 属于账号运行态。

当前 App 会把未读数清零，但没有一个明确的账号 teardown 接口。

修复要求：

- 增加 `clearAccountRuntimeState()`，清最后消息标题、内容、未读数和账号回调；
- 未登录时保活服务可以继续存在，但不得触发账号 API、WebSocket 重连或显示旧消息；
- 高安全退出可以选择停止后台服务，普通退出保留用户的设备级保活偏好。

### 5.14 P2：聊天文件夹

文件：`lib/features/chat/providers/folder_provider.dart`

`chat_folders` 是全局 SharedPreferences 键，文件夹中可能保存 `includeChatIds` 和 `excludeChatIds`。

影响主要是新账号继承旧账号分组和旧 chatId。虽然聊天列表已经按账号隔离，仍可能造成错误过滤和账号痕迹泄漏。

修复要求：

- 文件夹键改为 `chat_folders_<accountId>`；
- 默认文件夹可以作为设备模板，新账号首次使用时复制模板；
- 账号退出时重建 FolderNotifier。

### 5.15 P2：媒体与文件缓存

当前头像缓存、聊天媒体缓存、下载文件、自定义表情目录大多是全局目录：

- `AvatarCacheManager`；
- `ChatMediaCacheManager`；
- `Application Support/media_cache`；
- `Application Documents/custom_emojis`；
- 部分下载文件和临时文件。

这些文件默认可以保留以提高性能，但必须满足：

- 新账号没有任何旧索引可以导航到旧文件；
- 文件名或缓存元数据不直接作为账号数据列表展示；
- 提供“退出并清除本机数据”选项，删除指定账号的媒体索引和私有目录；
- 自定义表情和用户主动下载的私有文件应放入账号目录；
- Flutter 内存 ImageCache 在高安全退出模式下可执行 `clear()` 和 `clearLiveImages()`。

## 6. 已正确或基本正确的部分

### 6.1 聊天列表

`chatListProvider` 已 watch 当前用户 UUID，账号变更会重建 notifier。App 进入未登录状态时也会 reset。

### 6.2 消息列表

`messageListProvider` 已 watch 当前用户 UUID；内存窗口、SharedPreferences 键和 Isar MessageModel 都包含 accountId。

### 6.3 聊天 Isar 模型

`ChatModel` 和 `MessageModel` 的主键和查询包含 accountId，可以保留旧账号本地缓存并在同账号再次登录时复用。

### 6.4 E2EE 密钥

E2EE Secure Storage 命名空间使用 `userId + deviceId` 哈希，账号之间已隔离。退出时不需要删除私钥，否则会破坏同账号历史加密消息解密能力。

### 6.5 WebSocket

认证状态离开 authenticated 后会断开并清除 WebSocket Token。

### 6.6 桌面端选中状态

桌面端已在未登录时清除 selectedChatId、selectedChatInfo、资料面板和导航位置。

### 6.7 朋友圈

手动退出会 reset 朋友圈状态。但 Token 失效等非手动路径仍应纳入统一协调器。

### 6.8 聊天记录线上恢复能力

当前客户端具备从线上重建聊天列表和消息窗口的基本能力：

- `/chat/list` 会分页拉取全部可见会话；
- 打开会话时 `/message/list` 默认先拉最近 30 条消息；
- 继续上拉时通过 `before_seq` 分页加载更早消息；
- 断线补偿通过 `/message/sync` 按 `last_seq` 拉取增量消息；
- 拉取成功后重新写入按 accountId 隔离的 Isar 缓存。

但当前服务端 `MessageService.getMessagesBySeq()` 只遍历最近 12 个自然月的消息分表。因此删除本地消息库后，不能承诺恢复超过该查询窗口的历史消息。上线前必须二选一：服务端扩展游标查询以覆盖承诺的完整保留期；或产品明确告知用户只能恢复最近 12 个月。没有完成其中一项前，前端不能显示“全部聊天记录可恢复”。

以下数据也不能仅依靠线上恢复：

- 未发送成功或尚未进入服务端的消息；
- 离线草稿和待上传媒体；
- 远程文件已经失效或被删除的图片、视频、语音和文件；
- 用户主动清空、单向删除、阅后即焚的数据；
- 不允许查看入群前历史的群聊消息。

### 6.9 E2EE 恢复边界

线上保存的是密文和发送时为各设备生成的密钥信封，不保存客户端私钥：

- 同一设备保留原 E2EE 私钥时，重新登录后可以解密包含该设备信封的线上历史；
- 删除 Secure Storage 中的私钥后，即使线上返回消息，也可能只能显示加密占位文案；
- 新设备生成的新密钥不一定存在于旧消息的密钥信封中，因此不能默认解密全部旧消息；
- 当前代码没有完整的私钥云备份、恢复或旧消息密钥重新封装流程。

所以 E2EE 私钥不属于普通缓存。除非先建设可靠的加密密钥备份与恢复能力，否则任何自动清理流程都不得删除它。

### 6.10 本地聊天记录最终策略

本地聊天数据采用“保留、隔离、惰性校准”：

1. 普通退出保留当前账号的 ChatModel、MessageModel、消息窗口和 E2EE 私钥；
2. 退出后立即销毁内存 Provider，使登录页和其他账号不可见；
3. 同账号重新登录时先展示自己的本地缓存，再用服务端结果校准；
4. 新账号登录时只能查询自己的 accountId，绝不扫描其他账号数据；
5. 用户主动清除本机账号数据后，先拉会话列表，进入会话再按需分页恢复消息；
6. 线上恢复期间明确显示“正在同步”，不能用空白界面暗示历史已永久丢失；
7. 未发送消息和离线队列按 accountId 冻结，只有同一账号重新登录后才能恢复处理。

## 7. 目标架构

### 7.1 单一账号标识 Provider

新增只读账号标识：

```dart
final currentAccountIdProvider = Provider<String>((ref) {
  return ref.watch(
    authServiceProvider.select((state) => state.user?.uuid ?? ''),
  );
});
```

所有账号级 Provider 必须 watch 此 Provider，不能只 watch ApiClient。

### 7.2 账号会话协调器

建议新增：

`lib/core/session/account_session_coordinator.dart`

职责：

- 监听 `previousAccountId -> nextAccountId`；
- 维护单调递增的 `accountEpoch`；
- 统一执行运行态 teardown；
- 统一 invalidate 账号级 Provider；
- 取消旧账号异步任务；
- 区分手动退出、Token 过期、强制下线、删除账号、切换账号；
- 收集清理错误但保证凭证清除继续执行；
- 对同一退出事件加锁并保证幂等，避免 Token 失效、WebSocket 强退和用户点击退出同时重复执行；
- 落盘记录 `accountId + reason + phase`，App 被杀后可在下次启动完成未结束的本地 teardown。

推荐状态转换：

```text
authenticated(A)
  -> signingOut(A)
  -> localTeardown(A)
  -> credentialsCleared
  -> unauthenticated
  -> authenticated(B)
  -> accountProvidersRebuilt(B)
```

任何路径只要从 authenticated 离开，都必须触发同一套 `localTeardown(A)`。

建议为清理原因和范围使用强类型枚举，禁止用多个布尔参数组合：

```dart
enum SessionExitReason {
  manual,
  tokenExpired,
  forcedOffline,
  accountDeleted,
}

enum LocalDataAction {
  keepAccountData,
  clearDownloadableCache,
  purgeAccountData,
  purgeEncryptionIdentity,
}
```

`purgeEncryptionIdentity` 只能由独立二次确认触发，不能成为退出流程的隐式默认值。

### 7.3 两阶段退出

阶段一：远端尽力清理，设置短超时。

- 提交 `/auth/logout`；
- 提交推送解绑；
- 结束通话或会议；
- 不允许网络失败阻止本地退出。

阶段二：本地确定性清理。

- 先阻止新请求和旧异步回写；
- 断开 WebSocket；
- 清推送运行态和 pending tap；
- 清账号运行态 Provider；
- 清或隔离离线队列；
- 清 TokenStorage；
- 导航到登录页。

阶段二必须可重复执行。每完成一个关键阶段更新落盘标记；只有所有本地 teardown 完成后才删除标记。即使远端退出失败、进程崩溃或设备断网，本机也不能停留在“凭证已变更但旧账号 Provider 仍活跃”的中间状态。

### 7.4 账号世代防竞态

每个账号级异步加载应捕获：

```dart
final requestAccountId = ref.read(currentAccountIdProvider);
final requestEpoch = ref.read(accountEpochProvider);
final result = await api.load();
if (requestAccountId != ref.read(currentAccountIdProvider) ||
    requestEpoch != ref.read(accountEpochProvider)) {
  return;
}
```

Notifier 被重建且正确 dispose 时也可以阻断回写，但静态服务和单例仍需要显式 epoch。

### 7.5 账号级本地键工具

新增统一工具，禁止业务自行拼接不一致的键：

```dart
String accountStorageKey(String accountId, String suffix) {
  if (accountId.trim().isEmpty) {
    throw StateError('accountId is required for account-scoped storage');
  }
  return 'account:${accountId.trim()}:$suffix';
}
```

所有账号级 SharedPreferences、文件目录、内存 Map 使用相同命名规则。

### 7.6 离线队列与本地唯一数据

离线队列项必须包含 `accountId`、`chatId`、客户端消息 ID 和待上传资源归属：

- 退出时停止 worker 并冻结当前账号队列；
- 登录账号 B 时只加载 B 的队列；
- 重新登录账号 A 后，先校验消息是否已由服务端接收，再恢复发送；
- 清除本机账号数据时明确提示会删除多少条未发送消息；
- 在队列完成账号化之前，过渡版本仍应安全优先清空旧全局队列，避免用 B 的 Token 发送 A 的消息。

### 7.7 清理结果与可观测性

协调器应为每次退出生成 traceId，并记录不含敏感内容的结果：退出原因、旧 accountId 哈希、执行阶段、失败组件和耗时。清理单项失败不能阻塞 Token 清除，但必须可诊断并在下次启动重试本地清理。

## 8. 统一清理清单

### 8.0 清理矩阵

| 数据/资源 | 普通退出/失效/强退 | 清除缓存 | 清除本机账号数据 | 删除加密身份 |
| --- | --- | --- | --- | --- |
| Token、用户快照、ApiClient Token | 清除 | 不涉及 | 清除 | 清除 |
| Provider 可见状态、页面选中状态 | 清空 | 不涉及 | 清空 | 清空 |
| WebSocket、RTC、录音、后台任务 | 停止 | 不涉及 | 停止 | 停止 |
| ChatModel、MessageModel | 按账号保留 | 保留 | 仅删除目标账号 | 保留或已删除 |
| 联系人、收藏、表情、文件夹缓存 | 按账号保留 | 保留 | 仅删除目标账号 | 保留 |
| 离线消息、草稿、待上传媒体 | 按账号冻结 | 保留 | 提示后删除目标账号 | 保留 |
| 临时文件、可再下载媒体 | 保留 | 删除 | 删除目标账号 | 不涉及 |
| E2EE 公私钥 | 保留 | 保留 | 默认保留 | 二次确认后删除 |
| 语言、主题、下载策略 | 保留 | 保留 | 保留 | 保留 |

### 8.1 任何退出路径都执行

- 增加 accountEpoch，阻止旧请求回写；
- `webSocket.disconnect(clearToken: true)`；
- `contactListProvider` 清空/重建；
- `chatListProvider` 清空/重建；
- `momentProvider.reset()`；
- `walletProvider` 清空；
- VIP 状态和订单 invalidate；
- `deviceCountProvider` invalidate；
- 账号隐私设置 invalidate；
- 红包/转账进程缓存清空；
- 桌面端 selected chat/profile/nav 清空；
- 会议悬浮状态清空；
- 当前通话、录音、临时媒体任务结束；
- 未读角标和后台通知内容清零；
- pending notification tap 清空；
- 取消旧账号上传、预取、同步和定时任务；
- 清 TokenStorage 和 ApiClient Token。

### 8.2 手动退出额外执行

- 服务端 `/auth/logout`；
- 精确推送解绑；
- 冻结当前账号离线队列和草稿，等待同账号重新登录；
- 旧版全局离线队列在完成 accountId 迁移前安全优先清空。

### 8.3 Token 失效额外执行

- 不再尝试依赖失效 Token 的远端请求；
- 本地 teardown 与手动退出完全一致；
- 记录退出原因供登录页提示。

### 8.4 “退出并清除本机数据”额外执行

- 删除当前账号 ChatModel、MessageModel、UserModel；
- 删除账号级 SharedPreferences 键；
- 删除账号自定义表情和私有媒体目录；
- 清头像、聊天媒体磁盘缓存和 Flutter ImageCache；
- 删除前统计并提示本地唯一数据，包括未发送消息、草稿和待上传文件；
- 完成后重新登录只能依靠线上会话和消息接口惰性重建；
- 默认保留 E2EE 密钥，保证同设备仍有机会解密线上历史。

默认普通退出不应删除已正确按账号隔离的聊天、消息和 E2EE 密钥。

### 8.5 “删除加密身份”额外执行

这是独立的高风险操作，不能和“清除缓存”共用按钮：

- 展示不可逆警告：旧加密消息可能永久无法解密；
- 要求二次确认或输入登录密码；
- 明确显示影响的账号和设备；
- 删除指定 `userId + deviceId` 命名空间的 E2EE 公钥、私钥和注册标识；
- 通知服务端注销该设备公钥；
- 清理完成后不承诺恢复旧 E2EE 消息。

### 8.6 明确禁止

- 禁止退出时调用 SharedPreferences 全量 `clear()`；
- 禁止退出时清空整个 Isar 实例；
- 禁止删除全部 FlutterSecureStorage；
- 禁止为了避免串号而删除所有账号聊天记录；
- 禁止在新账号缓存为空时扫描其他账号键作为 fallback；
- 禁止在账号 ID 为空时读取账号级缓存；
- 禁止让旧请求、旧 WebSocket 事件或旧队列在 accountEpoch 变化后写入。

## 11. 数据迁移策略

### 11.1 UserModel

UserModel 旧记录没有来源账号，无法可靠判断归属。联系人可以从服务端重建，因此升级时应删除旧 UserModel 联系人数据，不要猜测并迁移到当前账号。

### 11.2 SharedPreferences 旧全局键

允许迁移的前提：

- 当前只有一个已知账号；
- 迁移只执行一次；
- 迁移目标账号 UUID 明确；
- 迁移成功后删除全局键并写迁移标志。

无法确认归属的数据直接删除或保留为设备模板，禁止扫描并合并到任意新账号。

### 11.3 自定义表情文件

旧 `custom_emojis` 目录无法可靠区分账号。建议：

- 已登录升级时仅向当时账号迁移一次；
- 没有明确账号时不自动上传；
- 其余旧文件保留在 legacy 目录，用户手动导入或清理。

### 11.4 聊天与消息数据

现有 ChatModel 和 MessageModel 已包含 accountId，不做破坏性迁移，也不因升级或退出删除。升级后执行一次完整性检查：

- accountId 为空的记录禁止展示并移入待清理集合；
- 合法账号记录继续保留；
- 消息窗口、已删除消息 ID、阅后即焚状态等 SharedPreferences 键继续保持 accountId + chatId；
- 不用线上最近消息覆盖本地更长历史，只做按消息 ID 和 seq 合并；
- 服务端成功返回空列表只代表当前分页为空，不能据此批量删除更早的本地历史。

### 11.5 离线队列

旧版全局队列无法可靠判断账号归属，升级时不得迁移给当前登录账号。可以保留一份只用于诊断的数量统计，但消息正文和附件应安全删除；新版队列从创建时就写入 accountId。

## 12. 测试方案

当前测试目录没有发现覆盖“账号 A → 退出 → 账号 B”的前端缓存回归测试，需要新增。

### 12.1 Provider 单元测试

每个账号级 Provider 至少覆盖：

1. 账号 A 加载非空数据；
2. 退出后状态立即为空；
3. 账号 B 登录后 Provider 被重建；
4. 账号 B 服务端返回空列表；
5. 页面保持为空，不出现账号 A 数据；
6. 账号 A 的延迟响应在 B 登录后返回，不得回写；
7. 账号 B 请求失败时不得回退到 A 的内存缓存。

### 12.2 联系人测试

- A 有 20 个好友，B 为新账号 0 好友；
- 普通退出、Token 过期、强制下线三条路径结果一致；
- App 重启后 B 仍为 0；
- Isar 中 A、B 联系人可并存且查询互不影响；
- 服务端空列表会删除 B 的过期本地联系人索引。

### 12.3 钱包与 VIP 测试

- A 有余额和交易，B 余额为 0；
- 切号瞬间不显示 A 的余额；
- B 请求失败时显示错误/空态，不显示 A 数据；
- VIP 状态、VIP 订单同样隔离；
- 红包和转账缓存不能跨 accountId 命中。

### 12.4 收藏与表情测试

- B 收藏为空时不得扫描 A 的收藏键；
- B 不得看到或上传 A 的自定义表情；
- 两账号云更新时间独立；
- legacy 迁移只能发生一次。

### 12.5 离线队列测试

- A 离线发送一条消息后退出；
- B 登录并恢复网络；
- A 的消息不得使用 B Token 发送；
- Token 过期和强制下线路径同样阻断；
- 正在处理的队列在 accountEpoch 变化后停止。

### 12.6 运行资源测试

- 通话中退出；
- 会议最小化时退出；
- 录音中退出；
- 上传媒体中退出；
- 退出后无旧账号 WebSocket、RTC、录音、Wakelock、后台通知内容或导航回调。

### 12.7 聊天记录保留与恢复测试

- 账号 A 普通退出再登录，首屏先加载 A 自己的 Isar 缓存并完成线上校准；
- A 退出后登录 B，B 不能查询或展示 A 的 ChatModel、MessageModel 和消息窗口；
- 清除可再下载缓存后，文字历史仍在，远程地址有效的媒体可以重新下载；
- 清除 A 的本机账号数据后，B 的本地历史不受影响；
- A 重新登录后可通过 `/chat/list` 重建会话，并通过 `/message/list` 分页重建服务端可见历史；
- 超过服务端查询窗口、本地未发送消息和失效媒体必须展示准确提示，不能承诺已恢复全部历史；
- 保留 E2EE 私钥时，同设备可解密包含本设备信封的历史；删除私钥后测试旧密文显示不可解密提示；
- 清理过程中强杀 App，下次启动必须根据落盘阶段完成 teardown，不能短暂展示旧账号数据。

### 12.8 平台回归矩阵

至少覆盖：

- iOS 模拟器和真机；
- Android 模拟器和真机；
- macOS；
- Windows；
- Web 刷新前和刷新后。

重点验证 iOS Keychain 会跨卸载保留部分数据、Web ProviderContainer 长生命周期、桌面端常驻托盘和 Android 后台服务。

## 13. 验收标准

满足以下全部条件才算完成：

1. 账号 B 登录后的第一帧不出现账号 A 的昵称、好友、设备、余额、VIP、动态、收藏或表情数据。
2. B 服务端返回空列表或网络错误时，界面不回退到 A 的缓存。
3. A 的异步请求、WebSocket 事件、推送点击和离线队列不能在 B 会话中生效。
4. 所有账号级持久缓存都可通过 accountId 定位。
5. 手动退出、Token 过期、强制下线使用同一套本地 teardown。
6. 聊天和消息缓存可以为多个账号保留，但只能由对应账号读取。
7. 设备级偏好不会因为普通退出丢失。
8. “退出并清除本机数据”可以删除指定账号缓存，不误删其他账号缓存。
9. 自动化测试覆盖 A 非空、B 为空、请求延迟、请求失败四个关键场景。
10. 普通退出和清除缓存不会删除本地聊天文本、离线草稿或 E2EE 私钥。
11. 清除本机账号数据后，重新登录可以恢复服务端可见范围内的消息，并明确提示不可恢复边界。
12. 删除 E2EE 私钥必须独立二次确认，且不能由退出、Token 失效或缓存清理间接触发。
13. 退出过程中进程崩溃后，再启动仍能完成幂等清理，不显示旧账号首帧。

## 14. 建议的完成顺序

按安全影响排序：

1. 联系人；
2. 钱包、交易、红包和转账；
3. 收藏消息和表情云数据；
4. 统一退出协调器与离线队列；
5. VIP、设备数、隐私和通知；
6. 聊天文件夹；
7. 通话、会议、录音和媒体清理；
8. 分级的“清缓存、清账号数据、删除加密身份”。

不要先做“退出时删除所有 SharedPreferences/Isar”。这种做法会破坏设备偏好、同账号快速恢复和 E2EE 历史消息能力，且不能解决异步请求跨账号回写。正确方向是建立明确的账号边界，再让所有退出原因进入同一个 teardown。

最终决策：默认退出只清会话和运行态，不删除聊天持久数据；默认清缓存只删除可再下载文件；清账号数据只影响用户明确选择的账号；E2EE 私钥只允许通过独立高风险操作删除。这是在防串号、数据可恢复性和用户隐私之间最稳妥的平衡。
