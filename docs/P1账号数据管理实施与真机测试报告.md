## 1. 本阶段交付结果

P1 将容易混淆的本地数据操作拆成三个互不替代的入口：

| 操作 | 删除内容 | 明确保留 | 完成后状态 |
| --- | --- | --- | --- |
| 清除缓存 | 可重新下载的图片/视频/文件缓存、当前账号下载副本、Flutter 图片缓存 | 聊天、联系人、草稿、离线待发消息、E2EE 私钥 | 保持登录 |
| 清除本机账号数据 | 当前账号的 Isar 聊天/消息/联系人、账号级 SharedPreferences、草稿、离线队列、账号私有媒体 | 服务器账号、其他账号本地数据、当前账号 E2EE 私钥 | 退出登录 |
| 重置加密身份 | 旧设备私钥被新密钥替换，服务器公钥同步更新 | 账号及普通业务数据 | 退出登录 |

界面在“设置 → 数据和存储 → 本机账号数据”提供三个独立入口。高风险操作分别要求输入 `CLEAR` 和 `RESET`，避免误触。

## 2. 核心实现

### 2.1 账号级数据清理服务

- 新增 `AccountDataCleanupService`，清理范围必须绑定 `accountId`。
- SharedPreferences 只删除目标账号前缀和目标账号精确旧键，不扫描或模糊匹配其他账号。
- Isar 按账号删除聊天、消息和用户数据。
- 删除媒体前先收集其他账号引用；被其他账号引用的共享文件不会删除。
- 离线消息队列、草稿和账号私有媒体纳入统计及风险提示。

### 2.2 中断恢复

“清除本机账号数据”使用持久化清理日志，按以下阶段推进：

1. 已计划；
2. 已删除目标账号引用的本地媒体；
3. 已删除 Isar 数据；
4. 已删除账号级偏好；
5. 已删除离线队列；
6. 已删除账号私有目录。

应用启动时先恢复未完成清理，再决定是否恢复旧登录态。如果待清理账号仍是当前登录账号，会先清除认证信息，防止清理中断后短暂显示旧账号数据。每个阶段可重复执行，全部成功后才删除清理日志。

### 2.3 媒体按账号归属

- 新下载文件迁移到账号私有 `downloads` 目录。
- 桌面端下载副本迁移到账号私有 `desktop_downloads` 目录。
- 自定义表情迁移到账号私有 `custom_emojis` 目录。
- “清除缓存”不再递归删除整个临时目录，只处理明确可重新生成或下载的缓存。

### 2.4 E2EE 身份轮换

- 先在安全存储中生成并暂存新公私钥。
- 使用现有 `PUT /user/e2ee/device-key` 更新服务器公钥。
- 服务器更新成功后，将暂存密钥提升为当前设备密钥并移除暂存记录。
- 如果在服务器更新或本地提升期间中断，下次初始化会使用同一组暂存密钥继续，避免生成多组不一致身份。
- 身份轮换完成后统一退出，要求用户重新认证。

当前后端没有独立的设备密钥撤销接口，因此 P1 使用现有公钥覆盖接口完成轮换。

## 5. 尚未包含的后端能力

以下内容仍属于后续前后端联合阶段，P1 不作“完整历史恢复”承诺：

- 消息接口目前只覆盖后端允许查询的历史范围；全部历史恢复仍需后端明确消息保留期限并扩展查询。
- 新设备恢复旧 E2EE 消息仍需密钥备份或消息密钥重新封装能力。
- 离线发送跨重试的最终去重仍建议由后端提供客户端消息 ID 幂等保证。
- 推送解绑、设备下线和服务端会话撤销仍需以正式接口契约统一验证。

因此，P1 已解决本机账号数据的安全清理、隔离和密钥轮换，但不能替代 P2 的服务器历史消息与跨设备 E2EE 恢复能力。
