# 代码治理与重构路线

更新时间：2026-06-23

## 目标

这份文档用于把当前代码治理从“凭感觉重构”变成可执行流程。原则是先止血、再建边界、最后逐步拆热点文件；不做大面积重写，不在没有验证的情况下改变聊天、钱包、通话、同步等核心行为。

## 治理原则

1. 不重写核心链路

聊天、消息同步、离线推送、钱包、通话、账号登录等链路只做小步拆分。每次拆分必须保持外部行为不变。

2. 先拆职责，不改业务

第一轮拆分只做移动代码、命名、提取组件、提取纯函数、提取 service/controller，不顺手改接口、不顺手改 UI、不顺手改数据库。

3. 每次只动一个边界

一次任务只处理一个文件或一个功能切口，例如“聊天输入区组件化”或“消息上传逻辑下沉”，不要同时整理聊天、钱包和后端。

4. 先补保护，再做复杂改造

高风险链路拆分前先补最小验证：后端单测、Flutter analyzer、关键页面手动 smoke、接口返回结构检查。

5. 保持兼容层可见

如果必须兼容旧字段或旧返回结构，兼容逻辑要集中在 parser/adapter，不继续散落在页面和 provider。

### P4：后端 handler/service 边界治理

目标：handler 变薄，业务规则集中，接口契约清晰。

第一批对象：

- `backend/internal/handlers/chat_handler.go`
- `backend/internal/handlers/user_handler.go`
- `backend/internal/handlers/meeting_handler.go`
- `backend/internal/handlers/setting_handler.go`

拆分规则：

- handler 只做鉴权上下文读取、参数绑定、错误响应、调用 service。
- 权限校验、状态流转、数据库事务放到 service。
- 复杂 response DTO 放到独立类型文件，不在 handler 临时拼 map。
- WebSocket 广播 payload 建议集中构造，避免多个地方字段不一致。

验收：

```powershell
cd backend
go test ./...
```
